# A jointly chosen gate/up coordinate on routed experts

[The complete 256-expert bank test](full-bank.md) replaces **every** captured layer-0 routed slot under one shared coordinate. The train-selected Q4/Q4 diagonal improves held eight-output RMS .109739 → .074142 at the same gate/up bank rate plus 4,096 bytes, but unchanged GGUF with a shared Q8 input scores .005431. No complete-model loss or native gain follows; the frozen all-bank Q4 reader is not an engine candidate.

A static power-of-two diagonal applied to both the input and the inverse gate/up weights improves a four-bit local response. It does not yet earn a serving change. On held actual routes for layer-0 expert 151, the train-selected diagonal cuts the expert's perturbation of the full routed sum from 0.04643 to 0.03201 relative RMS against the same symmetric Q4 weight/input control. The unchanged GGUF weights with a Q4 input code reach 0.03986, and with a Q8 input code reach 0.00215. Those last two are particularly sobering: changing the joint coordinate buys less than keeping the existing weight representation and paying another 1,024 input bytes per token for a Q8 code that the whole route can share.

## Contract and selection

The data are the pinned Qwen3.6-35B-A3B Q4_K_M layer-0 route capture used by [the actual-route input study](../../../moe/real-gate-input/README.md). Expert 151 has 24 selected train tokens and 29 disjoint held tokens. Its gate and up GGUF matrices are each 512 by 2048; the unchanged Q5_K down matrix is 2048 by 512. The script uses the installed ggml Q4_K/Q5_K decoder, then FP32 BLAS gate/up, SiLU times up, FP32 down, and actual captured router scores. Other experts' outputs remain unchanged. Reference and candidate both use the decoded GGUF matrices, so the error is due to recoding gate/up and input, not to the difference between GGUF and official BF16 weights. The ratio is the score-weighted change in expert 151's down output divided by the captured **whole eight-expert routed-sum** norm for these tokens. It is not the error of a replacement eight-expert sum or language loss.

For a channel `j`, let `mW[j]` be the maximum absolute gate/up coefficient across both output matrices and `mX[j]` the maximum absolute input on the 24 selected train tokens. Set `r[j] = log2(mW[j]/mX[j]) - median_j log2(mW[j]/mX[j])`, then `d[j] = 2^clip(round(alpha*r[j]/2), -3, 3)`. The train scan covers `alpha = 0, .5, 1, 1.5, 2`; it selects `1`, without using held targets. The online map is `x' = d*x`, one signed Q4 group-32 input code with FP16-rounded dynamic max scale shared by gate and up, signed Q4 group-32 gate/up weight codes with separate FP16-rounded max scale per row/group encoding `W/d`, two dots, SiLU/up, unchanged Q5_K down, then weighted routed sum. Integer codes use nearest-even rounding and range `[-7,7]`. The script packs two signed nibbles per byte and restores them before numerical evaluation. The `alpha=0` control uses **the same two-operand quantizer and bytes**, minus the diagonal. An unchanged GGUF weight with Q4 and Q8 input codes, and a recoded Q4 weight with Q8 input code, are separate controls.

The input relative RMS falls from .15295 to .09189 at alpha 1, while weight relative RMS rises from .09726 to .10585. The joint output improvement comes from spending some weight fidelity on a better shared input, not from a better weight codec alone. Only 89 of the 2,048 selected diagonal entries differ from one. Power-of-two factors avoid general multiplies in a suitable exponent-format lowering, but the script actually performs the input multiply; exponent shifts are not assumed free.

## Paid boundary and execution

Two 512-by-2048 Q4 code matrices take 1,048,576 bytes packed, plus 131,072 bytes of row/group FP16 scales. This exactly matches the two original GGUF Q4_K images' 1,179,648 physical bytes, though not their layout or numerical values. The diagonal adds 4,096 FP16 bytes per expert, making the recoded pair 1,183,744 bytes. One dynamic Q4 input takes 1,024 packed bytes and 128 FP16 scale bytes per expert/token. Q8 takes 2,048 plus 128. The unchanged down image takes 720,896 GGUF bytes. The source checks the packed nibble and scale byte counts against these sizes. It does not count a learned codebook, an index or a padding allowance because this format has none; hardware tiling could introduce padding and must pay for it.

Before gate/up there are 2,048 input coordinate products or exponent adjustments and 64 dynamic group reductions/scales per expert/token. Both matrices read that *one* code; their 65,536 separate row/group scales feed 2,097,152 integer weight/input terms in a packed implementation. Scaling/accumulation across groups, SiLU, 1,048,576 down products, and router weighting remain. In the current Python evaluation, nibble unpack, group-scale multiplication and materialization of FP32 matrices happen before BLAS. Those decoded arrays are much larger than the compact image. On this two-thread CPU, the held 29-token batch's Q4 input packing averages about .009 ms/token and its already-decoded three-matrix consumer about .037 ms/token. These timings are diagnostic of the Python boundary, **not** packed native timing or a speedup. The weight pack is an offline operation; `results.json` records its elapsed time separately. A native packed kernel would need to measure input preparation, group reductions, weight loading, reconstruction or integer dot, down and the route sum together.

The diagonal belongs to expert 151. It cannot be silently folded into the preceding norm: that input also feeds the router and other experts. Without a common diagonal for all selected consumers, applying this coordinate costs a distinct input code and 2,048 input operations for each selected expert; the existing grouped implementation shares one code across experts. Our result shows **gate and up** can accept one paid jointly chosen code. It does not show that eight routed experts can share it. A bounded shared-coordinate test across 16 train-selected experts appears below. It preserves one code across that set; the remaining experts keep their captured outputs. It is not the full 256-expert replacement.

## One code shared by 16 routed experts

[`shared_routes.py`](shared_routes.py) ranks experts by **train** route frequency, keeping the top 16: 151, 155, 234, 55, 92, 124, 134, 144, 76, 186, 175, 62, 109, 136, 192 and 199. It computes the common diagonal from the maximum gate/up coefficient across all 16 and all 113 train inputs. Each token with at least one selected expert pays for exactly **one** transformed group-32 Q4 code, shared by gate and up for every selected expert slot. All 16 pairs of weights are inversely transformed and recoded. For each slot, it substitutes the offline decoded GGUF reference or recoded output into the captured eight-expert sum; the unselected slots remain the same captured native outputs in every arm. Held evaluation never chooses a new diagonal or expert set. There are 236 selected train slots on 63 of 113 tokens, and 185 selected held slots on 69 of 126 tokens. Multiple selected experts share a token on 49 train and 41 held tokens.

| Gate/up weights, shared input | Train complete-sum delta RMS | Held complete-sum delta RMS |
| --- | ---: | ---: |
| Original GGUF, Q4 input | .05849 | .05123 |
| Original GGUF, Q8 input | .00326 | .00281 |
| Repacked symmetric Q4, Q8 input | .03665 | .03144 |
| Repacked symmetric Q4, Q4 input, no diagonal | .06894 | .06008 |
| Same Q4/Q4 with shared alpha .5 | .05534 | .04776 |
| Same Q4/Q4 with shared alpha 1 | .05136 | .04327 |
| Same Q4/Q4 with shared alpha 1.5 | .05038 | .04266 |
| Same Q4/Q4 with shared alpha 2 | .05550 | .04871 |

Train selects alpha 1.5; 159 of its 2,048 factors differ from one. Held error drops 29.0% against same-byte repacked Q4/Q4 and 16.7% against original GGUF/Q4, even while **one input code is shared by all 16**. This does not rescue the proposed Q4 path: Q8 with unchanged GGUF weights cuts held error 93.4% versus the selected shared Q4 coordinate. The recoded pair costs 1,179,648 bytes for each of 16 experts, or 18,874,368 total, plus **one** shared 4,096-byte diagonal. One Q4 token code costs 1,152 bytes; Q8 costs 2,176. The selected common Q4 preparation does 2,048 coordinate products and 64 group reductions per covered token, versus the untransformed Q8 preparation; each changed slot still does two 2048-by-512 projections, SiLU/up and the unchanged down projection. There is no per-expert input transform or code inside the 16-expert set. Unselected experts use native captures here, so a full serving route still needs their existing input preparation and weight stream, and 16-expert traffic cannot be extrapolated to all 256.

The two-thread NumPy run records packing and decoded BLAS timings separately. On held inputs alpha 1.5 spent .006 ms per covered token preparing input and .070 ms per selected slot on already-decoded consumers; original GGUF/Q8 spent .006 and .057 ms respectively. These are not native packed-code timings. At a real decoder, Q4 group scales, unpacking, tile padding and whether the common code can be reused alongside the rest of the route must all be measured. The next falsification is one diagonal for **all 256** gate/up banks with all eight route slots recoded on held tokens, then full-model quality and native fused preparation. The sixteen-expert result establishes a shared-coordinate effect, not a viable replacement for Q8.
