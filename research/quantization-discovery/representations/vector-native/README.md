# Native paired gate/up reader

The HIP reader consumes one Qwen3-0.6B MLP layer at its full 1,024 input and 3,072 hidden dimensions. One byte at `[hidden, input]` selects a gate/up pair. The image producer owns its codebook and gain: `table[256,2]` has final little-endian FP16 weights with the FP16 gain already folded in. The kernel reads the byte and one 32-bit table entry, multiplies both values by the same FP32 input, accumulates each projection in FP32, then writes one FP32 `SiLU(gate) * up` result per hidden channel. No expanded weight matrix sits behind the compressed arm. The BF16 down projection is common and absent from every arm; this is the complete gate/up and SwiGLU boundary, not a full MLP latency result.

`fixture.py` exports the exact full-layer polar, learned-pair and scalar-scale images from `/path/to/workspace/data/kelana-subbit/vector-full/images/`, along with original weights rounded to FP16. The scalar image fits 16 FP16 scales to real layer weights. Its native reader consumes one byte with four scale bits and four label bits, reads one of those paid scales, reconstructs the two labels, and rounds each product to FP16 before accumulation. Its model bytes are 3,145,728 indices, 32 scale bytes, a two-byte gain and 12 shape/width descriptor bytes, totaling 3,145,774 bytes. The polar and learned pair arms each charge 3,145,728 indices, 1,024 FP16 table bytes, a two-byte FP16 gain and 12 descriptor bytes, totaling 3,146,766 bytes. The full expanded FP16 pair control costs 12,582,912 weight bytes. The common input and 12,288-byte FP32 output apply to all arms. Fixed polar radii and angles are compiled constants; preparation computes their FP16 table from the paid gain and uploads it. The trained learned-pair table must be loaded, not synthesized from the gain. Image fitting, offline index selection, host-to-device image upload and allocation are outside kernel timing, as they are outside the repeated inference operation.

The input is eight real layer-0 validation vectors, positions 576–583, from the original BF16 producer capture. Their BF16 bit patterns become FP32 values for every arm. `fixture.py` writes independent NumPy FP32 matrix-multiply and SiLU outputs for each exact prepared FP16 image. The HIP runner compares all 3,072 outputs per vector against that reference and the expanded-FP16 control. The compiler targets `gfx1151`; one 32-lane wave owns one hidden row. The first 64-thread attempt was numerically wrong because its cross-wave shuffle lost half the projection. [Its rejected numerical receipt](rejected-wave64.json) stays here so that timing cannot be mistaken for a result. The corrected reader reduces within one 32-lane wave.

## Measured full-channel result

The corrected [GPU receipt](results.json) contains one and eight input rows. Each number is the median microseconds per complete gate/up plus SwiGLU invocation across 11 rotated rounds. All 3,072 output channels reach the FP32 boundary.

| Reader | One input, µs | Eight inputs, µs | Relative output RMS vs expanded FP16, one / eight |
| --- | ---: | ---: | ---: |
| Polar 32 angles × 8 radii | 30.145 | 194.174 | .15884 / .14247 |
| Scalar labels × 16 fitted FP16 scales | 30.035 | 196.345 | .36068 / .34239 |
| Learned 256-pair table | 30.000 | 194.578 | .14180 / .13511 |
| Expanded FP16 gate/up | 42.523 | 230.761 | 0 / 0 |

All arms agree with the independent NumPy evaluation of their own exact FP16 weights within 4.7e-7 relative RMS. The executable rejects nonfinite output or an independent-reference relative RMS above 1e-5 before timing any arm. It also rejects a prepared polar table different from the charged image. The polar table regenerated from the FP16 gain matches all 256 stored pair entries bit-for-bit. Its preparation and 1,024-byte GPU upload took 235.4 µs on the measured run. That cost amortizes only after repeated uses of a layer; index fitting is offline and excluded. The learned table comes from image storage, so its preparation consists of loading the paid 1,024 bytes instead of trigonometric generation. The common inputs and FP32 outputs reside on device during the kernel interval.

At nearly equal byte rate and the same native lookup, the learned table has lower response error than polar and essentially equal latency. The scalar-scale image saves 992 stored bytes relative to polar but has substantially higher response error on these inputs. The fitted scalar reader is 0.4% faster than polar on one input and 1.1% slower on eight. Those differences are too small to select a reader here. [The preceding fixed-scale panel](fixed-scale-panel.json) used the same polar/learned images and kernel but the first analytic scalar scale grid; its [fixture identity](fixed-scale-fixture.json) and numerics remain for provenance. It measured at a different 956 MHz median GPU clock versus this panel's 908 MHz, so compare within panels rather than pooling absolute times. The 1-byte formats beat this particular expanded FP16 wave-row control, not an optimized GEMM or full-model baseline. The learned table is the stronger equal-rate control. A native speed result cannot redeem a model with unacceptable loss, and the down projection, other layers, model scheduling and full-model quality remain outside this panel.

Rebuild and run from the repository root:

```bash
D=research/quantization-discovery/representations/vector-native
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 /path/to/workspace/data/fish-s2-pro/venv/bin/python "$D/fixture.py"
hipcc -w -O3 --offload-arch=gfx1151 "$D/reader.hip" -o "$D/build/reader"
/path/to/workspace/projects/bonsai-halo/tools/run-batch-compare --runtime-max 42s --memory-gib 20 --exec "$PWD/$D/build/reader" "$PWD/$D/build" > "$D/build/timings.json"
```

The maintained wrapper serializes the shared GPU, bounds the process and restores the resident service. GPU event timing covers 32 successive host-submitted launches per arm and round, including submission gaps. Eleven rotated paired rounds follow eight warmup launches per arm. Inputs and images live on the GPU before timing; the output FP32 store is included, but the output copy to the host is outside timing. Batch sizes one and eight each project all 3,072 channels. The preparation time uses a host wall-clock around fixed-polar table generation, the 1,024-byte upload and device synchronization, and is reported separately. This panel is an inference microbenchmark with a real input boundary, not full-model serving throughput or a quality acceptance verdict.
