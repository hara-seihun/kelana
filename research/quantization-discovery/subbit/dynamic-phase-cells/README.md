# A moving query scale breaks constant RoPE code cells

The [rounded phase-cell construction](../rounded-phase-cells/README.md) fixes both query and key steps. The two-dot direct signed-nibble key consumer instead sets each prepared query's signed-byte step to its maximum absolute coordinate divided by 119. Rotating one shared Q/K plane can change that maximum. Even when **every integer code is unchanged**, its final score multiplier moves. Taking one midpoint per code cell is therefore not an exact optimizer for the native query map.

This result gives the event partition and a valid global lower/upper bracket for that moving-scale map. It also keeps the unrotated coordinates in the score: changing the maximum can relabel all 32 query coordinates, not just the rotated pair. The executable uses eight coordinates and one common key step to keep its witness small. The native key image has coordinate-specific steps; the event equations also apply after scaling each prepared query coordinate by its own fixed step.

## Domain and proof

Let the first two coordinates of each key and each of two observing query heads rotate by the same angle `p`; the other `D-2` coordinates stay fixed. The keys have a fixed positive scalar step `s_k` and signed-seven codes `c_j(p)`. For each query `q_ht`, let `M_ht(p)=max_i |(R_p q_ht)_i|`, `d_ht(p)=M_ht(p)/C`, and `z_ht,i(p)=clip(floor(C (R_p q_ht)_i/M_ht(p)+1/2),-C,C)`, with `C=119`. A zero query has zero codes and contributes no score. The two-dot consumer splits each signed-eight-bit `z` into low and high signed nibbles. Its real score for causal key `j` is `b_htj + s_k d_ht(p) <z_ht(p),c_j(p)>`. The fixed `b` can contain other, phase-independent score contributions. The real teacher dot is invariant under the shared rotation, so its causal probability is fixed. For coordinate-dependent key steps `s_i`, rotate the raw key/query pair first, form prepared query coordinates `a_i=s_i (R_p q)_i`, set `M=max_i |a_i|`, and encode each key coordinate with `s_i`. The same root families apply to the two sinusoidal prepared coordinates and the fixed prepared coordinates. The score is then `d<z,c>`, without a common `s_k`; the local Lipschitz constant uses `max(s_0,s_1) hypot(q_0,q_1)` instead of `r`. The executable checks the common-step specialization. This statement is over real arithmetic, not an FP32-bit identity.

All code and maximum-branch changes occur on a finite set. A rotated component has the form `a cos p+b sin p`. Enumerate key half-integer crossings at fixed `s_k`. For each query, enumerate the following candidate roots:

* `|u|=M0`, `|v|=M0`, `u=+v`, `u=-v`, where `u,v` are the rotated pair and `M0` is the maximum of the remaining coordinates;
* `u=t M0/C` and `v=t M0/C` for half-integers `t=m+1/2`, `-C<=m<C`;
* `u=+t v/C`, `u=-t v/C` and the reversed pair;
* `|u|=C a_i/t` and `|v|=C a_i/t` for each fixed coordinate `a_i` and each nonzero half-integer threshold, when the positive target lies between `M0` and the rotated pair's norm.

The last family is easy to miss: the scale crosses a fixed coordinate's rounding threshold even though that coordinate does not rotate. Each equation is a single sinusoid equal to a constant and has at most two roots per revolution, apart from identically satisfied equations, which do not partition a code state. The deliberately loose bound is `12+8C(2D-1)` candidate query roots and `56` candidate key roots per vector. Sorting these roots partitions the circle into intervals on which every code and the identity of the maximum component are fixed. An endpoint can have a third tie-rule image, so it must be evaluated separately. The fixed-step result's constant-cell objective does **not** carry over: `M(p)` still varies on a variable-maximum interval.

There is nevertheless a cheap bound without a stationary-root solver. Within an open cell, put `A_htj=(s_k/C)<z_ht,c_j>` and `f_ht(M)=KL(P_ht || softmax(b_htj+A_htj M))`. Its derivative is `E_model A-E_teacher A`, hence `|f'_ht|<=max_j A_htj-min_j A_htj`. The maximum of fixed magnitudes and two rotated components is Lipschitz in phase with constant `r_ht=hypot(q_ht,0,q_ht,1)`. Thus the mean two-head causal loss in a cell is Lipschitz with constant `L=mean_ht r_ht (max_j A_htj-min_j A_htj)`. At its midpoint `m`, the cell's infimum lies above `loss(m)-L*(right-left)/2`. Evaluate midpoints and boundaries for an upper bound; take the minimum of these cell lower bounds for a global lower bound. Subdivide only cells whose lower bound can beat the incumbent. The finite event construction plus arbitrarily fine subdivision gives an epsilon-global offline optimizer, but **one sample per cell is not exact**. The Python receipt uses floating roots and losses, so its bracket is numerical evidence for the theorem rather than a machine-checked interval-arithmetic certificate.

## Checked small construction

`fit.py` fixes seed 7429, five causal keys, two heads, eight query/key coordinates, `C=119`, fixed key step `.75`, and phase-independent other scores. Its receipt stores the actual vectors, selected labels and source SHA-256. There are 40 key and 42,184 query candidate events, making 32,705 distinct open cells. The zero-phase mean teacher-to-candidate causal KL is `.01494739`. The best sampled boundary or midpoint is `.00511255` at phase `5.36415236`; the midpoint of its own cell scores `.00511255`, whereas a quarter-cell point scores `.00511304` with unchanged labels. The global midpoint-Lipschitz bracket on this candidate partition is `[.00468439,.00511255]`. The observed gain is a synthetic conditional quantizer result, not Qwen held quality; the gap prevents calling the sampled phase an exact optimum.

For comparison, separately optimizing a **different** fixed query step `.02` on the same inputs picks phase `.64851722` and scores `.00497026` on its own fixed-step map. Replaying that phase with the actual dynamic-max map scores `.00520746`, worse than fitting the dynamic map directly. The fixed-step construction cannot silently stand in for the deployed signed-byte query preparation.

At inference a selected phase stores the same signed-nibble key cache and still uses two signed-nibble dots for each head's score. It adds the phase metadata and append/query angle composition priced in [the RoPE gauge study](../rope-commutant/README.md). Query preparation remains a dynamic 32-coordinate maximum, 32 rounds and splits per head/group, plus 32 coordinate-step products for the actual nonuniform key image, the paid Q/K producer and softmax. Offline root enumeration costs up to `O((N+H C D) log(N+H C D))` before causal-loss evaluations, with `H` distinct query vectors. The 32-coordinate real-model fit is much larger than this toy. The code does not time a native reader or change Bonsai.

The first useful engineering reduction is event filtering and cell lower-bound pruning, not a denser phase grid. If held composed quality improves at matched code bytes, measure phase append, dynamic query preparation and score together against zero phase under the wrapper before selecting an engine map.
