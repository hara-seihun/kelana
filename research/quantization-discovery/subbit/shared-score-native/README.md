# Native cost of sharing one key-score dot

The frozen Qwen3-0.6B layer-14 three-dot score retains most of the four-dot arm's quality on a quantized upstream producer, but its 25% reduction in signed-nibble products buys much less elapsed time in a direct gfx1151 reader. A paired native experiment with 32 independent queries and 256 or 1,024 occupied keys per query measures both heads' packed-key scores and their complete per-head softmax. It consumes four packed key dwords per group/key, with no expanded key image. The result argues against installing the frozen score map for speed alone. Change the paid producer and labels before spending another native implementation round.

| Context / 32 streams | Four dots, score + softmax | Shared three dots, score + softmax | Four dots, append + prep + score + softmax | Shared three dots, same boundary |
| ---: | ---: | ---: | ---: | ---: |
| 256 | 8.108 us | 7.846 us, 3.2% faster | 21.599 us | 20.986 us, 2.8% faster |
| 1,024 | 17.101 us | 15.588 us, 8.8% faster | 30.524 us | 29.155 us, 4.5% faster |

Medians are nine rotating paired rounds, 24 invocations per sample; all 72 raw measurements and the wrapper clock trace are under `/path/to/workspace/data/kelana-subbit/shared-score-native/`. All arms read the same 16-byte packed key/group/token, produce the same number of FP32 probability rows and use the same two-head softmax. The shared arm uses two signed-nibble `v_dot8_i32_iu4` passes on an eight-bit base query and one on its four-bit difference from the other head. The four-dot arm uses two passes per independently rounded head. The kernel scores four dwords per pass, so the difference is four dot instructions per key/group. It folds scaling and the base-score addition into the score kernel, and never writes an intermediate key vector.

Each invocation in the complete boundary appends one 16-byte packed key per group/stream, prepares 512 query coordinates per stream using dynamic maxima and round-to-nearest, scores every key, then normalizes both heads. The synthetic input uses a fixed `mt19937(60214)` seed, two correlated real query heads and packed random nibble keys. Query preparation includes even the unused fourth digit in the shared arm, so its measured overhead is conservative. The append models the cache write after key-code production; **binary K projection, full RMSNorm, RoPE/plane selection, key-label quantization, attention-value multiplication and O are not measured**. The keys and queries are synthetic rather than the earlier captured image. Native code checks the first group's packed-dot FP32 softmax against an independent scalar unpack/dot reference for both arms at 256 keys; the largest probability difference is 6.64e-9. That checks this score program's map, not bit equality to the frozen CPU replay or the teacher.

The time comparison is specific to one 256-thread block per query/group, 32 independent streams, 256/1,024-key contexts, device-resident inputs and gfx1151 HIP events. The output buffer contains all 16 heads per stream, but the experiment does not time a full attention layer, a K producer or model TPS. Its 25% logical dot saving becomes only 1.369 us at 1,024 keys once append, query preparation and softmax are included. Even this gain must pay for the existing layer-14 held causal KL change from .276883 to .278158 and post-O relative error from .020487 to .020591 on a quantized upstream producer; there is no native quality-matched int4 comparison or complete-model NLL. The high-priority question remains joint paid Q/K/key-label training on broader composed text, rather than shaving another frozen query selector. If quality recovers, carry real packed captures into a fused score/value consumer and benchmark with the full key producer.

The wrapper restored `bonsai-halo.service` to active. It recorded a quiet socket and low sampled clocks in `clock.json`; these paired ratios are more useful than transferring the absolute microseconds to a busy serving run. The pinned packed inputs are deterministically generated by `probe.hip`; no fixture download is needed. Reproduce from a Kelana writer checkout:

```sh
mkdir -p /path/to/workspace/data/kelana-subbit/shared-score-native
hipcc --offload-arch=gfx1151 -O3 -std=c++17 \
  research/quantization-discovery/subbit/shared-score-native/probe.hip \
  -o /path/to/workspace/data/kelana-subbit/shared-score-native/probe
/path/to/workspace/projects/bonsai-halo/tools/run-batch-compare \
  --runtime-max 37s --memory-gib 6 --pin-clock \
  --clock-log /path/to/workspace/data/kelana-subbit/shared-score-native/clock.json \
  --exec /path/to/workspace/data/kelana-subbit/shared-score-native/probe \
  /path/to/workspace/data/kelana-subbit/shared-score-native/samples.json
```

`identities.txt` in that data directory hashes the measured source, executable, raw samples and clock receipt. This is a research native cost result; Bonsai's executable and serving defaults did not change.
