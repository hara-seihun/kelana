# Temporal order does not buy a cheaper frozen key score

The paid Qwen3-0.6B signed-nibble K cache has a useful first difference at layer 14. Can a second-order predictor shrink its serial direct-score stream? On four inspected validation windows, the answer is no. Predicting each coordinate by `2*c[t-1]-c[t-2]` raises the held residual entropy from 2.841 to 3.503 bits/symbol at layer 14 and from 3.473 to 4.171 at layer 0. It also enlarges the complete residual alphabet from 31 to 57 symbols. The larger code costs about 20 additional bytes per token against first differences, with the same row or group address layout. It loses to static mixed keys even before its extra score-recurrence work.

An absolute-label Huffman control matters here. It avoids the cross-key score scan altogether, but loses 14.8 bytes/token to first differences at layer 14 in both byte-aligned layouts. At layer 0 absolute labels nearly tie first differences, and neither compressed group stream beats the 112-byte static mixed cache. This points away from polishing a frozen temporal predictor. A learned K producer must shape its labels for independently addressable direct scores, or the existing first-difference native reader must repay its serial parser and score scan.

Each group has 32 signed-nibble coordinates. Eight training windows fit one complete-alphabet canonical Huffman table per group for each order and width; four previously inspected 256-token validation windows determine the bill. The absolute code packs all `[-7,7]` labels. First differences use the preceding full `[-15,15]` alphabet so their charged bytes reproduce the existing [direct-score Huffman study](../key-entropy-direct/README.md) exactly at width 32. Second differences `c[t]-2*c[t-1]+c[t-2]` lie in `[-28,28]` for every legal cache history. The first key in each predictive block is a 16-byte absolute anchor, and the first residual is an ordinary first difference. Each block has a four-byte address. Streams start on bytes. Row mode adds one byte length per independently appended non-anchor key; absolute row mode adds one per key. Length-table metadata is paid once for the 1,024 held keys using the minimum fixed width for the observed trained maximum length: four, five and five bits per symbol for absolute, first and second. The trained maximum depths are 8/9 for absolute, 16 for first and 17 for second. Thus any legal 32-symbol row under these tables fits in at most `ceil(32*17/8)=68` bytes, so its one-byte length is valid on the entire signed-nibble domain; the largest observed row is 30 bytes. This is a rate calculation from trained canonical lengths rather than an emitted native bitstream. Its table covers the entire stated code domain, and every held history round-trips under the recurrence.

For integer query `q`, let `s[t] = q·c[t]`. Second differences give `s[t] = 2*s[t-1]-s[t-2]+q·e[t]` after the first two scores. First differences give `s[t] = s[t-1]+q·d[t]`; absolute labels give one independent dot per key. Both heads share the decoded labels, but have their own score recurrence. The source checks all recovered code rows and both heads' integer scores on the first block of every held window/group. These are exact integer identities, not a promise of bit-identical FP32 softmax, and no native query preparation, Huffman parsing, append time or score-scan latency was measured. Second-order dots also admit signed-byte residuals but pay another score multiply/subtraction and carry two live scores. The existing first-difference row stream is the only tested compressed point here below the 112-byte static mixed cache on layer 14 with independent key-row addressing, saving 6.479 bytes/token before its reader bill. It changes neither the paid weights nor original-producer model quality.
