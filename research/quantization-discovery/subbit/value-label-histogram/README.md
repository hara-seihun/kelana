# Repeated-input value codes: cheap bytes, expensive histogram dots

The frozen rank-28 Qwen3-0.6B signed-byte V cache has an unusual layer-0 property. Within each inspected 256-token validation window, the number of distinct 28-byte codes in **every** GQA group equals the number of distinct captured QKV inputs: 147, 148, 127 and 146. Layer 14 has 256 distinct inputs and 256 codes in each group in every window. On this panel the code collisions are repeated producer inputs, not a new quantizer quotient. An append-time dictionary can store each repeated *224-byte whole value row* once and use one shared byte ID per key, without changing any code or the signed-byte value map.

For a 256-key append-only block with `u` distinct whole rows, store `224u` bytes of rows in first-occurrence order, 256 one-byte IDs, a two-byte count and a four-byte arena address. Its complete row payload is `224u + 262` bytes against 57,344 raw bytes. The four layer-0 windows cost 33,190 / 33,414 / 28,710 / 32,966 bytes, **125.273 bytes/key on average against 224**. Layer 14 costs 57,606, or **225.023 bytes/key**: the extra IDs lose. Repeated input gives a shared index across all eight groups on the observed windows. A byte holds all 256 IDs, including the all-distinct case. Building the dictionary needs a lookup or comparison on each appended key and managing its arena; these operations, the output factor and the key cache are not included in the byte count. This is an exact cache representation at unchanged weight rate and model behavior, not a measured native speedup. It does not beat the 112-byte signed-nibble cache on layer-0 bytes, but that cache has a different lossy value map; nor is this a comparison with an entropy codec fitted to these signed-byte labels.

The same labels permit an exact alternative attention sum. Let `c_k ∈ [-127,127]^28` be the group code, `i(k)` its dictionary ID and `n_{h,k}` the conserved nonnegative 4,095-unit mass for either observing head. Form `H_{h,j} = Σ_{k:i(k)=j} n_{h,k}`. Then

`Σ_k n_{h,k} c_k = Σ_j H_{h,j} c_j`.

This is integer equality on **all** such count rows, independent of rounding or the observed texts; each coordinate has magnitude at most `127×4095 = 520,065`, within signed int32. The CPU reproducer checks the identity in all eight groups on deterministic nonuniform count rows. FP32 output folding after this exact integer step is a separate scheduling question.

Across four previously inspected 256-position windows, summing distinct prefixes across eight groups and all causal queries gives 645,368 label uses versus 1,052,672 key uses at layer 0. The resulting two-head, 28-coordinate logical products fall 58,949,632→36,140,608, **38.69%**. Layer 14 has no reduction. This is not yet a cheaper byte-dot program: histogram counts reach 4,095 and need two byte digits per ID for a uniform dot4 reader, costing **72,281,216** layer-0 byte products plus 2,105,344 head/key histogram additions. The already constructed one-byte-dot sparse-overflow reader uses 58,949,632 low byte products plus 1,070,888 irregular scalar correction products on the same layer and count map. Histogram initialization, index gathers, scatter conflicts and dictionary construction are further unpaid. The count-domain identity is useful; the simple byte-reader lowering loses its logical arithmetic comparison with that parent. Keep the sparse-overflow consumer if a native experiment prices the indexed cache, and test whether repeated producer inputs make its saved physical bytes worth the lookup.

The domain is frozen paid Qwen3-0.6B V/O factors, train-selected FP16-rounded signed-byte steps, original-producer validation captures and four already inspected windows at layers 0 and 14.
