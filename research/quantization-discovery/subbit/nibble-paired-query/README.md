# Can one packed dot score both heads against a shared nibble key?

A GQA key is read by two query heads. Packing both signed-nibble queries into one signed-byte operand seems to offer one `v_dot4_i32_iu8` stream against that shared key instead of two separate streams. It cannot retain both integer scores on the full 32-coordinate code domain. This is a fiber collision, not merely a bad numerical scale. The cheapest exact radix escape needs a wider query operand, for which gfx1151 has no packed signed-16-bit dot. This rules out this particular arithmetic shortcut; it does not rule out learned approximate joint scores or a different instruction composition.

## Observation and collision

Fix one group of 32 coordinates. Each stored key code `c_j` and each head's prepared query code `u_j`, `v_j` lies in `[-7,7]`. The required observation is the ordered pair `(U,V)=(sum u_j c_j, sum v_j c_j)`, before the shared real score scale. Consider the whole-region packed query coordinate `e_j=u_j+B v_j` and a single dot `D=sum e_j c_j=U+B V`. A decoder may know `B` and even the complete key, but only receives `D` from the dot; it does not separately compute `U` or `V`.

To fit **every** `(u_j,v_j)` into a signed byte, positive integer `B` must obey `7(B+1)<=127`, hence `B<=17`. For each such radix set all 32 key codes to 1. One input has all query codes zero. A second has `sum u_j=-B`, `sum v_j=1`, with each query coordinate inside `[-7,7]`. Both give `D=0`, but the required outputs are `(0,0)` and `(-B,1)`. Even an arbitrary post-dot decoder cannot distinguish them. The executable witness covers every feasible positive radix from 1 through 17. Negative radices follow by negating the second head. The all-one key is an admissible code, not a claim about which keys the pinned model happens to produce.

This observation is stronger than counting image sizes: two inputs actually inhabit the same dot fiber and different two-score fibers. It also survives any bijective relabeling of the scalar dot result. If a consumer observes only a combined or approximate score rather than both heads' scores, its contract is different and this collision need not matter.

## The wider exact construction and its bill

For arbitrary 32-coordinate signed-nibble codes, `|U|<=32*7*7=1568`. Choose `B=3137`. The balanced remainder of `D` modulo `B` uniquely recovers `U` in `[-1568,1568]`, then `V=(D-U)/B`. The packed query coordinate has magnitude at most `7*(3137+1)=21966`, so it fits signed 16 bits, and `|D|<=4,920,384` fits signed 32 bits. This is a sufficient radix, not a proof of the minimum radix on this domain. The final real head-specific scale multiplies still have to be applied separately. In particular, packing cannot combine the two heads' generally different dynamic scales into one shared FP operation.

On gfx1151 the documented packed integer dot choices are `V_DOT8_I32_IU4` for eight four-bit lanes and `V_DOT4_I32_IU8` for four eight-bit lanes. The pinned instruction inventory has no signed-16-bit packed dot. The existing two-head nibble score therefore uses eight dot8 instructions for 32 coordinates, four per head. A signed-byte paired query would require eight dot4 instructions after unpacking the key into byte registers, *even if* its fiber collision were acceptable. The exact 16-bit radix query cannot enter either dot without further decomposition or another program. These are instruction-count and operand-width facts, not timings or a universal hardware lower bound. The key stays packed in memory in both comparisons; unpacking to byte registers is still online work. Query preparation, register lifetimes, key loads and cache-line traffic are not free.

The result rejects radix-packing **two independent exact head scores** into one `i8` dot as the reason to build a native consumer. It does not improve the frozen nibble image's quality or rate. The useful next experiment is the existing quality-credible two-dot query against int8 and BF16 key consumers on fresh quantized-upstream text, followed by native timing with query preparation and the full K producer charged. A genuinely cheaper one-dot route would have to learn a joint query/key coordinate or an acceptable lossy two-head observation, rather than assume that key sharing makes the arithmetic merge free.
