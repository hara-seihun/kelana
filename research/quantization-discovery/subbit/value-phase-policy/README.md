# Score-only phase selection for one-nibble value attention

Can a phase policy recover the response gain of a sixteen-phase search without reading value codes before selecting the phase? I fitted a linear sixteen-way policy using only the probability row. It removes the grid search's code projections and paid-output metric evaluations, but its held response error does not consistently beat one train-fixed phase. The missing input is the value code response, not another way to evaluate the same frozen quadratic.

## Construction and boundary

For a probability row `p` of `n` keys, phase `u` assigns prefix boundaries `floor(15*cumsum(p)[:-1]+u)` and final boundary 15. Adjacent differences are nonnegative counts summing to 15 on the normalized simplex. The frozen signed-nibble code vector `c_k` stays packed until the selected count map is consumed. A selected phase needs one prefix scan and at most fifteen code gathers, followed by one direct packed-nibble dot. There is no expanded int4 value matrix.

The selector scans the fractional parts of the unshifted prefix boundaries into eight bins, adds normalized context length and a constant, then scores sixteen phases by a fitted affine map. Each of the sixteen outputs is a dot of ten features. The probability scan costs `n-1` fractional/floor operations and bin increments, plus roughly 160 coefficient products and 160 additions per query/head. Constructing the *chosen* count vector needs another `n-1` boundary operations, unless the scan stores its boundaries, in which case it keeps `n-1` fractional values until selection. Either choice is charged. The model has 160 floating coefficients per head, plus feature center/scale. This is a scalar-work model, not a GPU latency estimate; histogram updates, softmax, count construction, sparse gathers, subgroup scheduling and O projection are not free. The higher-cost ablations also compute max, second moment, four largest probabilities and entropy; entropy requires a log per key if softmax has not already produced it. They are not the proposed cheap consumer.

Each phase's *training target* is the squared paid post-O error against the 4,095-count reference, computed offline using the frozen value codes. The sixteen targets for a row are normalized by their range before ridge fitting. Six penalties are selected by leaving out each of the eight train windows, refitting and summing the actual held-out train-window squared errors. The fixed baseline chooses its one phase by train squared error. The grid oracle sees the sixteen code-dependent reference errors at inference, so it is an unattainable bound, not an alternative with zero work. Earlier finite-grid and event studies instead optimize error against the floating code response; do not compare their numbers as though the objective and positions were unchanged.

At layer 14 it loses to the fixed phase by .00000850, despite improving three of four validation windows: the second window reverses. Adding probability moments, top four and entropy does not repair held layer 14, and makes layer 0 worse than the cheap histogram. The earlier eight-position/window probe made both policies look much better; doubling to sixteen positions reversed layer 14. Retain that selection failure rather than choose the smaller panel.

This is a sampled one-head conditional error on original producers, not an all-head 1e-4 allocation, fresh text, complete-model loss, native timing, or a changed weight image. The frozen nibble V/O map still loses to E4M3 on the matched complete post-O response. No runtime choice follows.

## Why probabilities alone have a hard limit

Even a perfect score-only policy cannot choose the best phase for every admissible value code map. Take three keys with probabilities `(0.31, 0.28, 0.41)`. The zero-phase counts are `(4,4,7)`; phase `.2` gives `(4,5,6)` and phase `.4` gives `(5,4,6)`. Use scalar codes and unit paid-output metric. For `(1,-1,0)`, the floating response is `.03`, so phase zero's response `0` has squared error `.0009`, less than phase `.4`'s `(1/15-.03)^2=.00134444`. For `(1,0,0)`, the floating response is `.31`, so phase `.4`'s `5/15` has squared error `.00054444`, less than phase zero's `(4/15-.31)^2=.00187778`. Phase `.2` is worse than the winner in both cases. The probability observation is identical and the optimal phase differs. These scalar codes sit inside the signed-nibble alphabet; padding the other 27 coordinates with zero embeds the witness in rank 28. Scaling the nonzero code differences scales the regret. This is a full-code-domain impossibility for *code-blind exact selection*, not a lower bound on the error of a policy on actual producer-reachable codes. The measured panel says the approximation is also fragile on the inspected real codes.
