# The complete output metric still overfits a frozen rank gauge

The [rank-group reconstruction fit](../binary-rank-pairing/README.md) failed on held output because it optimized the intermediate coordinate, not the paid two-factor response. This experiment fixes that objective, with no change in the binary image's stored rate or direct-reader work. It improves every training panel, but the held response reverses at layer 14 in both panels and at layer 0 in the larger panel. Merely inserting the missing output Gram is not a reliable frozen-image selection rule.

## Complete-map construction

Write the paid real matrix as `diag(post) U V diag(pre)`. The first A7 integer stage produces rank vector `h` and scale `b1`; the second grouped A7 stage produces rank codes `z` and common scale `b2`. A rank permutation repacks both sign planes as `PV` and `UP^-1`. The real product, binary payload, two quantizers, number of bitplane dots and rank intermediate remain unchanged. The second stage's 32-rank groups change, and its approximate response deliberately changes. Its per-input global maximum and `b2` are invariant under rank permutations. All group A7 choices, rounding and clipping are recomputed for the two affected groups after a swap.

Let `r = b1*b2*z - x*V^T`, in original rank order after scattering the new codes, and `G = U^T diag(post^2) U`. Then the **complete** same-image output squared error is exactly `sum_i r_i^T G r_i` in real arithmetic. The first-stage error and every cross-coordinate output interaction are present. For a proposal changing just two rank groups with reconstruction delta `D`, the exact objective change is `2 sum_i D_i^T (G r_i) + sum_i D_i^T G D_i`. Only 64 columns of `D` can be nonzero. Cache `Gr`, update it after an accepted swap and never multiply all 3,072 output rows for each proposal. This reduces one proposal from a full second-factor output replay to two 32-coordinate A7 quantizers and a 64-column quadratic form. It is an exact search reduction for this fixed-image, FP64 objective, not a proof that greedy swaps find the optimal permutation. A separate complete integer-stage replay checks the final scatter and codes.

The source is [`measure.py`](measure.py). With `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 research/quantization-discovery/subbit/binary-composed-rank/measure.py`, it writes [the CPU receipt](/path/to/workspace/data/kelana-subbit/binary-composed-rank/receipt.json). It starts each panel at a stable training-energy sort and accepts seeded cross-group swaps only when this full train output SSE falls. First/second A7 thresholds are `.77/.77` at layer 0 and `.78/.77` at layer 14. The target is the same paid image's unquantized FP64 factor response, not the original model's logits or gold tokens. Inputs come from pinned Qwen3-0.6B `mlp_up` original-producer fixtures, with nonoverlapping train and validation corpus splits.

The two panels vary both input spans and search duration; they are independent checks, not a controlled training-size ablation. The first layer-0 gain is 0.16% in relative RMS, against a 5.44% training reduction, and disappears in the second panel. Layer 14 loses on both. This is narrower than saying rank regrouping is useless: the energy-sorted gauge itself improves prior held responses, and another quantized producer can reorder sensitivity. It does show that fixing the missing Gram term alone does not cure frozen original-producer overfit.

The receipt records source, parent, image, fixture, first-stage integer, packed U/V, permutation and held second-stage integer hashes, plus every held per-input error. These are CPU original-producer response panels. There is no GPU use, complete-model NLL, native time, changed Bonsai executable or service state. Do not select these fitted permutations for a native reader. Next use the same 64-column exact update on **quantized-producer composed MLP endpoint or gold-continuation observations**, with disjoint training windows and an early-stop selection split. The full-model captures and paid image already exist; a different selection target is more valuable than longer search on this one.
