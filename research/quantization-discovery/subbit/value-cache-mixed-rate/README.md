# Paying for a fifth value-cache bit with a third-bit coordinate

The frozen rank-28 Qwen3-0.6B narrow V/O image has a 112-byte signed-nibble cache per token/layer, but its four-bit cache still trails the 224-byte E4M3 control after both receive paid output-code refits. Can we move bits from quiet coordinates to sensitive ones, keep exactly 112 cache bytes, and improve the complete two-head post-O response? On this image, the answer is no at layer 0 and a train-only, non-transferring gain at layer 14.

I froze the paid two-bit O image from `value-nibble-basis` and its rank-28 V producer. Eight 256-token original-producer train windows supply causal probabilities and original V/O targets. Each coordinate's signed 3-bit and 5-bit scale is picked by training-coordinate MSE among twelve quantile-derived scales plus the existing FP16 step. I measured the change in *complete* post-O squared error when replacing one parent cache coordinate, including both GQA heads and their shared output. The within-group allocation pairs a three-bit coordinate with a different five-bit coordinate. For one pair per group it exhausts all 756 ordered pairs; larger pair counts use the cheapest three-bit deltas and then the cheapest disjoint five-bit deltas. A dynamic program chooses the group's pair counts at each total, and the exact composed train response selects among 0, 1, 2, 4, 8, 16, 32, 56, 80 and 112 pairs. Four repeatedly inspected validation windows see only the frozen choice. This is an optimal one-pair choice under the frozen candidate scales and additive one-coordinate surrogate, **not** a globally optimal mixed-bit image or a jointly trained quantizer.

| Layer | Train pairs | Train post-O error parent → mixed | Held parent → mixed | Same-fit E4M3 held |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | .208893 → .208893 | .385148 → .385148 | .377798 |
| 14 | 2 | .162126 → .162119 | .334500 → .334550 | .325434 |

Layer 14 selects group 3 coordinates 19/27 and group 5 coordinates 21/22 as three/five-bit pairs. Its four held windows all worsen, by 0.0000073 to 0.0000839 in relative squared error. At layer 0 the best train single pair costs positive response error in every group, and the selected image does not move. The layer-14 train gain is 0.00000635 absolute, well below the .009066 held gap to E4M3 even before the held reversal. The complete map matters: promoting a coordinate on its own is not a free quality gain when another coordinate must surrender a bit.

Each group stores exactly 28 × 4 = 112 bits, 14 bytes; the eight groups total 112 logical bytes and still pad to eight 16-byte lines, 128 bytes. The per-coordinate FP16 steps occupy the same 448 bytes as the parent, but the two selected pair indices need at least 4 × 5 = 20 additional static bits at layer 14 unless encoded in the producer's layout. The right and paid O factors remain 208,640 bytes. This is not an equal-*instruction* map. The direct signed-nibble dot accepts the original codes. A three-bit code must be sign-extended to a nibble; a five-bit code requires a nibble plus a signed fifth-bit correction, and scattered bit extraction/preparation is charged before its dots. Even a held gain of this size would not justify a native replacement on the strength of cache bytes, which did not change. Neither this script nor its BF16-expanded Qwen continuation measures native latency or full-model loss.

This closes a cheap frozen-basis bit swap at exact per-group cache rate. Do not chase another fixed-cache bit allocation on these inspected windows. A useful next experiment changes the narrow right basis, cache codes and paid O signs together against quantized-producer complete-model gold/teacher continuation, with an equal-rate E4M3 arm. If it makes a half-byte cache competitive, price its fused producer, probability conversion, packed dot and O consumer on native hardware; a 3/5-bit bitstream has no current direct-consumer advantage over the nibble.

`measure.py prepare --layer {0,14} --split {train,validation}` prepares original-producer states and FP32 probabilities. `measure.py fit --layer {0,14}` performs the train selection and held replay; run from the Kelana checkout with `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=8 /path/to/workspace/data/fish-s2-pro/venv/bin/python`. `/path/to/workspace/data/kelana-subbit/value-cache-mixed-rate/` contains both prepared fixtures and `layer{00,14}.json` with all single-coordinate response deltas, selected steps and rates, train candidate results, held-window scores, source/model/capture/paid-image/cache hashes and fixture hashes.
