# One routed reduction for four binary-factor outputs

The existing sub-bit Qwen3-0.6B image stores a binary right factor `V` and a binary left factor `U`. Its ordinary consumer computes `h=V(x*scale_pre)` and then one signed reduction of `h` for every output row of `U`. Four adjacent output rows can instead share **one pass over `h`** without changing a bit of either factor image. This is a complete four-output map, not a claim that the GPU already has a cheap scatter instruction.

For each rank coordinate, let `a` be the first row's sign and let `b1,b2,b3` say whether the other rows differ from `a`. The existing four sign bits bijectively encode `(a,b1,b2,b3)`. Accumulate `a*h` in bucket `b1+2*b2+4*b3`. At the end, output 0 is the sum of all eight buckets; output `j` is the sum of buckets with `bj=0` minus those with `bj=1`, for `j=1..3`. Apply each row's original FP16 post-scale afterward. Expanding each bucket shows that its contribution to row `j` is exactly `U[j,r]*h[r]`. This holds for every real activation, every packed binary image and every rank, without reconstructing a weight matrix or an int4 tensor. The same proof applies to a quartet whose first-stage factor and output scales differ from those of another quartet.

## Cost and the real obstacle

In a scalar conditional-add grammar, the conventional four reductions issue `4R` signed accumulator updates. The shared consumer issues `R` signed bucket updates, at most 28 signed bucket-combination additions, `R` three-bit bucket selections and `R` dynamic routes. Eight live bucket sums replace four output accumulators. It reads `h` once per quartet instead of four times if the conventional reader does not reuse that input; neither saving implies a cache-traffic reduction when `h` is already hot. No extra factor bytes or static table are required. The producer `R*K` signed terms, scales, output writes, sign extraction and any cross-tile handling remain. This count does **not** price branch divergence, SIMD permutes, the index/route implementation, register spills, reductions, or a possible WMMA advantage of the conventional path.

If one signed update costs one unit and the extra dynamic route costs `c` such units, the quartet is cheaper only if `c < 3 - 28/R`. For these ranks that means `c < 2.920` at `R=352` and `c < 2.927` at `R=384`, before divergent routing and occupancy effects. Counting just signed updates would be a misleading 3.71–3.73x local saving. Recomputing eight masked dense dots would erase it. The existing eight-sign response-table consumer is also a strong alternative: it trades table construction and reads for regular addressing rather than paying this arbitrary bucket route. A native panel must compare both complete consumers, not just two scalar-add counts.

The executable receipt loads the sixteen pinned `.55`-target NanoQuant-initialized factor images for layers 0, 7, 14 and 27, with `mlp_up`, `mlp_down`, attention Q and O. It unpacks the **stored** U/V bits and evaluates the first validation activation from each matched Qwen fixture. All 16 images have all eight sign buckets occupied in every adjacent output quartet, so this frozen ordering does not get a smaller bucket array for free. In FP64 the two response constructions agree exactly on those sixteen activations; their dyadic BF16/FP16 inputs make that numerical check exact in this range. The algebraic identity covers the full real domain; it does not imply BF16/FP32 bit identity after reassociation.

The rank and shapes repeat across the four inspected layers; image-specific signs and all-bucket occupancy come from the receipt. These counts are a **conditional cheaper whole-map program** in the stated scalar grammar, not observed latency or a weight-rate/quality gain. The bits and exact real response are unchanged. Importantly, `mlp_up` has enough left-factor work that even charging a route at one signed-add unit leaves a large local margin; `mlp_down` is dominated by its unchanged first factor. A bounded native experiment should start with the up projection, price decoded sign bits, bucket routing and eight live sums, and compare the regular response-table route at the same activation and image. If route cost crosses the threshold, learn factor codes with a small shared pattern alphabet and static rank blocks rather than routing these frozen high-entropy quartets dynamically.
