# Byte response tables for the paid binary factors

The two-choice integer-ladder A6 activation map admits an exact signed-byte response table for each four-sign chunk. Both paid Qwen3-0.6B binary factor planes can consume those bytes directly. No int4 or floating weight image is reconstructed. A complete eight-sign block uses two eight-entry tables, 16 bytes of live table data, versus 256 bytes for the 128-entry int16 half-orbit table at the **same A6 map**. The byte construction adds a second indexed read, sign selection and row addition per block. It is a register-size and packed-lookup candidate, not a native speedup. A7 cannot use this byte table for four signs on its full code domain; it needs int16, or four two-sign byte tables and four reads per eight signs.

## Exact domain and width theorem

Let signed `b`-bit activation codes range over `[-2^(b-1), 2^(b-1)-1]`. For one chunk of `d` codes, fix the first sign positive and tabulate the `2^(d-1)` forms `T_m(q) = q_0 + sum(i=1..d-1, r_i(m) q_i)`, where each `r_i` is `-1` or `+1`. For **every** possible code vector and mask, the tight common range of stored table entries is

```
-d * 2^(b-1) <= T_m(q) <= d * 2^(b-1) - 1.
```

The lower bound takes every code at its negative endpoint with all relative signs positive. For the upper bound choose `q_0` at the positive endpoint and each other code at the negative endpoint with relative sign negative. A signed `w`-bit table therefore works for the entire domain exactly when `d * 2^(b-1) <= 2^(w-1)`. In particular, four-sign A6 requires and fits signed byte, while eight-sign A6 and four-/eight-sign A7 require int16. Eight-sign A13 still fits int16 exactly; eight-sign A14 does not. These are width necessities for this direct stored-response grammar, not lower bounds for arbitrary ISA programs.

The packed first sign selects `T` or `-T`. **Widen before negation**: the legal A6 four-sign entry `-128` can turn into response `+128`, which cannot be represented in a signed byte. Four chunk responses form each 32-code group dot. Its absolute value is at most `32*2^(b-1)`, so int16 holds the whole A6 or A7 group result. Multiply the group result by its integer ladder multiplier and sum in int32. For the two-choice `C=8` ladder, the largest multiplier is 512. Even at the largest 3,072-coordinate boundary, `3072*2^(b-1)*512` is 50,331,648 at A6 or 100,663,296 at A7, below the signed-int32 limit. This bound applies independently at both factor stages. The first stage's common real scale cancels inside the second-stage quantizer, and the final output receives that scale, the second common scale and the paid output factor scale. The table proof preserves the *chosen quantized integer map*, not the FP64 original-factor response or a particular FP32 reduction order.

## Work and actual images

For an `mlp_up` two-factor projection, `K=1024`, rank `384`, `N=3072`. Both stages together have 176 eight-code table blocks and 196,608 eight-sign response uses. The int16 half table has 22,528 entries, 45,056 bytes if resident across all blocks, at most 24,816 prep additions, 196,608 indexed reads and 193,152 row-reduction adds. The A6 `(4,4)` byte table has 2,816 entries, 2,816 bytes across those blocks, at most 4,576 prep additions, 393,216 indexed reads and 389,760 row-reduction adds. One streamed table block needs 16 rather than 256 live bytes. Both still need sign/index extraction, an A6 input quantizer at **each** stage, 49,152 integer-ladder group multiplications and reductions across the two factors, the rank intermediate, factor scales and final output writes. `v_perm`-style byte selection is an experiment to price, not a counted one-instruction gather. The 5.4-fold reduction in table preparation does not establish a faster reader against twice the lookup and accumulation work.

The [integer-ladder parent](../binary-shifted-scales/README.md) already measures the response quality of the *same* frozen two-choice map against the FP64 binary-factor map. Across four previously inspected input rows for each of sixteen `.55` images, A6 mean relative RMS by down/up/O/Q is `.036668/.033028/.036200/.027440`; A7 is `.018230/.015923/.017554/.014525`. The byte table reproduces A6's integer outputs exactly, so it inherits that conditional quality rather than claiming a new improvement. It saves one popcount/sign word compared with A7 but has markedly worse response error. Neither is a model-loss result.

`OPENBLAS_NUM_THREADS=1 python3 research/quantization-discovery/subbit/binary-table-width/measure.py` checks 16 packed paid images at layers 0, 7, 14 and 27, four previously inspected validation inputs each. It quantizes *both* boundaries under the parent two-choice `C=8` ladder, constructs byte A6 `(4,4)`, int16 A6 `(8)`, int16 A7 `(4,4)` and int16 A7 `(8)` tables, consumes actual packed U/V signs, and compares every 32-code group dot independently against unpacked integer factors. For each width, both partition choices produce identical intermediate and final integer SHA-256 values on every input. Observed first-/second-stage table ranges combined are `[-121,122]` for byte A6 `(4,4)`, `[-240,242]` for int16 A6 `(8)`, `[-245,245]` for A7 `(4,4)` and `[-487,488]` for A7 `(8)`. The complete-domain bound, not those observed extrema, licenses byte storage.
