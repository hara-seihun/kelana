# Exact softmax quotient of a short nibble-key history

The existing paid Q/K observer stores 32 signed-nibble coordinates per GQA group per key. Both query heads use the same key codes and coordinate steps. For a *two-key* causal attention row, storing two key vectors is unnecessary: store their signed coordinate differences. The first score is zero, and the second is the query dot the difference. This produces exactly the same real softmax and attention weights as the original two-code observer, including its existing lossy key and query quantization. The 32 differences lie in [-14,14], so a five-bit packed image takes 20 bytes/group, versus 32 bytes for two packed four-bit keys. Across eight groups that is 160 rather than 256 cache bytes for the two-key history. It does not save any weight bytes or the paid full K-norm producer.

With the existing signed-eight-bit query coordinate after multiplying by the frozen key steps, the two-key score difference is **one signed-byte dot of 32 products per observing head/group**, instead of two signed-nibble dots over *each* of two keys. The product counts compare unlike lane widths; they are not a fourfold instruction or time claim. The integer accumulator fits in signed 32 bits: `32 * 119 * 14 = 53,312`. There are 512 signed-byte products for both heads across all eight groups, instead of 2,048 signed-nibble products on the two-dot path for two keys. Expanding the 20-byte difference image into 32 signed bytes in registers, preparing 512 query coordinates, reducing/scaling the dots and storing a changed cache coordinate are real online costs. No GPU timing supports a latency claim. The equality is over real scores after integer dots and a common floating scale; it does not promise bit-identical FP32 softmax scheduling or logits.

## Why this stops helping at a long context

Here is a tight information bound for the *full* key-code domain, not for the actual model's reachable codes. Let each of `T` keys have `D=32` independent coordinates from the fifteen values `-7,...,7`. Require the ordered softmax probabilities for every possible basis query `e_i` and every key position. Two histories have this observation in common exactly when each coordinate differs by a constant across all `T` positions. Subtracting the first score proves necessity; adding a constant to all scores proves sufficiency. In each coordinate there is one representative whose minimum is zero, and the number of such sequences is `15^T - 14^T`. Consequently the exact number of score fibers is `(15^T - 14^T)^32`, and any fixed-length, jointly encoded history needs at least `ceil(32 log2(15^T - 14^T))` bits. Choosing the minimum as the origin realizes the quotient as a mathematical code; entropy packing and updating an existing cache when the origin moves are *not* free native instructions.

Relative to encoding independent base-15 symbols optimally, the gauge alone saves `-32 log2(1-(14/15)^T)` bits per group. At 2 keys that is 94.586 bits: the optimal quotient requires 155.455 bits, and the concrete 160-bit difference code is within five bits. At 32 keys the gauge saves only 5.377 bits/group. At 256 keys it saves **0.000000986 bits/group**. The 4-bit physical code's separate slack relative to base-15 entropy is not a softmax-gauge saving; exploiting it would require a different packing/decoding program. An independently chosen offset per cache block is not invisible to global softmax: cross-block scores need the missing offset restored.

`bound.py --output receipt.json` counts the fibers, checks two toy domains by exhaustive score-difference partition, and prints the length/rate curve. Its receipt is committed beside this report. No model inputs, GPU lock or serving state enter that exact combinatorial result.

The next native experiment is a short-context, two-key score consumer that keeps the difference in five-bit packed form and prices byte expansion, query preparation and cache update against the existing two-dot nibble path. For ordinary 256-token and longer histories, do not spend another iteration trying to remove whole-key cache bytes using a *lossless common softmax translation*. Change the lossy code family or exploit a measured restricted query/key domain instead. The proof assumes unrestricted basis queries, the full independent code alphabet, real-valued softmax and a joint history coder. It says nothing about approximation quality, query-rank restriction on actual text, or a nonlinear paid producer.
