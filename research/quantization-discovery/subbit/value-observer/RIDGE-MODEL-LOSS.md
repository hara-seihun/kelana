# Paid causal-ridge values on fresh model loss

The regularized layer-14 V/O decoder lowered held causal post-O squared error at the same 183,552-byte image rate. Does that transfer to gold loss when the damaged producer runs through the model? I froze both previously published ridge images and their corresponding unregularized paid controls, then forwarded twenty 256-token WikiText test windows, indices 32–51. These windows do not overlap the earlier right-basis model panel at 0–31, the causal train/validation capture, or the ridge selection procedure. Other programme studies have inspected some of these test positions, so this is a new image comparison, not a pristine corpus-level estimate.

The ridge-selected image improves NLL against its matched previous image by **0.18916 nat/token**, winning 17 of 20 windows. The ridge-uniform image improves by 0.15039, winning 15. Paired window bootstrap intervals for ridge minus predecessor, 50,000 resamples with seed 20260922, are [-0.29844, -0.06469] selected and [-0.29096, -0.01287] uniform. Selected minus uniform after ridge is -0.01311, 10 wins, interval [-0.12542, +0.10201]. Selected ridge versus original V/O is -0.00291, 10 wins, interval [-0.16215, +0.15592]. The right-coordinate allocation no longer has a robust language-loss advantage after equal-budget ridge fitting.

All four compressed arms retain **183,552 bytes (.466797 V/O BPW), 589,824 signed-grid factor terms/token and 384 logical BF16 value bytes/token**. The ridge changes paid two-bit O codes and FP16 output-row scales, not the right basis, ranks, cache width or decoder schedule. Selection used four leave-one-train-window-out causal response fits and penalty .01. No test token or gold loss selected its coefficients. This is BF16-expanded Hugging Face quality, not a native consumer or its latency.

The producer uses the refined binary body and norms in layers 0–13; the tied embedding/head, layer-14 Q/K and later layers are original. The original layer-14 V/O also sees this damaged producer, hence its 13.098 NLL is not a healthy-model baseline. Outputs use BF16 SDPA with TF32 disabled, 255 teacher-forced predictions per window. Teacher KL compares each image to original V/O on this *same* quantized producer. The improvement from response regularization survives into language loss, but leaves the model catastrophically worse than its original ~3–4 NLL. It does not justify native layout work or another local layer-14 code sweep. The next experiment should fit the early quantized V/O and MLP together on broader train gold/teacher continuation, with both the tied quantized producer and later body present; hold out text to choose an image before pricing a narrow consumer.
