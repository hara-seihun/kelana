# A regularized causal decoder at the same narrow V/O rate

The previous layer-14 right-basis study fits the paid two-bit output codes to four quantized-producer train windows and scores .336551 held causal post-O relative squared error at 192 shared value coordinates. Its equal-rate uniform-rank control scores .336175. Is the held error caused by the *frozen narrow features*, or by choosing output codes from an almost-perfect train fit? This experiment holds the right codes, scales, ranks, quantized producer, original Q/K and BF16-rounded narrow values fixed. It changes only the left decoder fit.

For a split with feature matrix `Z` of shape `1024×384` and original post-O output `Y` of shape `1024×1024`, an unrestricted real left decoder has loss `||ZC-Y||²`. The thin SVD `Z=USVᵀ` gives `C=V S⁻¹ UᵀY` on its nonzero singular directions, and `||Y-UUᵀY||²` is the global minimum over all real linear decoders on **that split**. The rank is 384 on both splits for both images at a relative singular-value cutoff of `1e-8`. A decoder fitted on validation is an oracle that uses held targets, not an attainable generalization bound. Its tiny loss therefore cannot certify a useful weight image. It does show that a fixed 384-feature linear response has enough *within-window* degrees of freedom to replay these 1,024 outputs with little error.

The unregularized train-optimal decoder triples held error. This is not a rank shortage proved by the small train residual; it is a severe split transfer problem. We then solved `min_C ||ZC-Y||²/N + λ tr(ZᵀZ/N)/384 ||C||²` with a single coefficient matrix for every window. Seven relative penalties from `1e-5` through `10` were selected by four leave-one-*train*-window-out fits, never by validation. Both arms select `.01`. The resulting real decoder scores .268313 selected and .273161 uniform held, with train errors .002964/.003173. Those dense FP32 decoders need 393,216 coefficients or 1,572,864 bytes and dense floating arithmetic. They are diagnostic controls, not sub-bit images.

Quantizing the selected train-ridge decoder **once** into the existing odd two-bit left alphabet and one existing FP16 output-row scale per head changes no right code, rank, descriptor, scale count or online factor work. The selected image scores .303868 held, down **9.71%** from the preceding .336551 at the same **183,552 V/O bytes (.466797 BPW), 589,824 signed-grid factor terms/token and 384 logical BF16 value bytes/token**. The uniform image moves .336175 to .310756. The selected image now wins this held causal error comparison, though its train loss rises to .054368 from .008251. Selected-rank held per-window errors move `[.304919, .611981, .310459, .114353]` to `[.270179, .520502, .288362, .134042]`: the fourth window worsens. This is a paid response construction, not a complete-model quality or native-speed result.

The online observation is the original-Q/K causal post-O output on captured actual layer-14 inputs after quantizing layers 0–13's body and norms. The original V/O supplies the target. There are four 256-token train windows and four distinct validation windows. The Python replay uses FP32 matrix products with BF16 narrow-value rounding, as in the preceding right-transfer comparison. Training the ridge and its leave-one-out selection adds offline solve work; inference consumes the same factor planes and code path as the previous paid image. The held oracle and held scores were never used to select `.01` or the stored code.
