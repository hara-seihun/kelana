# Unequal value ranks admit a seven-line, zero-crossing cache

The paid 192-coordinate narrow V/O images have a useful cache coordinate that uniform rank 24 cannot use. Layer 0 keeps ranks `[28,28,28,28,28,4,28,20]`; layer 14 keeps `[28,28,28,8,28,16,28,28]`. In either image six 56-byte value groups each occupy one 64-byte line, while the other two groups fit together in a seventh line. The group order changes, not the codes, attention weights or output-head assignment. The paired heads still have distinct scores and ordered accumulations.

| Image and layout | Value bytes/key | Distinct lines/key | Group-line requests/key, separate heads | Paired heads |
| --- | ---: | ---: | ---: | ---: |
| Selected 192, original compact group order | 384 | 6 | 26 | 13 |
| Selected 192, best reordered compact | 384 | 6 | 24 | 12 |
| Selected 192, reordered with gaps | 448 | 7 | **16** | **8** |
| Uniform rank 24, compact | 384 | 6 | 24 | 12 |
| Uniform rank 24, best seven-line layout | up to 448 | 7 | 20 | 10 |
| Full rank 28, compact | 448 | 7 | 28 | 14 |
| Full rank 28, aligned | 512 | 8 | 16 | 8 |

Both selected images attain these same cost points. The seven-line layout puts each 56-byte group at a line start, then puts the 8+40 or 16+32 bytes of the small groups together in the seventh line. The layer-0 layout may be expressed as offsets `[0,64,128,192,256,312,320,384]` indexed by original group ID; layer 14 uses offsets `[0,64,128,384,192,400,256,320]`. A group lookup uses its compile-time offset, not an online shuffle. The layer-0 layout can move its 8-byte group to offset 384 beside the 40-byte group; the search's lexicographic witness places it in an earlier line's unused tail. Both fit seven lines. Keeping group IDs on the projection and decoder sides preserves the same composed real map. FP32/BF16 native scheduling and bit identity must still be checked in a kernel.

The extra 64 cache bytes per key over selected compact buy eight fewer 64-byte group-line requests across the two separately scheduled heads, or four fewer in a paired-head unit. For a 4,096-key prefix across 28 layers, that is 7 MiB more resident KV than compact and 56 MiB fewer *requested* V line bytes per generated token for separately scheduled heads. Those are not off-chip bytes or a measured latency saving. The new seven-line coordinate also uses 7 MiB less resident KV than the full-rank-28 eight-line alignment at that prefix, while making the same 16 separate-head requests. The stored 183,552-byte V/O image and .466797 BPW rate do not change. This statement holds if all 28 layers had the selected rank profile; only layers 0 and 14 have paid selected images today.

`layout_opt.py` reads the frozen image receipts and exhausts the finite layout grammar. A group is a contiguous, ordered BF16 segment, one slot is eight bytes, groups may be permuted and gaps inserted, no bytes are duplicated, and lines are 64 bytes. The dynamic program's state is the placed-group mask and next free slot. It tries every remaining group at each possible slot through the next line boundary and minimizes crossing count, then terminal byte offset. No optimal layout needs to skip an entire empty line: deleting that line preserves all crossings and shortens the layout. Each group fits within one line, so every crossing adds exactly one group-line request per head. This proves the table's optima within that grammar, not a universal transaction bound or a GPU cache prediction. A six-line packing has four unavoidable crossings for both selected images. At seven lines uniform rank 24 still has two; eight 48-byte groups cannot fit in seven separate lines without crossing.
