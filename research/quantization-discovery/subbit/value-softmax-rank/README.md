# A paid block-gain limit for the narrow V/O image

The rank-28 shared value image already stores FP16 scales for each narrow input coordinate. I asked whether the causal post-O error left in that image is mostly a bad *coordinate amplitude*, which we could repair without changing its 208,640 bytes, two-bit codes, 688,128 signed-grid terms/token or 448 logical BF16 value-cache bytes/token. It is not, at least on these two frozen original-producer captures.

For each GQA group, split its 28 coordinates into seven blocks of four. Both heads share one gain per block. Fix the existing right/left codes, scales, original Q/K causal probabilities and teacher V/O output. Let `c_j` be a block's complete causal contribution after both heads' O slices, and `y` the teacher output. The 56-gain objective is `||Σ_j g_j c_j - y||² / ||y||²`, not an isolated value reconstruction error. With `C` containing the flattened block responses, its normal equations are `C Cᵀ (g-1) = C(y-Cᵀ1)`. For ridge strength `λ`, add `λ diag(C Cᵀ)` to the left matrix. All unconstrained train and held optimum gains in this panel are positive, so the unregularized solution is also the exact nonnegative optimum on each observed split. The held-only optimum is a diagnostic bound for this frozen 56-gain family, **not** an image selected from held data.

Eight 256-token train windows supply the fit. Leave-one-train-window-out relative squared error chooses `λ` among 0, .0001, .001, .01, .1, 1 and 10; it chooses .1 at both layers. Four separate, previously inspected validation windows supply held scores. The candidate folds each four-coordinate gain into the existing right FP16 scale slots and replays the BF16 narrow cache. No gain multiply is added online.

| Layer | Train base → selected | Held base → selected ideal → paid BF16 | Held-only optimal gain bound |
| ---: | ---: | ---: | ---: |
| 0 | .222819 → .222616 | .378887 → .380105 → .380103 | .373205 |
| 14 | .164176 → .163805 | .326195 → .325150 → .325149 | .310006 |

Layer 0 gets worse in all four held windows; layer 14 improves in all four by about .00105 aggregate. The exact train optima are only .222615 and .163801, so more precise fitting of these same 56 gains cannot buy much on train. The larger held oracle gap at layer 14, .326195 to .310006, comes from a gain vector with entries as low as .485, while its train optimum stays above .910. The fit's *data and observation*, not the solver's capacity, are the issue. These captures have been inspected often; the result is a bounded negative for a frozen original-producer image, not a fresh-text generalization claim. Do not spend native work on this gain-only variant. Learn the right basis and codes on quantized producers with broader composed-model gold/teacher continuation instead of searching more gains on these captures.

This is a continuous exact quadratic and a separately replayed paid BF16 map. FP32 block-response composition and changed BF16 rounding need not agree bitwise. It is not a model NLL result or a native speed measurement. The packed candidate images are retained as experiment evidence, not selected runtime implementations. Bonsai's executable, GPU and resident service did not change.
