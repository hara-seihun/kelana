# Sub-bit competitors and the first fair race

September 22, 2026. This is a comparator map, not a claim that a Llama-2 result transfers to Bonsai's 64-layer ternary hybrid. Start from Kelana's [prior art](../../PRIOR-ART.md) and [assignment contract](../../MATHEMATICS.md): the representation, input domain and consumer all belong in the claim. The Bonsai rate account at `/path/to/workspace/projects/bonsai-halo/docs/throughput-budgets.md` is more concrete than a nominal bit-width: HALO stores 26 code bytes plus a two-byte scale per 128 ternary weights, **1.750 physical bits/weight**; its streamed matrices total 5.600 GB per pass. It does not follow that a different model at 0.55 bits runs 1.750/0.55 times faster.

## What to beat

The quality cells below are *authors' reported measurements*, not a cross-paper leaderboard. W2 means WikiText-2 perplexity, lower is better. Rates are the paper's declared weight-matrix rate unless the cell explicitly says full-model file. For each model, keep its tokenizer, unquantized tensors, context window and evaluation implementation fixed before drawing a Pareto curve.

The apparent sub-bit STBLLM rows are not eligible at their nominal sparse nonzero density: NanoQuant [Table 2](https://arxiv.org/html/2602.06694) puts its 6:8 and 4:8 variants at **4.00 and 3.50 total BPW** after masks and auxiliary weights, not 0.80/0.55. The same table reports BiLLM **2.88**, ARB-LLM **2.51**, HBLLM **3.25**. Count their metadata, not the sparsity label. QTEA's [recent 1.7-BPW PTQ and lookup kernel](https://arxiv.org/html/2609.00224) is an optional ternary control, not a sub-bit result; its 7.2x generation claim is on its own customized hardware, not this GPU.

## The matched experiment

1. Freeze a single **pretrained** small base model and tokenizer. Record FP16 reference logits, WikiText-2/C4 perplexity with identical length and stride, and a fixed set of zero-shot tasks. Run NanoQuant at 1.00/0.80/0.55 and at least one 2-bit QTIP or QuIP# control with the *same calibration examples and calibration-token budget*. Record training/fine-tuning separately; QAT LittleBit and ParetoQ are upper-bound quality references, never pretend they are PTQ at equal cost. Replicate at two seeds if the small-model gap is near noise. A Bonsai-only ternary model cannot honestly be compared numerically to Llama-2-7B rows; quantize the same original weights or label the cross-architecture result descriptive.
2. Publish both `matrix payload bits / quantized matrix elements` and `8 × complete model-file bytes / original model parameters`, plus a tensor-by-tensor manifest: indices, low-rank factors, scales, codebooks, transforms, sparsity masks, padding, embeddings, norms and head. Also report peak runtime allocation, KV cache and any scratch lookup table separately. A 0.55 matrix BPW with a retained FP16 head is not a 0.55 full-model BPW.
3. On **gfx1151**, reimplement or port the winning packing/consumer, pin model and shape, then compare batch-1 decode and batched prefill at fixed context and token budget against resident HALO/A4, QTIP-like direct trellis and conventional unpack-then-dot INT4. Count actual bytes at DRAM/L2, vector and matrix instructions, registers/spills, scales, inter-stage writes, packing/lookup construction and boundary conversion. NanoQuant's packed sign/FMA kernel is a valid direct-consumption competitor but its two low-rank passes change arithmetic and scratch traffic. NVIDIA CUDA throughput and tensor-core-specific speedups are *not* AMD measurements. On CPU use T-MAC on the same processor and thread policy against an unpack-based ggml control. No competitor may win on BPW alone while moving work into an uncounted decoder.
4. Preserve the useful structural discovery when the native endpoint loses. Kelana's equal-fiber relabeling witnesses and [consumer-aware rate contract](../../MATHEMATICS.md) permit a shared label across operations. A one-instruction packed map still needs measured producer packing, register placement and the next consumer; semantic relabeling is not free.

## Task ladder, not tau first

Use fixed-token teacher-forced loss and W2/C4 perplexity first. They are cheap, continuous and catch failures like GPTQ's 2-bit Llama-3-8B W2 **160** versus ParetoQ's **8.0** in ParetoQ Table 1. Then run a small, fixed-seed, deterministic LM-evaluation set with exact accuracy and item-level paired differences. Only after a candidate survives those gates, test short tool-use episodes with frozen tools, policies, simulated user model and versioned task set. Track success per episode, valid tool-call rate, first divergence from the reference, prompt/decode latency, tokens and retries. An agent-quality claim needs enough episodes for confidence intervals, not a single pass-rate point.

[τ-bench](https://arxiv.org/abs/2506.07982) is a useful *later* acceptance test for a model still capable of multi-turn policy and tools, not a first quantization scaling measurement. The [maintained repository](https://github.com/sierra-research/tau2-bench) now calls the suite τ³-bench, includes airline/retail/telecom and a user simulator, and says its July 2026 v1.0.1 banking grading changes make earlier scores non-comparable. Simulation and stochastic user turns add variance and cost exactly when the first question is whether the quantizer preserved logits. Pin a repository commit, base split, agent and user models, task IDs, decoding configuration and multiple trials before comparing tau success. If the small model has near-zero baseline tau success, floor effects make tau incapable of resolving sub-bit progress; use the loss and short tool ladder instead.

**Shortlist:** NanoQuant 0.55/0.80/1.00 for pretrained sub-bit quality and packed-sign execution; LittleBit 0.30/0.55 and ParetoQ 1.00 only as QAT quality references; QTIP 2-bit for finite-state direct execution; Marlin group-128 W4A16 and T-MAC CPU for honest kernel controls. First unanswered comparison: how much of NanoQuant's sub-bit quality survives a *matched calibration budget on the same small model*, and whether two binary factor passes beat a single packed gfx1151 consumer after all metadata and conversions are counted.
