# Spend compute to avoid reads during single-stream decoding

This is a menu of experiments, not a claim that twelve new decoding algorithms work. The scarcity here is recurring model and KV traffic; a candidate operation is useful only when its extra arithmetic fits under that traffic or buys enough accepted tokens to avoid another read. The [finite maps](../finite/README.md) already demonstrate that twice the representation bytes can be faster with the right consumer. The [Qwen pilot](../qwen/README.md) has a harder immediate limit: its top-16 candidate pool misses many target continuations. Composition can retain labels across operations that do not individually descend to them, but no existence theorem pays for a native producer or consumer [composition](../../composition/README.md). The [radix-64 toy](../../toy2/radix64/README.md) saves an online dot by changing the output coordinate, while explicitly leaving wire and downstream conversion costs open.

For a batch-one target, write `W` for weights streamed per target pass, `K(L)` for KV bytes at context length `L`, `B` for effective bandwidth, `F(n)` for target arithmetic for `n` verified nodes, `C` for usable compute throughput, `D` for draft latency, and `E` for expected emitted tokens including the target bonus. A first screen is

`T/E = [D + max((W + K_ver(L,n))/B, F(n)/C) + T_boundary] / E`.

Compare it with `T_one = max((W + K(L))/B, F(1)/C)` on the *same* model and context. Savings require `T/E < T_one`. This roofline omits launch overhead, attention-mask layout, cache contention, register spills and early rejection; measure those rather than treating the formula as a throughput result. One verifier pass may stream weights once across many positions, but attention/KV traffic and activation writes need not stay constant. If verification is split into two launches, budget `W` twice unless the first pass really retains its weights. A cache hit or another user's concurrent work changes the effective `B`.

Exactness has several separate contracts. Greedy generation needs the exact winner and a continuation state identical to the target's, including its KV updates. Stochastic target sampling needs the target distribution or an exact rejection/sampling construction; an argmax certificate is insufficient. A draft's cheap approximate state can never silently become the target continuation state. For every suggestion below, compare the complete producer, target verifier and accepted-state handoff, not isolated candidate coverage.

## Ranked experiments

Each item names what to observe, what bytes it hopes to avoid, what computation replaces them, the first cheap discrimination and the status relative to prior work. The ordering values cheap, decisive experiments over architectural ambition.

1. **Certify an easy greedy winner before reading all output-head rows.** Observe exact target argmax, with target hidden state/KV already computed. Stream feature columns of every vocabulary row in decreasing expected discrimination order. Partial logit `s_t` and a bound `r_t` on the unvisited dot give a certificate when `s_c-r_c > max_{t≠c}(s_t+r_t)`; otherwise continue to the full head. This trades interval reductions and comparisons for omitted head-weight bytes, not transformer-layer bytes. It wins only if `B_saved/B > T_bounds + T_irregular + T_extra_launch`; a separate partial-kernel launch that rereads the head may lose. Test a tiled real tied Qwen head with bounded input coordinates, count certified contexts and measured head transactions, then compare one-pass full GEMV and a gather-friendly static tile order. The executable finite-head probe below establishes correctness and a synthetic byte frontier, not a real-model gain. The interval certificate is standard branch-and-bound, so the proposed contribution would be a cheap GPU data layout and suitable bounds, not the mathematical rule.

2. **Verify with a progressively sharpened but *certified* target.** Observe exact greedy winners at verified nodes, plus exact accepted KV. A first pass might establish logit intervals from quantized or skipped weight blocks; uncertain nodes pay a correction pass. Bytes saved are target weight or KV blocks skipped on nodes that certify. The added work is bounds, second-pass launches and irregular access. The test is a single layer or exact output-head certificate against a full-pass baseline, recording uncertain-node fractions by depth and whether the second pass rereads weights. It must have error bounds valid for the actual floating-point kernel, not just integer quantization cells. LayerSkip already does early-exit drafting and full-model verification [4]; certifying *target* decisions without completing target work is a different requirement and remains an unproven system design.

3. **Schedule tree nodes by byte value, not just probability.** Observe target-prefix coverage and wall time with exact tree attention. The existing finite result optimizes equal-price node mass, while Sequoia [3] already optimizes speculative trees and hardware size. Here a node's cost includes its depth-dependent KV traffic, tree-mask tiling and spills; allow unequal prices and count shared target-weight reads once per verification batch. Spend extra draft/tree-selection compute to omit expensive low-yield nodes. A node `v` is attractive only if its marginal reduction in expected future target reads exceeds its marginal verification time; simply ranking `p(v)/cost(v)` is not generally optimal with ancestors. Enumerate tiny ancestor-closed trees and compare Pareto-optimal coverage/estimated traffic with the equal-node optimum, then time corresponding masks. This is hardware-specific scheduling research, not a novel tree verifier.

4. **Keep a joint branch state in labels the next operation consumes.** Observe the exact paths for every independent random stream, and ultimately target acceptance and future state. Produce a small transition map directly in a SIMD-friendly byte coordinate, compose functions across positions or across jointly tracked branches, and avoid repeated token-ID decoding. Extra work builds hypothetical successors; saved bytes are intermediate score arrays, token/KV rematerializations and recurrent map reads if the consumer is direct. Compare full map producer plus native shuffle/permute against direct visited-state sampling and candidate-tree construction, at equal target coverage. The CPU finite experiment has a 14.7 ns constructed byte-prefix path versus 31.5 ns direct on its threshold toy; the learned Qwen bridge has no such timing. Whole-map composition is already established here. The question is whether real candidate production can afford every hypothetical row.

5. **Put unequal draft compute on high-value tree nodes.** Observe target coverage gain per extra producer microsecond, *conditioned on prefix survival*. Use a cheap independent draft everywhere and conditional correction or a larger candidate pool only for nodes with high survival probability and poor calibrated draft recall. This can save target reads by raising `E`, at the cost of more scoring and a larger verifier tree only where useful. Measure oracle pool ceiling by depth, then ablate selective correction against uniform correction at equal draft FLOPs and equal verification-node count on held target continuations. Adaptive trees are not new [1,3]; the joint node-specific fidelity allocation is a candidate experiment, not established novelty. The current Qwen pool ceiling makes improving the pool more urgent than merely reshaping a 64-node tree.

6. **Use target feature production to draft the next verification group.** Observe complete launch-to-launch accepted tokens, not auxiliary-head accuracy. While finishing one exact target pass, emit multiple cheap candidate heads or a compressed state that feeds a candidate map; reuse already resident activations to avoid a separate draft model's weight stream. Price additional head bytes and projection arithmetic against one removed target pass, including the probability that a candidate is discarded. Medusa [2] and EAGLE [5] already establish the broad shared-feature and multi-head strategy. A useful distinction would be producing a branch-state label tailored to the verifier's consumer and quantifying total extra HBM transactions. First compare an auxiliary head plus tree against the present learned 8 MiB borrowed-head implementation, not against a fictitious free draft.

7. **Stage draft rows into a reusable, verifier-aligned preparation.** Observe candidate paths and acceptance under the same proposal law. Prepare invariant output rows, quantized threshold tables or recurrent transition coefficients once per model version; at runtime compute only context-dependent coordinates and feed native map operations. This exchanges preparation storage and arithmetic for recurring draft-row reads and conversions. If preparation costs `P` bytes-equivalent and saves `Δ` recurring bytes per step, reuse needs `N > P/Δ`, before accounting for cache residency and invalidation. Test cold/warm sessions and checksum the prepared mapping against the original proposal. The radix-64 toy proves a structurally similar prepared-constant identity, not that Qwen's context-dependent scores admit a cheap preparation.

8. **Draft against a shorter KV view, verify against full context.** Observe exact final target samples and target KV. A draft reads a bounded window or selected KV blocks while the verifier reads the full context once for several candidates. Saved bytes are recurring draft KV loads as `L` grows, with extra compute for selecting/repacking context and poorer proposal quality. The break-even is `(D_full+V_full)/E_full > (D_short+V_short)/E_short` in latency per emitted token, where `D` is per-round drafting time and `V` is verification latency; measure both sides across context lengths. MagicDec [6] uses sparse-KV drafting for long contexts already. The local question is whether single-stream latency, not its paper's long-context throughput setting, benefits on this hardware.

9. **Choose the speculative horizon from measured memory/compute balance.** Observe accepted tokens per second, not acceptance alone. Estimate `E(n)` from held target continuations, and measure `D(n), K_ver(L,n), F(n),` spill and launch costs; choose `n` minimizing the displayed `T/E`. At short `L`, weight rereads may dominate; at long `L`, verifier KV and attention-mask cost can dominate. The extra work is calibration and dispatch; saved bytes are aborted unprofitable verification nodes or avoided passes when longer horizons pay. Compare a fixed six-token chain, fixed 6/18/32/64-node trees and one held-out policy. Hardware-aware horizon choice is in Sequoia [3], so only a new measured operating region or joint representation changes the story.

10. **Coalesce exact verification states that truly share future computation.** Observe exact continuation KV and target distribution. A tree may have equal token suffixes but distinct prefixes; merging by token ID alone is invalid. Search for equal *reachable target states* or an exact sufficient state under the next consumer, and merge only with a witness that both continuation and observation agree. Saved bytes would be duplicate KV and target arithmetic for genuinely equivalent nodes; extra work is hashing, equality checks and map lookup. On a finite-state target, enumerate equal-state prefixes and count eliminated nodes; on a transformer, first seek a meaningful certificate rather than asserting collisions. DAG sharing and automaton minimization are standard; actual equivalence at neural states is probably too rare, so this ranks low.

11. **Spend extra verification compute where uncertainty is expensive.** Observe exact target result under a specified greedy or stochastic contract. If a cheap approximate target produces an ambiguous short list, compute exact scores only for a certified superset of possible winners, using interval bounds on omitted candidates. Candidate-specific refinement could skip low-value output rows, but full transformer/KV state still must be available for future tokens. The first test compares certified row subsets against the full head and the uniform prefix certificate in item 1, counting irregular gathers and all weight bytes. This is branch-and-bound applied to head access; it is not an exact stochastic decoder unless probability mass of every omitted row is handled by a separate exact construction.

12. **Carry the branch coordinate through target-side fused operations.** Observe the same verified token and exact accepted KV/logits, rather than reproducing internal attention scores. Combine branch mask, position mapping, packed token labels and KV write selection so the verifier never writes a dense temporary per candidate only to gather accepted rows later. Extra address arithmetic, register pressure and larger fused kernels trade against intermediate HBM writes/reads and launches. Start with an instrumented tiny tree verifier: count actual bytes at each boundary, then fuse the largest redundant boundary and compare the end-to-end kernel with a tuned unfused baseline. Tree attention is established [1,2]; whether a particular packed label reduces memory traffic is an implementation question. If spills exceed avoided traffic, stop.

## One executable discriminator

`python3 research/speculative-maps/compute-bandwidth/frontier.py` regenerates [frontier.json](frontier.json) using only the Python standard library. It fixes eight target classes, sixteen signed integer input coordinates in `{-1,0,1}`, 4,096 seeded contexts and int16-range weights with decaying feature scales. The all-features GEMV is the exact greedy reference, including lowest-index tie breaking. After each feature the probe bounds every class's remaining dot by the sum of absolute unvisited weights; strict interval separation certifies the winner. It asserts equality with the independently computed full dot for every context and order. A tied or uncertain last step performs the full decision. The comparison baseline reads all `8 × 16 × 2` head-weight bytes per context; orders use the same weights and inputs.

| Feature order | Mean features read of 16 | Counted head-weight bytes | Bytes omitted | Extra candidate comparisons, worst-case mean |
| --- | ---: | ---: | ---: | ---: |
| Large-scale first | 8.675 | 568,512 | 45.78% | 60.72 |
| Fixed random | 13.017 | 853,056 | 18.65% | 91.12 |
| Small-scale first | 15.933 | 1,044,176 | 0.42% | 111.53 |
| Full GEMV | 16 | 1,048,576 | 0 | 0 |

This is a count of hypothetical *streamed* weight bytes, not file size, cache misses, latency or transformer-wide savings. Bounds are precomputed from weights, so the table excludes their storage and reads, input loads, feature scheduling, vectorization loss and launch cost. The extra-comparison column assumes checking seven challengers after every visited feature, even when the actual `all` short-circuits. The large-scale ordering was chosen from the fixture's known scales; it was not fit to those 4,096 contexts. The full reference is a strong exact-result baseline, but a real native comparison must include an optimized contiguous full-head GEMV, which may beat irregular partial reads despite 45.78% fewer counted bytes. Real hidden coordinates have no automatic `|x|≤1` guarantee. This toy isolates one potentially useful bandwidth/compute exchange and says nothing about stochastic correctness or whether the head dominates total inference time.

## Prior work used here

1. [SpecInfer](https://arxiv.org/abs/2305.09781) builds candidate trees and verifies them with tree-based target execution. Tree verification itself is prior art.
2. [Medusa](https://arxiv.org/abs/2401.10774) adds multiple decoding heads and tree attention. Shared feature drafting is prior art.
3. [Sequoia](https://arxiv.org/abs/2402.12374) optimizes tree structures and hardware-aware speculative decoding. Fixed-cost and hardware-aware tree optimization are prior art.
4. [LayerSkip](https://aclanthology.org/2024.acl-long.681/) uses early exits and shared activations for self-speculation, followed by full-model verification. An early-exit draft is not a target certificate.
5. [EAGLE](https://proceedings.mlr.press/v235/li24bt.html) drafts at the feature level while addressing feature uncertainty with shifted token information.
6. [MagicDec](https://arxiv.org/abs/2408.11049) analyzes long-context bottlenecks and sparse-KV drafting. A short-KV draft by itself is not novel.

Kelana already has [a real Bonsai final-head certificate study](../../argmax-observer/final-head/README.md). Its transaction-aware modeled saving is about 7–11% of head traffic, before native bounds and routing costs, much less than this toy's 45.78% unpriced saving. A new head experiment should beat or cheaply realize that existing construction rather than repeat it. The immediate speculative pilot priority is fixing candidate support and reusing already paid target decisions before spending more verification nodes. A head-certificate native comparison can proceed once its complete data path earns the attempt. None of these experiments needs more compute hardware.
