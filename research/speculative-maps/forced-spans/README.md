# Forced spans are known outputs, not free model state

A grammar can make the next emitted token certain while leaving expensive work on the path to the next *uncertain* token. That distinction is the opportunity. We should compile the complete map from the current model and grammar state through a forced span to the first free choice, not repeatedly ask the model to choose a token whose allowed set has size one.

This note uses **locally masked decoding** as its exact target. Given model probabilities `p(t | h)` and an allowed token set `A(g)`, the next-token law is `q(t | h,g) = p(t | h) / sum_{u in A(g)} p(u | h)` for `t in A(g)`. If `A(g)={t*}`, `q(t* | h,g)=1` whenever `p(t* | h)>0`. No logits, softmax, RNG or target-versus-draft acceptance test is needed to *select* that token. But the resulting model state must still be equivalent for every future observation. The law obtained by conditioning the **entire model sequence** on eventually satisfying a grammar is generally different from this local projection. Skipping logits is also wrong if the caller asks for original-model likelihoods or scoring of the forced string. The claims below concern exact local masking and state continuation, not unconstrained model sampling or global conditioning.

## Eight concrete mechanisms

1. **Elide the decision head at token-singleton positions.** The grammar runtime advances its state and emits the one token ID without vocabulary projection, mask, normalization or sampling. Compute the body/state update before the next non-singleton decision. Its benefit depends on whether the model head is a separately skippable kernel and whether the previous forward already produced otherwise useful logits. A singleton after EOS handling or tokenizer alignment must be proved at the **token** level, not inferred from punctuation in the output text.

2. **Resolve forced bytes against the tokenizer before claiming a forced token.** For a literal `{"a":`, a vocabulary might contain `{"`, `"a"`, `":`, and `{"a":` as separate tokens. Several legal token paths emit the same bytes; a token may even contain the first variable byte, such as `":0`. In that case the byte automaton's next character is certain while its next token has several admissible IDs, and those IDs may induce different model states and probabilities. Build a product of grammar parser state and tokenizer-prefix state. Jump only through a uniquely determined token path; otherwise retain the allowed-token alternatives or explicitly change the target distribution to a declared canonical-token policy. Stop a jump before any token crossing an unknown field boundary.

3. **Prefill a known token run in one target invocation.** Once token IDs are known, causal transformer layers can process the run in parallel using their normal prefill attention mask, installing KV entries for every forced position. The output projection is required only at the next free-choice position. This trades `m` serial decode launches for one chunk invocation; it does **not** remove the layer FLOPs or KV writes, and a prefill kernel can have a worse total byte bill for a short run. Preserve absolute positions, RoPE offsets, causal masking and attention-cache layout. An API that accepts `m` known input tokens but still makes `m` autoregressive calls has not implemented this mechanism.

4. **Contract a forced span's recurrent transition.** For `h' = A_t h + b_t`, compose `(A_2,b_2) ∘ (A_1,b_1) = (A_2 A_1, A_2 b_1+b_2)` and apply the resulting pair once. In a scalar, diagonal or otherwise cheaply composable state, a fixed template can prepare the pair offline. If the token IDs are known only at runtime, computing the summary still has a cost; scan or structured kernels may help latency even if arithmetic work stays comparable. For a dense `d × d` transition, building the full product may cost more than `m` matrix-vector updates. A gated state transition only fits this shortcut if its factors are known independently of the incoming state, or a certified reduced-state map is found.

5. **Compile the span directly into a finite reachable-state transition.** When the incoming state has a genuinely small reachable domain, tabulate the complete span `F(s)` once, including the state information future consumers need. A native byte shuffle or compact lookup may replace many per-token operations. A table indexed solely by grammar state is invalid if two histories at that state have different KV/recurrent states. Keep representation-entry, table traffic and exit costs explicit; an exponentially large hidden-state table is not a proposal for a full transformer.

6. **Compile fixed-template output observers.** For a schema that always emits `{"kind":"...","value":`, the template bytes need not pass through a per-position vocabulary head. A producer can emit the fixed text and compute only the boundary state that the variable value's head observes. If an application consumes structured fields rather than a token transcript, its final observer may permit an even smaller boundary representation. Reporting exact original token IDs, per-token logprobs, or arbitrary continuation narrows that freedom. This is the same whole-map question as the contracted FFN observer, with a much larger and more stateful input domain.

7. **Quotient the grammar machine, then prove the model boundary separately.** Merge parser states only if every possible future token string is legal from both, with the same completion policy. That reduces masks and enables cached deterministic continuations for repeated schema states. Equal grammar futures do *not* imply equal model distributions. A valid joint quotient additionally needs equivalent next observed probabilities and matching successor equivalence for each permitted token. Treat the grammar quotient as a producer for a combined grammar/model-state search, not a license to discard KV.

8. **Contract deterministic edges of speculative trees and batch shared templates.** A verifier's branch with one admissible token has conditional probability one under the locally masked law. Carry the chain as known-token prefill and spend proposal/verification nodes only at actual choices; at a choice, cache every candidate's distinct continuation state. Across requests sharing a schema literal, reuse prepared token alignment and static transition parameters, while batching each request's dynamic state application. This changes scheduling and memory layout, not the exact target law; a transformer still computes its per-request KV. Tree layout, cache adoption and batch size determine whether fewer decisions improve throughput.

## Executable exact map and a negative control

[`exact_span.py`](exact_span.py) defines a finite-state language-model toy over the field `F_97`. Each token changes state by `h' = a_t h+b_t (mod 97)`. The grammar forces `(4,7,9,4)` and then allows tokens `{0,1}`. At the free choice, two positive state-dependent integer weights give an exact rational locally masked distribution. Preparing the forced run yields a single affine pair `(A,B)`. The script checks all 97 incoming states: ordinary token-by-token execution and the contracted update produce the same state, next-choice distribution and state after either possible next token. It also compares against *omitting* forced-token updates, which changes the next-choice law. Run from the repository root:

```sh
python3 research/speculative-maps/forced-spans/exact_span.py
```

A reusable fixed template of length `m` costs `m` transition-composition steps in preparation, then one multiply, add and modular reduction per incoming state rather than `m` of each. Grammar emission still outputs `m` tokens or bytes. The toy has a scalar state, no attention and no measured serving speed. For a one-off dynamic span, preparation costs `m` compositions and the online arithmetic may lose. In a transformer, omitting the forced pass is especially wrong: each new token adds keys and values that a later query can attend to even if that token had probability one under the grammar.

A two-token counterexample makes the point without any head calculation. If a forced token has `h' = 2h+1`, and the next optional token's probability is `h'/97` for `h'` in range, starting at `h=1` gives `3/97`, not `1/97`. The grammar has removed the decision, not the causal effect. The script uses a different, fully enumerated positive-weight law.

## What to measure next

Trace actual JSON/code outputs at the **token-ID** level. Record lengths of singleton-support runs, ambiguous byte-forced runs, unknown value boundaries, reusable template frequencies and request batch sizes. For each path, compare `L_decode ≈ m(L_body+L_head+L_launch)` with `L_prefill(m)+L_boundary_head+L_parser` and with a contracted-state variant only where a sound state map exists. Count model FLOPs, KV writes and reads, head work, launches, preparation, parser/tokenizer work and conversion. Benchmark the full consumer path, including the first unconstrained token and one subsequent token; compare exact locally masked probabilities or chosen token law *and* continuation state. A success at output-string equality alone is insufficient.

## Prior art

- [DOMINO, ICML 2024](https://proceedings.mlr.press/v235/beurer-kellner24a.html) addresses grammar/subword misalignment and uses speculative constrained generation. It is a reminder that character-level certainty is not token-level certainty.
- [Grammar-Aligned Decoding, NeurIPS 2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/2bdc2267c3d7d01523e2e17ac0a754f3-Paper-Conference.pdf) distinguishes locally restricted decoding from sampling the base model conditioned on a valid full completion.
- [Copy-as-Decode, 2026](https://arxiv.org/html/2604.18170v1) uses grammar-enforced copy spans and parallel prefill to update a transformer's KV cache rather than running serial per-token decode. Its editing/copy grammar is more specific than arbitrary JSON literals.
- [Parallelizing Linear Recurrent Neural Nets Over Sequence Length, 2017](https://arxiv.org/abs/1709.04057) gives the associative-scan route for suitable recurrences; it does not turn nonlinear transformer attention into an affine transition.
