# Frozen public-source continuation panel

`manifest.json` fixes 24 raw-completion prompts before any Qwen3-1.7B target output is observed. There are eight code, eight prose and eight structured JSON prompts. Each family has two 256-token, three 1024-token and three 2048-token prompts. Every case requests 64 continuation tokens. The manifest includes the exact prompt text, token IDs, source location and SHA-256; no source checkout or tokenizer is needed to run it.

The code prompts continue TypeScript declarations in the public [Pi Stack repository](https://github.com/the project lead-seihun/pi-stack) at `a72324174e194b9f7e7101ee0649583391b4d32d` under the MIT license. Each uses a different source file. The source-file hash and character offset are in each case. These are source-code prefixes, not instructions asking for code.

The prose prompts start at eight different article headings in Salesforce [WikiText-2 raw](https://huggingface.co/datasets/Salesforce/wikitext), `test` split at `b08601e04326c79dfdd32d625aee71d232d685c3`. The reconstructed text SHA-256 is `696cca6b65a171b0a358a4be6732cdfdf2dd6164a32e20fd70e3c13fc4dfae83`. WikiText carries CC-BY-SA-3.0 / GFDL terms. The structured prompts take eight *other* articles from that split. They encode consecutive actual article paragraphs as either JSONL records or JSON-RPC `article.index` calls with a declared parameter schema. The JSON protocols are fixture constructions, not a claim that WikiText distributes those records or that a production endpoint exists. They represent ordinary repeated-key structured output; no canonical-token grammar is imposed.

All starts and transformations are fixed in `build.py`. Prose and JSON source articles are disjoint. Their source starts differ from the earlier speculative-decoding pilot's 64-token test windows; code is from a separate public repository. The earlier train and validation windows come from other WikiText splits. No target answer or per-case acceptance outcome informed selection. The target is the official Qwen3-1.7B tokenizer at `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`; its exact tokenizer-file hash is in the manifest. Prompts use raw token IDs without a chat template, BOS or synthetic suffix. Stop-at-EOS is disabled for a fixed 64-ID comparison. Measure matched serial and verifier continuation from the same prefill; report prefill separately, and count every emitted target token and elapsed verifier/drafter work. The JSON corpus tests normal model continuation, not a constrained-output verifier contract.

Read cases with `from load import load_cases` in this directory. `load_cases(family='code', lengths={1024})` filters while retaining manifest order. To rebuild, use `/path/to/workspace/data/fish-s2-pro/venv/bin/python build.py` from any directory; `--check` checks the committed bytes. Rebuilding requires the pinned public Pi Stack Git object, the pinned WikiText text and the pinned local tokenizer. The committed manifest remains sufficient when any of those source caches are absent.
