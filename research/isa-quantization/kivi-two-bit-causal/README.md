# KIVI 2-bit: full original Qwen layer, paid causal image

**Result.** The single frozen official-supported **KIVI K2/V2 G32/R32** configuration on Qwen3-0.6B layer0 gives inspected-held complete **16-query-head/8-KV-head post-O relative squared error 0.003124373**, mean head attention KL **0.0761010**, at **304,768 B peak** (249,856 B final) for the whole eight-head cache. It is smaller than both already-frozen TurboQuant K3/V2 images, **385,040 B** with literal shared program matrices, and yields much lower local output error than their original **1.359112** and coupled-gamma **0.437581**. This is a low-bit source-rate control, **not** an equal-rate comparison or evidence about full-model generation, native time or universal method ranking. The original KIVI4 full-layer arm has held **0.000063002** at **419,200 B peak**; quality drops at two bits. No configuration, retention or quantizer selection followed the observed results. The [exact rate and sharing ledger](RATE.md) limits this single-sequence statement: at two256-token sequences the sketch shares its program once and becomes smaller in represented peak; no larger-context quality is extrapolated.

## Pinned method and causal state

KIVI: Liu et al., [*A Tuning-Free Asymmetric 2bit Quantization for KV Cache*, ICML 2024](https://proceedings.mlr.press/v235/liu24bz.html), [official source `jy-yuan/KIVI@876b4d2`](https://github.com/jy-yuan/KIVI/tree/876b4d2d08e3b1d5f70d0969c299d8c7c42ddfb6); [upstream example](https://github.com/jy-yuan/KIVI/blob/876b4d2d08e3b1d5f70d0969c299d8c7c42ddfb6/example.py) specifies 2 bits/group32/recent32. Keys use per-channel unsigned 2-bit min/max across **32 arrived tokens**, values per-token 2-bit min/max across **four 32-coordinate groups**. The encoder computes `(max−min)/3`, nearest-even code assignment to 0…3, then stores **FP16 origin and step**, while recent vectors are BF16. After the current query, a complete recent K32 slab flushes; the oldest V flushes only when V recent reaches33. No future K, model fit or new source capture is used. This is the same Qwen CPU adaptation and online chronology as [the frozen KIVI4 source reader](../kivi-causal-cache/README.md), now using the paper's 2-bit quantization rather than its 4-bit setting: post-Knorm **post-RoPE** K is BF16 rounded for insertion, while the unchanged teacher uses original FP32 post-RoPE computation after BF16 internal RMSNorm; V is projected BF16. It is not a byte-identical reproduction of upstream Llama GPU code.

The source is the original complete Qwen layer0 [full-layer observer](../skvq-global-gqa/README.md): checkpoint revision `c1899de289a04d12100db370d81485cdf75e47ca`, checkpoint SHA256 `f47f71177f32bcd101b7573ec9171e6a57f4f4d31148d38e382306f42996874b`, fixture `/path/to/workspace/data/kelana-subbit/fixtures/qwen3-0.6b-wikitext/layer00-self_attn_q_proj.npz` SHA256 `389e5f8c17ac151070b12094849f450130ab9c1684f51b402d59fd4e7ac2008f`. All 16 Q heads share the appropriate eight 128D K/V heads in GQA pairs; the original Q/K RMSNorm and gamma, RoPE, BF16 boundaries, causal softmax, V and complete 1024×2048 O are unchanged. Static common Q/K/V/O/gamma are **12,583,424 B** in every cache arm. Teacher-forced 8 train +4 inspected-held windows of 256 positions are the complete accepted panel, not an autoregressive/full-model score.

The peak was established **before scoring**. Each 32×128 K chunk is **1,024 B 2-bit codes +512 B FP16 fields=1,536 B**. Each 128D V token is **32 B 2-bit codes +16 B FP16 fields=48 B**. Recent BF16 K/V vectors cost256 B each. At t256 **before** its query's flush, each KV head has 7 quantized K chunks (224 tokens), 32 recent K, 223 quantized V, 33 recent V:

`7×1536 + 32×256 + 223×48 + 33×256 = 38,096 B/head; eight = 304,768 B peak`.

After the query's K and V flush: `8×1536 + 224×48 + 32×256 = 31,232 B/head; eight = 249,856 B resident`. Each 256-token window has **64 K chunk flushes** and **1,792 V token flushes** over eight KV heads. The 189,888-B chronological logs are audit evidence, **not** a second simultaneously retained cache; each individual head's packed final image is 31,232 B. There is no additional fitted codebook, static descriptor or generic magnitude table. Shared source weights and common position counters (2 B if paid on the same basis) are outside the displayed cache figures for all compared readers. At length256 the KIVI2 cache state is **80,272 B less** than TurboQuant cache+program and **114,432 B less** than KIVI4's cache; these have distinct representations and rates.

[`build.py`](build.py) emits actual paid final images and timestamped `K`/`V` flush events **only after** the current causal query; its manifest carries every before/after serialized prefix's SHA256, size, counts and field ledger. [`replay.py`](replay.py) imports **none** of the builder's quantize, packing or decoding functions. It checks each prefix byte length/hash, reads the actual log **at its event time**, independently decodes all eight states, recomputes both GQA queries per KV head and complete causal V/O, and independently verifies every 2-bit digit and FP16 field against only source BF16 K/V available when that flush occurs. It requires event-log exhaustion and byte equality to every paid final image, tests original source group0 equality to the canonical KIVI4 donor, and checks the full teacher denominator against the original KIVI4. Prefix source producer projections are CPU-vectorized, but the builder/reader admits a token only on arrival. Source arrays and observer scratch are **not** passed off as retained cache: at prefix256 this literal CPU reader expands two FP32 8×256×128 K/V arrays (**2,097,152 B transient**) plus scores/mix/teacher; a fused packed native consumer could avoid whole-cache expansion, but **none is timed or claimed here**. Encoder cost includes 64×4096 K scalar extrema/code assignments and 1792×128 V scalar assignments/window; the literal reader unpacks all past K/V at every query, does two query reductions per shared KV head and the full O. FP16 field conversion, recent insertion/flush and score/softmax/V/O work are not free.
