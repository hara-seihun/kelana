# Fixed-slot resident KIVI2: one frozen cooperative GPU candidate and conventional control

**Completed bounded native acceptance and timing, September 25, 2026.** All four held windows pass 4,096 device pre/post phases and 16 full-output guards. At eight measured K-flush boundary steps, the stable-slot arm saves 28,728 B of explicit global allocations but has a **1.612× median matched event ratio** (slower) against the genuinely cooperative conventional control. This is a bounded latency result, not an average-token or full-256-output result. The only intended inputs are immutable recorded BF16 K/V arrivals, eight held t128/t256 Q/teacher/conventional-CPU snapshots, and the original O. No source/model rerun, query fitting, prepared quantized-event upload, ordinary KV shadow, or full-256-output claim. The CPU-only [stable-record sidecar](../kivi-stable-records/README.md) already checks all 6,144 phases against original donor logs; this directory replays the four held windows into the candidate **physical layout** and a no-shadow conventional layout, with independent original-event byte comparison at every pre/post phase. The parent reviewed the fixed source/bill/schedule, admitted each bounded stage separately, and the gate admitted timing only after all four independently audited acceptances passed.

## Placement declared before outcomes

One natural placement, no allocator/precision/tile ladder: eight 128-thread CTAs, one per KV head, each with one lane per K channel for K32 and four group-owning lanes per V head for V33. The same `quant32` device routine, exact double-to-half `step_bits.hpp`, and the same K/V CTA geometry serve both arms. A 128-thread CTA scans the stable recent or quant slots by **exact entire-record byte equality** (one lane per recent slot, one or two quant slots per lane), selects the first matching/live-or-free slot on lane zero, pays its refcount insertion/deletion, and cooperatively copies only new payloads. Both query kernels use eight 128-thread CTAs, one KV head/two Q heads per CTA, direct chronological dereferences and the original softmax/V/O reduction; one 128-thread `finish_o` CTA grid combines eight partials. There is no grouped histogram/mass shortcut favoring the candidate. Runtime-mode branches in four common mutation bodies contain both arm paths; they are **one compiled module**, not two hypothetically specialized independent bodies.

These are **layer-0 V records**. Embedding→RMSNorm has no history before that V projection, so repeated token inputs naturally repeat V here; rotary embedding affects Q/K rather than V. The upstream rotary-score study counted 1,247 unique inputs/IDs among 3,072 positions. This program nonetheless uses only exact full-record bytes, never a vocabulary or token-ID oracle. Later-layer history-dependent V need not repeat; no layer-0 saving is multiplied by model depth.

The candidate fixes `148×384 B` quant slots, `33×2048 B` recent slots, eight `18,944 B` K slabs, `224+33` u8 references, `148+33` u8 counts, two padding bytes, and five signed 32-bit state/error fields: **276,428 B** all-reserved persistent `Cache`. K32 overwrites only the flush slab after all readers have loaded it; older K chunks stay put. Recent records are a modulo-33 chronological ring of slot handles, and deletion occurs when the oldest reference leaves at V33. Quant slots are append-only during this 256-token context; admission above 148 unique values fails, not reallocates. The subsequent [source-capacity witness](../value-record-source-capacity/README.md) demonstrates a reachable rejection:149 distinct donor-token V records plus32 existing tokens exceed the148 aged slots after t181's query flush. Guaranteeing all256-token source histories in this same fixed-slot layout needs224 aged slots and29260 additional bytes, erasing the measured memory advantage (+532B versus the conventional total). This is a layout bound, not an unreported second native setting.

The independent no-shadow conventional `Control` reserves eight K slabs plus eight `224×48 B` quant-V arrays plus eight `33×256 B` BF16 recent rings and one error word: **305,156 B**. It quantizes the oldest stored recent record on device at V33 with the same placement. Original conventional *logical record bytes* are the reference, not flat physical slab contiguity.

| Simultaneously live device global allocations, one arm at a time | Candidate B | Control B |
| --- | ---: | ---: |
| Mutable persistent cache | 276,428 | 305,156 |
| V-flush 384-B complete-record staging (`Scratch`) | 384 | 384 |
| Current BF16 K/V arrival | 4,096 | 4,096 |
| Current original Q, float32 | 8,192 | 8,192 |

Difference **28,728 B** before HIP/driver rounding; per-cache mutable+stage is 276,812 vs 305,540 B. These are sequential-arm active bills, not a claim that two simultaneously allocated programs share O for free. Original model producer weights/source computations and host source logs are common upstream, not supplied to either device kernel. `compile-receipt.json` pins the exact whole-module source/binary/assembly hashes and all nine gfx1151 kernels: **50,500 B** device bodies + nine 64-B descriptors at the reviewed build; each has **zero private scratch**. The common mutation kernels use append K 468 B/0 LDS, append V 4,108 B/44 LDS, K32 8,344 B/4,608 LDS, V33 7,036 B/144 LDS. Candidate-only slot finish 1,648 B/156 LDS, early phase finish 120 B; direct candidate/control readers 14,436/13,968 B, **5,632 B LDS per CTA** for either arm; common O finish 372 B. Eight K or reader CTAs' LDS is distributed on-chip, not global bytes. Full module code/descriptor allocation is paid; per-arm utilized bodies overlap in four runtime-mode kernels, so adding hypothetical per-arm modules would double-charge shared code. ELF/loader, CPU fixture storage and runtime allocations outside explicit buffers are not included in these global buffer totals.

The host reads one immutable 1,049,088-B arrival file and O for each held trace, plus each original Q and 4,096-B CPU reference at two observed steps. Preparing a candidate starts with a host 276,428-B zeroed `Cache` staging object copied once before the causal trace; this **initialization H2D and host staging are paid preparation**, not 4-KB-only lifetime traffic. O's 4,194,304-B H2D is also preparation. At each t, only the current 4,096-B arrival is uploaded; 8,192-B Q uploads happen only at the two retained query positions. Offline audit copies complete raw states to host, then saves them losslessly with zstd; audit traffic is **excluded** from measured timing traces but is not claimed absent during acceptance.

## CPU result and device boundary

`cpu.cpp` emits the exact fixed physical candidate/control memory coordinates, including positional rings, slot handles, active counts, fields and padding. It uses the separately established CPU stable-record transition as its quantization/transition oracle; this correspondence does not prove the HIP transition. `audit_physical.py` independently reconstructs original per-head records from original causal event streams and BF16 arrivals, compares every chronological record byte on both physical arms, checks live slot count/reference multiset and uniqueness, and checks donor per-phase SHA/length. Four held windows × two arms × 512 phases = **4,096 physical frames**, each arm/window **606,272 original ordered record checks**. `prelaunch-receipt.json` records immutable arrival and all eight Q/CPU/teacher hashes checked against `../kivi-two-bit-dot-native/snapshots.json`, original O hash, source/binary identity, resource bill and the bounded CPU receipts. Its `prelaunch.py` validates everything in seconds without a GPU call. The original sidecar's 6,144 phase audit includes the eight train windows; it is not a GPU result.

When authorized, `native.hip` starts empty for each mode/window, appends the recorded arrival, snapshots the pre-query state, computes full16Q/8KV/1024-O only at t128/t256, performs the K32/V33 flush, and snapshots post state at **all** 256 steps. The independent audit checks all 1,024 per-window device frames (512/arm) against original event logs and retains exact raw snapshot SHA plus lossless `.zst`, not just final digests. At each retained Q it compares full O to retained original conventional CPU O with **maxabs≤0.005 and relative L2≤0.005**. Actual outputs are saved as 4096-B `.f32` per arm/state for teacher SSE and arm-difference comparison. A compiled kernel is not a parity receipt.

After **all four** audited device acceptances, timing creates fresh empty causal traces, never imports an already-expanded cache, never replays an unchanged query as a substitute for mutation. One bounded attempt/window/arm, control then candidate, records t128/t256 event from K/V+Q H2D through append, complete query/O and K32/V33 flush, and separates input/compute/host wall. Both positions are **K-flush boundaries**; those eight matched-step samples discriminate the placement, not average per-token throughput or a randomized benchmark. O H2D and the earlier 127/255 steps are explicit preparation outside the measured boundary. Unknown Q at other positions is not invented or emitted; no complete-256-output claim is made.

## Native result

All eight admitted stages returned zero with Bonsai active at the unchanged PID **145247** before and after every stage. Four device acceptances independently audited every pre/post image in both resident arms: **4,096 phases** and **4,850,176 original ordered record checks**, all byte-exact including live reference counts and slot lifecycle. The maximum complete-O error against retained original conventional CPU O was **7.153e−7** coordinate-wise and **8.530e−7** relative L2 across 16 output guards. At each of the eight retained Q positions the two arms emitted **byte-identical 4,096-B outputs** (maximum arm difference zero). Teacher SSE summed over these eight held complete-O states is **0.8326574748 per arm**; it is not a metric for all 256 causal positions or the full source-model benchmark.

After all four audits passed, fresh trace timing had these event medians in µs:

| Boundary step | Control | Stable slots | Median matched-state ratio |
| --- | ---: | ---: | ---: |
| t128 | 80.517 | 177.303 | 2.170× |
| t256 | 104.066 | 147.414 | 1.520× |
| All eight states | 89.933 | 147.414 | **1.612×** |

All eight individual matched event ratios exceed one, ranging from 1.185× to 2.832×. Event input transfer medians across all eight are 20.654 µs control and 19.069 µs stable; compute-span medians are 69.278 vs 127.675 µs, host-wall medians 112.171 vs 226.022 µs. Both measured positions trigger K32 and V33 flush; this is a fixed-placement flush-boundary discriminator with one fresh control-first trace per window/arm, not a repeated randomized timing claim or average-token throughput. Acceptance event spans included audit traffic and are excluded from these timing summaries. The stable cache's **28,728-B global-buffer advantage** and byte-equivalent outputs do not compensate for its slower observed boundary in this placement.

[`results.json`](results.json) and [`summarize.py`](summarize.py) own reproducible medians, each matched ratio, source and binary identity, resource categories, and all stage trace hashes. Every 297,779,200-B device snapshot stream is retained losslessly as `held-N-snapshots.bin.zst`, with uncompressed and compressed SHA in `audit-held-N.json` and each `accept-held-N-receipt.json`; `zstd -dc` reconstructs the exact raw frames without rerunning the device. Each held window retains actual outputs, teacher SSE and arm comparison in its acceptance receipt; raw acceptance/timing JSONL and one-attempt admission logs are retained. All four full acceptance receipts were checked against actual compressed frames and output bytes before any timing stage.

## Explicit review and bounded stage schedule

`bash build.sh` compiles only and writes a separate ignored `build-receipt.json` when the immutable native-run `compile-receipt.json` exists. It does not rewrite accepted identities. The parent recovered the accidentally ignored emitted assembly on integration: its exact SHA and every source/resource field match the frozen receipt; the relocated host executable's SHA differs (`rebuild-receipt.json`), so it is not labeled the measured binary. Assembly is now tracked, not discarded by workspace cleanup. A rebuilt host executable is not silently approved to reuse the original native-run authorization. For the original prelaunch workflow, `g++ -std=c++20 -O2 -w cpu.cpp -o cpu`, then `python3 prelaunch.py prepare` audits the held CPU physical traces and writes the frozen bill. Rebuilding clears timing readiness. Before any device call the parent must review the fixed source, the exact allocation/host staging bill, all immutable preflight checks and bounded schedule. Only after approval for **one specific stage** may the parent write `prelaunch-receipt.json`'s `source_hash`, a space, `accept|timing`, a space, `held-N`, and newline into the ignored `launch-approved.sha256` marker (e.g. `SOURCEHASH accept held-0`). The runner consumes this exact-stage, single-use marker before admission; every additional stage needs renewed parent authorization. Merely running `prelaunch.py` or compiling does **not** authorize a launch; absent/mismatched marker makes `run-stage.sh` exit before touching GPU admission. Code changes invalidate the source hash and marker.

With that separate authorization, execute `bash run-stage.sh accept held-0` through `held-3`, and only after **all four success/audit receipts**, `bash run-stage.sh timing held-0` through `held-3`. Each invocation checks source/input hashes, refuses an earlier attempt receipt, makes one nonblocking measurement-lock admission, verifies the same live Bonsai PID before/after, and gives `gpu-run --host-mib 1024 --gtt-mib 512` at most **45 seconds** foreground execution. No auto-retry, no alternate kernel placement. Admission denial or byte/output failure stops the experiment with the attempt log. `stage_receipt.py gate` revalidates source/binary, all four audited snapshot compressed/raw hashes and all output bytes before any timing. Acceptance trace files are stored as lossless `held-N-snapshots.bin.zst`, restorable with `zstd -dc`; `audit-N.json`, output files, stage receipts and attempt logs remain. All eight one-attempt stages completed without source/placement changes or retries. The marker for each authorized stage was consumed before admission; rerunning a finished stage is refused.
