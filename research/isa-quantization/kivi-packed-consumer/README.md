# Exact packed-coordinate consumer for the frozen KIVI Qwen cache

**Outcome: an exact semantic factorization, not an established execution win.** Keeping the paid 4-bit KIVI K/V labels as the online representation lets the complete two-Q-head causal query be computed without constructing a 256×128 decoded K or V matrix. At the length-256 preflush boundary the direct arithmetic saves **114,432 per-element dequantization FMAs** versus an honest conventional packed dequant-dot reader. But one concrete complete gfx1151 placement increases kernel instruction body by **2,928 B**, VGPR use **23→36**, LDS **5,632→22,112 B**, and preparation/barriers; it is a size/work tradeoff, not a native speedup. The original KIVI image and model stay exactly the same. No new fit/config/cache bitwidth, GPU launch, source gauge or held selection.

The [byte-query error contract](QUERY_ERROR.md) handles the distinct approximate boundary: keep the cache labels, encode the folded query in bytes, bound full-row score oscillation, then use the sharp Lean-proved positive-ratio TV inequality and the actual V/O diameter. Existing cache error and chunk-specific biases remain paid. The [value-aware support certificate](RATIO_SUPPORT.md) then solves the scalar ratio-box observer exactly by an endpoint threshold, with Lean proof, an exact sorted rational implementation and explicit shared-head relaxation limits.

## Exact consumer algebra and boundary

The frozen owner [`../kivi-causal-cache/`](../kivi-causal-cache/) contains the actual source-observed eight train/four held 256-token windows, each online event log, all 256 before/after paid-state hashes, final postflush image and full original model/causal observer. It uses the primary KIVI-supported 4-bit/G32/R32 variant with Qwen BF16 recent vectors, FP16 min/step, grouped K per channel across 32 **causally prior** tokens and V per token/32-coordinate group. Our [`map.py`](map.py) reads those exact logs only when flushes occur, appends the current original-source insertion, verifies each **preflush** byte-state hash, and compares directly with the independent owner's [`replay.decode`](../kivi-causal-cache/replay.py) ordinary packed dequant reader at the same prefix. The complete common source Q heads, K/V producer, Q/K norm, RoPE, original BF16 O and teacher contracts are unchanged. A query receives its two already-normalized/rotated dynamic 128-vectors; *that upstream preparation* and the insertion/quantize/flush are common work outside these query kernels, not a claim of free inputs. Quantizers and persistent metadata are paid by KIVI; nothing is prepared offline for a particular query.

For K chunk `c`, channel `d`, head `h`, code `i_{t,d}`, source FP16 origin `o_{c,d}`, step `s_{c,d}` and live query `q_{h,d}`, compute once per head/chunk `A_{h,c,d}=q_{h,d}s_{c,d}` and **`B_{h,c}=Σ_d q_{h,d}o_{c,d}`**. Each quantized token score is `B_{h,c}+Σ_d A_{h,c,d} i_{t,d}`, with original `1/√128` afterwards. Crucially `B` varies by chunk; it cannot be dropped as a common softmax row shift. Recent BF16 keys use their original dot. Normalize **both full causal score rows** by stable max/exp/sum; no score or probability is omitted.

For quantized V token `t` and coordinate group `g`, let its FP16 origin/step be `a_{t,g},b_{t,g}` and score-derived probability for head `h` be `p_{h,t}`. Prepare `C_{h,g}=Σ_{t<quantV}p_{h,t}a_{t,g}` and `D_{h,t,g}=p_{h,t}b_{t,g}`. The mixed V output coordinate `d∈g` is `C_{h,g}+Σ_{t<quantV} D_{h,t,g} j_{t,d}` **plus** the recent-BF16 V weighted sum. Finally each original BF16 O row consumes all 128 mixed values for both heads, returning the complete 1,024-vector GQA contribution. The same cache is read by both queries; their `q`/probabilities/factors differ. No expanded K/V matrix is an input or retained runtime state. [`Kelana/KIVIPackedConsumer.lean`](../../../Kelana/KIVIPackedConsumer.lean) proves the rational score distributivity, value distributivity and complete arbitrary-readout equality for **any deterministic shared normalizer**, arbitrary per-token/chunk fields and all finite widths. The theorem treats different chunk origins separately; BF16/FP16/FMA rounding remains the numerical boundary. It needs no lookup table, KIVI source refit, equality only on the captured panel, or imaginary free `B` shift.

The CPU `map.py` compares this direct formula with the owner’s **on-the-fly conventional packed dequant-dot** for *every actual prefix* of all twelve original windows and feeds both complete probability/V/O outputs against the original teacher. It does not use the final image retroactively for early queries. [`train-*.json`](train-0.json), [`held-*.json`](held-0.json) and [`results.json`](results.json) pin every window and the original KIVI image SHA. Across all twelve, maximum absolute direct/conventional discrepancies are **4.50e−6 score**, **5.76e−7 mixed V**, **3.54e−7 final O**; the canonical uncompressed source score check remains **1.34e−5**. Both constructions have the same real-arithmetic map and observed behavioral quality (the few final digits differ through FP32 order):

The owner's named KIVI cache is the established strong quality baseline: 52,400 B peak dynamic state, 46,592 B after final flush, **zero extra generic table**. Its two Q heads, K/V, O and Q/K gamma are **1,573,376 B unchanged common static weights**. Both kernels read the identical current preflush state with K quant chunk bytes, V quant token bytes and recent BF16 vectors. Common 2-B position metadata is outside the displayed state. No full decoded matrix should be called a 52,400-B inference cache.

## gfx1151 complete compile-only control and resource/work ledger

[`consumer.hip`](consumer.hip) has **two complete single-query kernels** for these two 128D query heads, shared K/V, complete preflush cache, all visible scores, stable parallel softmax, quantized+recent V mixing and original BF16 1,024×256 O. The conventional arm unpacks each nibble and its actual FP16 origin/step **inside** the dot/reduction; it does *not* pass an expanded K/V matrix or drop per-chunk fields. The direct arm cooperatively prepares K chunk factors/biases and V token/group factors/biases in LDS, then reduces raw codes. Both use the same q/softmax/recent/O program and output one complete 1,024-vector. Cached source rotary/norm Q generation, original K/V insertion, K/V min/max/packing on flush, and full O weight bytes are equal common work, separately accounted above. This comparison isolates the changed **query reader**, not complete generation latency. No kernel was launched.

`./build.sh` compiles both with `hipcc -O3 --offload-arch=gfx1151 -save-temps -c`; [`assembly-gfx1151.s`](assembly-gfx1151.s), [`compile-receipt.txt`](compile-receipt.txt), [`opcode-receipt.json`](opcode-receipt.json) and [`opcodes.py`](opcodes.py) keep emitted bodies/resources and static opcode evidence. Kernel descriptors are 64 B each; common HIP runtime/host stubs, original O static bytes and packed KIVI state are excluded from the following **difference**:

| Complete query from packed state | Kernel body | VGPR/SGPR | LDS | Private scratch |
|---|---:|---:|---:|---:|
| on-the-fly conventional dequant-dot | **13,612 B** | 23 / 46 | **5,632 B** | 0 |
| direct chunk-score / token-value packed coordinates | **16,540 B** | 36 / 46 | **22,112 B** | 0 |

The direct kernel’s resident query workspace comprises fixed-capacity `K factors 8×2×128 floats=8,192 B`, `V factors 2×256×4 floats=8,192 B`, K/V biases 96 B, common scores/probabilities 4,096 B, mixed V 1,024 B and reduction scratch 512 B, totaling 22,112 B. Conventional needs only common 5,632 B. At the actual length-256 **preflush** state there are **seven quantized 32-token K chunks, 223 quantized V tokens, 32 recent K and 33 recent V**. Across both Q heads the direct map replaces one of two FMAs for each of `2×224×128=57,344` quantized K contributions and `2×223×128=57,088` quantized V contributions: **114,432 fewer per-element dequant FMAs** in this source form. It adds K `7×2×128=1,792` live `q×step` factors, equally many `q×origin` terms plus chunk-bias reductions; V `223×4×2=1,784` live `p×step` factors, origin products and group-bias reductions. Its emitted V preparation assigns eight producer lanes a serial pass over the 223 quantized tokens; that is paid dependence/latency, not a free 1,784-way parallel oracle. It also adds synchronization/shared-factor traffic. Source logical FP16 field reads decrease dramatically versus per-code conventional reads, but the conventional hot fields may cache and the direct arm increases LDS traffic. Both still load both heads’ nibble codes and apply `2×32×128=8,192` recent-key score terms, `2×33×128=8,448` recent-value terms, plus **262,144 common O-row multiply/add terms** and 512 softmax exponentials. Static emitted instruction lines are 2,400 versus 3,008, including 37 versus 42 static barrier sites; those site counts are **not** dynamic instruction/barrier totals.

At peak state plus own device body, the conventional data+query-code is **66,012 B**, direct **68,940 B**; both also read unchanged common O and other model weights. State is identical; only compiled code and LDS change. This placement therefore buys a large per-element arithmetic reduction but **loses static code size and LDS/VGPR resources**, with extra preparation concentrated in eight lanes. It does not establish better elapsed execution or a new quality/size frontier. An alternative tiled factor placement could change the resource/work balance, but none was timed or claimed here. QServe/fused quantized attention and other native KIVI consumers are not superseded; this is a priced exact-map local gfx1151 screen for the owned images.
