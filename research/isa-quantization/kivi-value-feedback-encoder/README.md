# Conventional / error-feedback KIVI2 value flush: CPU correspondence and gfx1151 compile

This is **one** untuned producer placement for the fixed chronological experiment in [`kivi-value-error-feedback`](../kivi-value-error-feedback/) at donor commit `da88542`. The donor's accepted eight complete original-O observations are reused: original K2/V2 relative SSE **.003068937**, feedback **.002139543**, delay2 **.002973482**. Nothing here recalculates those outputs or measures execution time. No GPU kernel was launched by this study; device byte parity and latency remain unknown. Parent prelaunch review repaired null-pointer offset formation in the conventional arm: its unused residual pointer now stays null instead of forming an out-of-object address. No arithmetic or placement changed; recompilation retains exactly the same body/resource counts, with new source/object/assembly hashes in the receipt. CPU arithmetic and its successful parity result were not rerun.

## Exact producer and correspondence

[`encoder.cpp`](encoder.cpp) independently implements a complete source-V flush for both conventional and feedback arms. Four group32 source-based FP32 minima and binary64 `(max−min)/3` supply unchanged actual-FP16 origin/step bytes; the FP32 target is source+resident FP32 residual only in the feedback arm. Both quantizers use source step, FP32 subtraction/division, nearest-even/clamp to 2-bit digits, and the same 48-byte packed record (32 code bytes, 16 field bytes). The feedback arm decodes **stored FP16 fields** with separate rounded FP32 multiply then addition, subtracts from target in FP32 and commits 128 FP32 residuals; the conventional arm leaves them zero. Host build disables FMA contraction. There is no source-based retuning, changed K, relocated event, altered consumer format or decoder residual.

[`parity.py`](parity.py) reads the SHA-pinned original BF16 arrival streams and original causal V records plus donor feedback events/manifests. For each of four held streams, eight KV heads and 224 original t33…256 V flushes, it compares the *entire* conventional packed record to the original, feedback's 16 field bytes to both records and all 32 feedback code bytes to the donor, and both pre/post **actual 512-byte residual SHA at every one of 256 prefixes/head** to the donor manifests. It checks final residual SHA. [`parity-receipt.json`](parity-receipt.json) pins source/donor manifest hashes and host implementation: **7,168** complete V events, **8,192** prefixes, **16,384** residual-state checks, **114,688** feedback field bytes and **917,504** decoded digit comparisons; zero mismatch. This is independent C++ arithmetic against the Python/NumPy donor, not a GPU result.

[`native.hip`](native.hip) lowers the *same* conventional/feedback arms into a single runtime-arm V33 flush body. It uses the established [`kivi-stable-resident`](../kivi-stable-resident/state.hip) control arm's exact recent ring `[8][33][256]` and quant-record `[8][224][48]` coordinates, with eight 128-thread CTAs (one per KV head, four group-owning lanes at 0/32/64/96) and a separate 128-float/head residual pointer. At t33…256 the source is recent slot `(t−33)%33`, record slot `t−33`. Original K flush, append, query reader and O finish are common and not rebuilt or charged as new bodies here. This is a producer replacing that arm's V33 body, not a separate cache or per-query decoder. Source is retained in 32 register floats per group lane as in the owning quantizer, and the FP32 decode's multiply and add stay separate with `-ffp-contract=off` (compiler-internal division refinement may use FMA). The compiler allocates 50 VGPR, 14 SGPR per thread, four wave32/CTA, zero fixed LDS and zero private scratch; [`compile-receipt.json`](compile-receipt.json) pins the gfx1151 object and tracked [`assembly-gfx1151.s`](assembly-gfx1151.s). The body is **2,432 B** plus **64 B descriptor**. These resource counts are for the one runtime-arm body, not for a full compiled resident-cache module, code residency, driver allocations, occupancy or speed.

## Operation and state bill

Per flushed 128-coordinate V: common to both arms are the 256-byte BF16 source, four 32-value FP32 min/max scans, four source `(max−min)/3` steps, four origin/step FP16 pairs, 128 FP32 subtract/divide/nearest-even/clamp code decisions, packing 128 digits into 32 bytes, and writing 16 field bytes. The conventional arm's source and output are not free; both arms write the **same 48 B/flush** and maintain the existing recent/quant cache. Feedback additionally reads 128 FP32 residuals (**512 B**), adds 128 FP32 targets, decodes 128 actual-field digits (**128 FP32 multiplies + 128 separately rounded FP32 additions**), subtracts 128 FP32 errors and writes 128 FP32 residuals (**512 B**). Thus its extra sequential residual traffic is **1,024 B/flush**, **1,835,008 B/held stream** across 8×224 flushes, with no extra per-query work. Its live persistent state is **8×128×4 = 4,096 B per sequence**, initialized to zero and updated only on V flush. Under the donor's full cache ledger, conventional peak/final **304,768/249,856 B** becomes feedback **308,864/253,952 B**. The source ring, packed output, K, Q, O and readout are common. The four active group-owning lanes carry source and decoded temporaries in VGPR; no global target or decoded-vector scratch is allocated. A register allocation of 50 VGPR/thread applies to all 128 launched lanes even though only four own groups, so this placement does not assert good utilization. Byte traffic is a logical residual-load/store count, not a measured DRAM count or a claim about cache hits.

## Reproduce, bounded and CPU/compile only

From this directory, with donor commit in the local Git object store:

```sh
mkdir -p /tmp/kivi-feedback-donor
git archive da88542 research/isa-quantization/kivi-value-error-feedback | tar -xf - -C /tmp/kivi-feedback-donor
g++ -std=c++20 -O2 -ffp-contract=off -frounding-math -shared -fPIC encoder.cpp -o encoder.so
python3 parity.py /tmp/kivi-feedback-donor/research/isa-quantization/kivi-value-error-feedback
hipcc --offload-arch=gfx1151 -O3 -ffp-contract=off -save-temps -c native.hip -o native.o
python3 compile_receipt.py
```

Generated `.so`, `.o`, `.bc`, `.hipi`, `.out` and compiler temporary files are not evidence or resident state. Successful `compile_receipt.py` removes the `native-hip-*`, `native-host-*`, bundle and object intermediates after preserving assembly and hashes, so completed builds do not prevent managed-checkout release. Source, donor hashes, arithmetic receipts and one device assembly are retained. A later native run would require separate review/admission and comparison of *actual device bytes and residual state*, not inference from the successful CPU correspondence or compiler resource descriptor.
