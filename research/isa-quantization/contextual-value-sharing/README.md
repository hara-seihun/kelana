# Contextual value-sharing discriminator: layer 1

**Result on one fixed original-model boundary:** none of the 12 complete 256-token windows has even one repeated full-eight-head BF16 V record or G32 KIVI2 V record under the specified CPU projection contract. This is a bounded negative for exact interning at layer 1, not a statement about generic deeper layers or approximate representations. Token IDs repeat often, but their original-model contextual residuals and the projected full records do not. The layer-0 [exact V dictionary](../kivi-value-intern/README.md) relies on equal embedding-derived records; those counts cannot simply be transferred across the first attention/MLP block.

In `teacher` mode it restores original layer-0 Q/K/V/O and both norms and leaves the original MLP intact. `*_teacher_post` is thus the actual BF16 post-layer-0 residual, which is the input to layer-1 `input_layernorm`; it is neither the captured pre-MLP norm input nor a damaged/quantized layer-0 output. The original layer-1 forward and its V projection were **not** captured. This study projects that genuine original boundary with the original checkpoint's layer-1 gamma and V weight on CPU; the projected V is a **specified CPU discriminator**, not a claim to reproduce an unrecorded native GPU layer-1 V tensor bit-for-bit.

No cross-window equality or cache carry-over is used. The 4 validation windows were previously inspected elsewhere, not fresh held-out data. ## Exact bytes being counted

[`screen.py`](screen.py) reads only the layer-0 teacher post-residual and original layer-1 gamma/V matrix. CPU contract: decode retained source BF16 residual; calculate squared mean and `rsqrt(mean+1e-6)` in FP32; round normalized vector to BF16 nearest-even; multiply BF16-decoded vector by original gamma in FP32 and round BF16; FP32 matrix multiplication by original BF16-decoded V weights, then round output BF16 nearest-even. This is one declared rounding rule, not a rounding sweep or a replay of the original GPU BF16 GEMM. No layer-1 attention, O, quality or speed is measured. Raw records are all 1,024 coordinates of the captured original BF16 residual (2,048 B); normalized-input and V records are 1,024 BF16 values each across **all eight** 128-channel KV heads (2,048 B). All records are little-endian, position-major. Quant records are the [KIVI2 V rule](../kivi-two-bit-causal/build.py): for each head, four contiguous G32 groups, source BF16-derived FP32 min/max, 2-bit nearest-even/clamped digits, FP16 low/step; concatenate eight 48-B head records into one **384-B** position record. No per-head interning. Byte equality on full records determines uniqueness; Python byte sets use their built-in hash table only as an accelerator for exact equality, not approximate/hash-only matches.

For query `t` (1-based), **before** its flush, aged quant positions are `[0,max(0,t-33))` and recent BF16 V positions are the remaining up to 33; **after** the query, aged positions are `[0,max(0,t-32))` and recent has up to 32. Aged quant records are calculated from their source V at their later flush; neither quant/recent domain nor heads are conflated. These are the same causal phase/age rules as original KIVI2, without actually running an attention reader. Each per-window receipt reports both phase maxima, first age exceeding 148, and t181/t256 counts; no source state arrays are copied into this directory.

Each individual window has 256 unique captured residuals, 256 unique normalized inputs, 256 unique projected BF16 V and 256 unique packed V records. In every window the before-query t181 aged/recent counts are **148/33 unique** and the after-query aged/recent counts are **149/32 unique**. The fixed layer-0-derived 148 aged slots first fail at **after-query t181** (before-query t182). At t256 the before-query counts are 223/33 and after-query 224/32, all unique. A dynamically sized exact dictionary stores all these values plus references without any shared V payload: final V payload is still `224×384 + 32×2048 = 151,552 B`, plus 256 one-byte references and any header/metadata; for the layer-0 five-byte serialization convention it is 151,813 B, **261 B larger** than plain final V. K bytes are unchanged. Resizing a fixed 148 aged-slot store to 224 costs 76 more 384-B slots (29,184 B), before headers/references/allocator and write/move work. This says nothing favorable about peak RAM or reader latency. Computing a CPU projected V, four min/max reductions/head, digit packing, dictionary lookup and indirection are paid operations; source residuals, checkpoint weights and offline receipts are not claimed as resident cache savings.

```sh
cd /path/to/workspace/projects/kelana
for w in 0 1 2 3 4 5 6 7; do OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 /path/to/workspace/data/fish-s2-pro/venv/bin/python research/isa-quantization/contextual-value-sharing/screen.py train "$w"; done

```

Each window is an independent sub-minute CPU computation. `python provenance.py` verifies recovered source custody and `python aggregate.py` regenerates `summary.json` from existing receipts only; these avoid repeating the successful projection. The 12 small JSON receipts contain source SHA-256s, all full-record uniqueness controls, token-ID pair controls and causal phase counts. The capture and fixture remain with their existing data owners; no GPU, forward recapture, fitting, new service or stored giant tensor is involved.
