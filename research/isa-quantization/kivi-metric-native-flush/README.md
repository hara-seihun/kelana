# Complete gfx1151 compile-only K-flush path for the frozen KIVI metric encoder

**Outcome.** A single declared 128-thread / one-32×128-key-slab implementation compiles for `gfx1151`. Its CPU-callable arithmetic emits **exactly the frozen 2,560-byte K image for all 96 original and all 96 metric donor flushes** (12 windows × 8 chunks) with **zero differing code or FP16 field bytes**. Compiled device body grows **7,684 → 9,164 B** (+1,480), VGPR **36 → 62**, SGPR **9 → 12**, while LDS remains **4,608 B**, scratch zero, and one static barrier site each. The metric's immutable 2,304-B model-group FP16 U/D image makes device **body + 64-B descriptor + metric data 7,748 → 11,532 B** (+3,784) before common runtime/host stubs and all source/model/cache bytes. There is heavy serial FP64 work and no device launch; **host byte parity and device compilation are distinct facts, not proof of native bitwise parity or a speedup**. No new fit, bitwidth/config change, held quality sweep, GPU timing or deployment.

## Fixed arithmetic and causal boundary

The identical immutable donor source is [`../kivi-response-metric/`](../kivi-response-metric/): the 2,304-B model-specific FP16 `U[128,8],D[128]` metric image SHA256 `2d4837028c2e04fb61b3f554eb409b4ff450374634b54febabe451cd846cadc9`, original KIVI 4-bit/G32/R32 FP16 affine fields and BF16 recent keys, original 128-coordinate forward sweep, and unchanged packed query/V/O consumer. Both original and metric target events are read only after the original causal 32-key group becomes complete. Source BF16 keys already passed unchanged original Qwen projection, K norm and RoPE, as specified in [KIVI's source owner](../kivi-causal-cache/); building those source vectors and moving/retaining the slab are common upstream work, **not claimed free**. The full two-head query reader, stable softmax, V and O remain unchanged from the frozen donor; the encoder alone is compiled here. Original and metric preserve the same 52,400-B per-sequence peak cache state and 46,592-B postflush state. The metric's 2,304 B is **one immutable model-group asset**, shareable among simultaneous sequences; transient encoder workspace and repeated work are separately charged below.

The one chosen source placement ([`encoder.h`](encoder.h), [`encoder.hip`](encoder.hip)) is a **128-thread block for one complete 32×128 BF16 key chunk**. Each lane `d<128` first computes its 32-token min/max **in FP32**, derives `(max−min)/15` in FP32, selects original 0…15 nearest-even codes from those *unrounded* fields, and writes actual FP16 origin/step to a 256-entry LDS half array. The 4,096 initial codes live in LDS. After one barrier, lanes `t<32` each own one token. Conventional control immediately packs its 128 initial nibbles into 64 bytes; metric arm first loads paid FP16 U/D/fields, computes eight FP64 accumulated `s=Uᵀe`, then performs exactly **one serial d0→127** sweep. Its represented residual and quadratic gradient use FP64 after conversion of the paid FP16 fields/image, `j=clip(rint_even(code−gradient/(step·curvature)),0,15)`, skip zero step, and update eight `s` registers after each changed code. Each token owner writes its packed 64 bytes; all 128 lanes write the common 512-B FP16 field region of the final **2,560-B** event. Both kernels have the same pointer contract: completed source BF16[32×128], immutable metric FP16[1152] (unused by baseline), output packed uint8[2560]. There is no expanded key matrix, dictionary, extra prepared magnitude table or uncounted per-group persistent state. The shared code/fields are **4,096+512=4,608 B LDS per block**, plus emitted 36/62 VGPR per thread. No device-private scratch is emitted.

The shared [`encode_cpu.cpp`](encode_cpu.cpp) calls the exact declared C++ finite helpers for all eight slabs of one source window, without importing the Python donor encoder. [`parity.py`](parity.py) writes the immutable BF16 key slabs obtained from the original source fixture, invokes that CPU executable, and compares **every code and field byte** with the two independent stored K-event logs at their causal flush times, including all eight training/four inspected-held windows. `train-*-parity.json`, `held-*-parity.json`, and [`results.json`](results.json) pin all source SHA, metric SHA, full donor concatenated-K SHA, new encoded SHA and mismatches. Both arms match **12/12 windows, 8/8 flushes each, 245,760/245,760 compared bytes**, including all K fields. CPU compiler here is Clang21; HIP device compiler ROCm7.2.3 Clang22. FP32 division, FP16 casts, FMA contraction and FP64 reduction order may differ when the emitted device code actually runs; this is **compile-only**, so native numerical parity and latency remain unmeasured. If near-tie codes change on a future native launch, the donor's exact quality cannot silently be attributed to it.

## Emitted resources and complete work ledger

[`build.sh`](build.sh) compiles CPU and `hipcc -O3 --offload-arch=gfx1151 -save-temps -c encoder.hip`; [`assembly-gfx1151.s`](assembly-gfx1151.s), [`compile-receipt.txt`](compile-receipt.txt) and `results.json` retain the emitted body labels, object symbol sizes/resources and selected static opcodes. Static opcode sites are **not** dynamic instruction counts. The source code and object have no external model-specific generated table or special query-preparation copy. Runtime/HIP host stubs, original source weights, K/V/O reader, original BF16 input and packed result are common and excluded from the following **difference**:

| Complete single K-flush kernel | Body | Descriptor | LDS | VGPR / SGPR | Scratch | Static barrier sites | Static FP64 opcode sites |
|---|---:|---:|---:|---:|---:|---:|---:|
| Original on-the-fly KIVI 4-bit | **7,684 B** | 64 B | 4,608 B | 36 / 9 | 0 | 1 | 0 |
| Frozen metric code assignment | **9,164 B** | 64 B | 4,608 B | 62 / 12 | 0 | 1 | 105 |

Each flush consumes the existing **8,192-B BF16 recent-K slab** and produces **2,560 B** of fields plus packed K. Common phase1 loops over 32 keys ×128 channels to find min/max and select **4,096 initial codes**, including 4,096 FP32 normalized divisions/rounds, and packs 2,048 output code bytes plus 512 fields. The metric adds, **per flushed chunk**, 32 tokens ×128 dimensions ×8 terms to form initial `s` (**32,768 FP64 product/accumulate terms**); then for each of 32 tokens a **serial 128-coordinate chain** with 8-term `U·s`, 8-term `U·U`, one FP64 quotient/rint/clamp and an 8-term `s` update per coordinate (**98,304** additional rank-8 product/update terms, **4,096 FP64 divisions**). Thus one flush adds ~131,072 rank terms plus 4,096 divisions under this literal placement, and eight flushes per 256-token window repeat it eight times. Curvature `U_d·U_d` is recomputed **per token** here, not secretly hoisted into a 128-value prepared table; the FP16 U/D global image is logically read by each active token lane and may cache physically. The **critical path** for each of 32 token lanes includes 128 initial rank-dot contributions, followed by 128 serial coordinate decisions each depending on the preceding `s` update. Serial work, FP64 throughput and register occupancy could dominate. The original source/reader, Q/K norm/RoPE, V packing, both full score/softmax/V reductions, and 1,024×256 O multiply/add readout are common unchanged obligations. Across N concurrent independent sequences, the metric image remains **2,304 B once per model group** while each sequence has its own 52,400-B peak KIVI cache and repeats its K-flush work; the device body's code is likewise shared. Any runtime copies of U/D or allocated work buffers are additional implementation costs, not implied by this compile-only ledger. The CPU oracle keeps input/output arrays and FP64 work separate from serialized inference-state accounting.
