# Causal KIVI key-code assignment in a paid query-response metric

**Result: nearby-size quality/work tradeoff, not a strict size or speed domination.** Retaining every original KIVI 4-bit K/V affine grid, field, packing, BF16 recent vector, V byte, and causal K/V flush boundary, one train-defined FP16 diagonal-plus-rank8 metric changes only K nibble **assignment** at the existing 32-key flush. On the original Qwen3-0.6B layer-0 two-query-head/shared-K/V 256-token source observer, inspected-held complete GQA-pair post-O relative squared error is **0.000135159** versus strong unchanged KIVI **0.000155355** (13.0% less error), with **54,704 B** peak cache+model-specific metric versus KIVI **52,400 B** peak cache (4.40% more). The train gain is 3.72%. A [fixed longer-recent-V control](../kivi-v45-control/README.md) now scores **.000136901** at **54,688B**, just16B less: the metric arm's held pair advantage over that stronger rate control is only **1.27%**, while it adds much more encoding work. Both held head attention KL values improve; original source Q/K/V/O/gamma, BF16 rounding contract, RoPE and full causal softmax/O remain unchanged. There is extra offline metric preparation and real online flush work. **No GPU execution, elapsed latency, full-model inference or unconditional frontier win is claimed.** The additional static metric belongs to this particular group, not a free generic decoder pool asset.

## Rule fixed before candidate quality

The coordinator received the rule and train0 acceptance gate before any candidate score. Eight original **training** windows supply original two-head FP32 normalized/RoPE queries `q_{h,t}`. Set `C=mean(q qᵀ /128)` over 4,096 train queries. Compute its leading eight nonnegative eigenpairs, `U` as eigenvectors times sqrt eigenvalues, and `D_d=max(C_dd−||U_d||², 10⁻⁶ trace(C)/128)`; orient each eigenvector by making its maximum-magnitude component positive. Store **FP16 row-major U[128,8] and FP16 D[128]**, exactly **2,304 model-specific bytes**. The reader/encoder uses only these stored FP16 values converted to arithmetic FP64, not unreconciled FP64 preparation coefficients. [`metric.py`](metric.py), [`metric-manifest.json`](metric-manifest.json), eight `train-*-gram.npy` covariance contributions and [`metric-fp16.bin`](metric-fp16.bin) fix this provenance/image; metric SHA256 `2d4837028c2e04fb61b3f554eb409b4ff450374634b54febabe451cd846cadc9`. No held queries, V/O-dependent objective, future keys, candidate score, rank/diagonal/seed sweep or metric refit enter preparation.

At each original K flush **after that query**, calculate the original per-channel KIVI min/step FP16 fields and original 0…15 nearest-even codes from only its 32 now-available BF16 rotary keys. For each token start represented residual `e_d = float(FP16 origin_d)+code_d·float(FP16 step_d)−source_key_d` and `s=Uᵀ e`; sweep coordinates `d=0…127` **once**. With `G_d=D_d e_d+U_d·s` and `A_d=D_d+||U_d||²>0`, a code change represented by `δ=(j−code_d)·step_d` has exact stored-metric change `2δG_d+δ²A_d`. Choose nearest-even `j=clip(round(code_d−G_d/(step_d A_d)),0,15)`, skip zero step, and increment `e_d`/`s`; no iterative refinement or held branch. Keep the original FP16 fields and nibble placement, original recent BF16 K and **literal original V packed flush bytes**. The metric is a surrogate for train query score error, not causal teacher/attention optimization; it does not guarantee complete O improves in each window. The independent [`replay.py`](replay.py) verifies each of the 16 possible code choices via explicit objective differences rather than trusting the rounded formula, checks stored fields and original codes against available source keys, and recomputes the final represented objective. The [general code-update study](../low-rank-code-update/README.md) supplies the finite rational energy identity and nonincreasing finite-grid sweep in [`Kelana/LowRankCodeUpdate.lean`](../../../Kelana/LowRankCodeUpdate.lean). It does not prove floating rounding or that this score surrogate bounds complete output loss; the [joint K/V study](../joint-cache-error/README.md) retains that observer's cross terms.

Train0 gate was predeclared **candidate pair post-O error ≤0.95× KIVI**, both head KL ≤1.05× KIVI. It passed at `.000135287 / .000145641` pair relative squared, KL `.00280849/.00099218` versus `.00370973/.00118796`; only then were all remaining train and four held windows evaluated. No acceptance threshold or code rule changed after opening held. The original KIVI owner is [`../kivi-causal-cache/`](../kivi-causal-cache/), and the frozen packed query consumer is [`../kivi-packed-consumer/`](../kivi-packed-consumer/). This is **not** KIVI's named standard code-assignment rule; call it a query-response-aware KIVI-grid variant, not a published KIVI result or a better-than-all-cache state of the art.

## Complete causal image and original consumer

[`program.py`](program.py) consumes only an original K event when its slab is available, replaces its 2,048 nibble bytes using the paid metric and **copies its 512 FP16 field bytes**. It copies V's 80-byte original event at precisely the original delayed V flush; early queries still have recent V and original recent K. It records eight K and 224 V chronological event bytes, 256 actual preflush state hashes, final postflush image and per-chunk original/new SHA, changed-code count, and stored-image objective before/after for every window. The event logs are **evidence of chronological insert/flush, not duplicate live cache state**. [`replay.py`](replay.py) independently consumes these events only after their causal query, checks all 256 preflush hashes, all 8 K groups' fields/codes and exhaustive 16-level coordinate decisions, the 224 original V events **byte-identically**, and final image. It computes all original two-head full causal scores, stable softmax, original V mixture and original BF16 1,024-column O, comparing actual original teacher outputs. Every one of eight train/four inspected-held windows passes. Per-window binaries/manifest/replay are `PANEL-WINDOW-{final.bin,flush.bin,prefixes.json,replay.json}` and `PANEL-WINDOW.json`; [`results.json`](results.json) requires all twelve and aggregates absolute SSE/reference energy instead of averaging ratios.

## Cost and future execution boundary

At peak t256 preflush: seven quantized K slabs 17,920 B, 32 recent K 8,192 B, 223 quantized V 17,840 B and 33 recent V 8,448 B = **52,400 B** unchanged; the 2,304 B group-specific U/D yields **54,704 B**. Final postflush dynamic state remains 46,592 B (plus metric =48,896 B). The metric train-only preparation requires 4,096 Q projections/normalizations/RoPE (already original source work, but repeated offline here), 128×128 covariance accumulation and one 128D eigendecomposition. At each key flush there is the original `32×128` per-channel min/max plus original nibble assignment, then **32×128×8** products to initialize `s`, **32×128×8** rank-gradient products and **32×128×8** rank-state updates over one 128-coordinate sweep (with 32×128 diagonal operations, nearest-level round/clamp, and code writes). Across eight flushes that is 786,432 rank-coordinate product/update positions in this serial rule, plus 32,768 coordinate decisions, not free preparation. A more selective update can skip zero deltas but is not measured here. V insertion/flush, all K/V code/field loads, both heads' packed query score/softmax, V mixture and full O are **identical work forms** to the original KIVI consumer; only the K code values differ. Current CPU replay expands K/V as **transient scratch** for numerical acceptance (up to 262,144 B per query); it is not a 54,704 B total CPU process or native implementation. A native flush implementation, register/code ledger and end-to-end timing remain outstanding; do not treat lower held error as a speed claim or strict quality/bytes/work domination. The separate [fixed conventional V45 allocation](../kivi-v45-control/README.md) costs54,688B peak,16B below this variant. It recovers11.88% held pair-O error versus original KIVI (this metric recovers13.0%), with all four held windows improving and better aggregate train O than this metric. It leaves attention KL unchanged. That comparison sharply limits the apparent rate-quality advantage of the extra metric; no further rank/sweep tuning follows. No GPU used.

The displayed rate is for **one sequence**. U/D is immutable model-group data, whereas each recent buffer belongs to one sequence. At N concurrent 256-token sequences the represented peak assets are `52,400N+2,304` for this metric variant and `54,688N` for V45, before common source/code/scratch. Thus the former has fewer represented bytes from N=2 (107,104 versus109,376B). This is not measured runtime memory: the current CPU encoder converts U/D into **9,216B of FP64 arrays**, and source/error/mode buffers plus full-prefix decode scratch are separate. A native prepared copy or on-load conversion must also be priced. Sharing the immutable metric does not share away the coordinate-sweep work, which repeats for every sequence.
