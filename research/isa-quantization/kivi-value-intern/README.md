# Exact full-eight-head V-record interning on KIVI2

**Fixed control, not a new quantizer.** A literal first-occurrence dictionary over equal *stored byte records* reduces the 256-token original full-layer KIVI2 serialized cache from 304,768 B peak/249,856 B final to **241,925–263,429 B peak / 187,013–210,053 B final** across all eight original train and four inspected-held windows. Mean peak is 254,661 B train and 258,917 B held; mean final is 200,325 B train and 204,325 B held. Savings are **serialized-state only**: the measured offline encoder retains a conventional K/V shadow and two encoded images during maintenance, so this experiment does not establish a lower *working-memory* footprint or a faster reader. It is an ordinary exact dictionary control, not a novel ISA primitive or a fit on the held set. The parent's [value-record quotient](../value-record-quotient/README.md) provides the Lean finite regrouping and continued-state simulation foundation, separating unchanged positional readout from an unmeasured grouped-probability reader.

## Frozen layout and chronology

One image has a five-byte header: little-endian `u16 t`, `u8 phase` (`0`: after arrival, before current query's flush; `1`: after that query's flush), `u8 quant_unique`, `u8 recent_unique`. Then for heads 0…7, byte-for-byte original K2 quantized chunks (1,536 B each) followed by their original recent BF16 K tokens (256 B each). Then come first-occurrence, position-major full-eight-head **384-B** quantized V dictionary records, one **u8** reference per quantized position, first-occurrence, position-major full-eight-head **2,048-B** recent BF16 V dictionary records, and one **u8** reference per recent position. Records for separate heads or quant/recent domains are never conflated. The length is precisely

`5 + original_K_bytes + 384*quant_unique + quant_positions + 2048*recent_unique + recent_positions`.

The phase and `t` determine original K/V counts without an extra length table: before query, quant V positions `max(0,t−33)`, recent `t−quant`; after query, quant `max(0,t−32)`, recent `t−quant`. K chunk count is `(t−1)//32` before and `t//32` after, recent K `t−32*chunks` per head. The horizon 256 bounds quant/recent references and dictionary counts to 224/33; **no uncharged 16-bit index, allocation capacity, indirection offset, or extra per-head dictionary** is needed in the serialized image. Header, both index arrays, even unique singletons and first-occurrence records are paid. No hash collision is trusted: the literal encoder performs byte equality on complete records. Canonical first occurrence is rebuilt on every transition; after the oldest recent token flushes, its final reference and, if unreferenced, its 2,048-B dictionary entry disappear. This makes reclamation real rather than retaining a historical vocabulary. Every K byte, both V quantizer's codes/FP16 fields, and the BF16-recent rule are unchanged.

At each `t`, append the original BF16 K/V arrivals to the before-query state, query it, then consume the original paid K32 flush when due and oldest-V flush at recent33, and construct the after-query state. No future tokens, fit, clustering, or group-width selection enter this layout. A live consumer reads the 1-B V reference for each position, computes `dictionary_base + reference*384/2048 + head*48/256`, and reads the exact head's 48/256-byte record in the **same positional order** as baseline. At a 256-position query that is 256 distinct reference bytes (223 quant +33 recent before the query flush), potentially4096 reference operations across16 Q heads without reuse, up to two separate V dictionary address calculations per position/head-query pair; both GQA Q heads may reuse a fetched KV-head record, but no reuse is assumed free. K access, score, softmax, V weighting and full O remain original. No expanded K/V matrix is necessary to dereference the image; no packed native attention kernel or speedup is claimed. Reordering/grouping the V contributions could alter floating-point rounding and is not part of the quality bridge.

## Actual causal custody and independent acceptance

[`encode.py`](encode.py) reads the canonical original [`../kivi-two-bit-causal/`](../kivi-two-bit-causal/README.md) per-head event streams and only the arriving source BF16 vectors; it writes a **1,049,088-B/window chronological event stream** (`u16 t + 2048-B K arrival + 2048-B V arrival` for every position), actual final image, and all **512 before/after image hashes, exact byte lengths, counts and component ledgers** in each `*-manifest.json`. The already-paid original K/V flush events remain in their source files, with hashes pinned here; the new arrival event stream and original logs together are the transition witness, **not** an additional simultaneously retained cache. Prefix images are materialized, hashed and discarded rather than committing twelve enormous duplicate streams of complete snapshots; the original events plus arrivals deterministically regenerate their bytes and the final image is committed literally.

[`verify.py`](verify.py) imports none of the encoder's packing, dictionary, layout or decoding functions. It independently loads source arrivals, checks the audit event stream and original event-log hashes/timestamps, regenerates each immutable original KIVI2 per-head state and checks its original paid per-prefix SHA256/length, parses every new image (header, K, both payload tables and both index arrays), checks dictionary uniqueness and canonical first-use ordering, **compares every decoded K and V logical record byte-for-byte with the original at every prefix**, and checks final images byte-for-byte against the original donor. It checks event exhaustion, all 6,144 phases, and the 12 actual final images. The existing [`../kivi-two-bit-causal/results.json`](../kivi-two-bit-causal/results.json) complete 16Q/8KV full-O quality receipts transfer exactly because each query reads the identical ordered K/V records; no unchanged model or observer is rerun. Those receipts give held full-O relative squared error **0.003124373**, mean head KL **0.0761010**, not a new generation score. SHA256 is audit integrity, not the equality criterion; decoded actual bytes are compared directly.

First-use rebuilding made **25,604,918 complete-record equality probes** across the panel's 6,144 snapshots; equality can inspect up to 384 or 2,048 B per probe and all prior active positions may need rescanning twice per arriving token. At t256 one live query needs the 256 positional V-reference fetches plus head-record accesses; numerical attention/O work does not vanish. Building an image writes the complete K bytes again and copies all unique V entries and positional references. The 8-head source arrival is 4,096 B per token, and each post-query flush consumes eight original K chunks (8×1,536 B at multiples of 32) or eight V records (384 B from t33 onward). Original quantizer operations and insertion staging remain paid.

**Working-state obligation.** The literal Python audit encoder holds conventional K/V record lists as well as its serialized image, and the source producer/teacher arrays, event logs and JSON receipts live in offline scratch. Conventional active V alone reaches **153,216 B** (223×384 +33×2,048); K reaches 151,552 B at that same before-query phase. If this literal maintenance holds old and next encoded images simultaneously, the maximum measured *sum of those two image lengths* is **522,376 B**, before those original K/V lists, 4,096-B arriving record, temporary concatenated/search records, Python object overhead, source producer tensors, manifests or events. It exceeds the 304,768-B original cache even without those further costs. The [separate in-place/dictionary-native maintainer](../kivi-value-intern-maintenance/README.md) now removes this shadow and second image with all6144 states equal. It pays284674B fixed buffers and299008B conservatively rounded writable ELF/stack state on this panel, plus shared code and3.36GB of moves; those are separate implementation receipts, not a revision of this rebuild encoder's measured bill. The dictionary-search data structures are the paid image entries themselves, not an unpriced hash table; this encoder's Python lists and rebuilt temporary buffers are additional working memory. The finding is serialized representation savings and lossless query indirection, not a demonstrated total-RAM or runtime win.
