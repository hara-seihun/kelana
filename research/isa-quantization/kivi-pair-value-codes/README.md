# Deterministic two-coordinate V2 source assignment

**Frozen consumer, one paid source program.** At each original after-query V33 flush, retain the original source-derived FP16 low/step for every G32 and choose each disjoint pair's two 2-bit digits from all 16 possibilities, minimizing its *stored FP32* two-Q-head O-column Gram energy on the original BF16 source V. Use the lexicographically smallest `(digit_i,digit_j)` on exact FP64 energy ties. K2, recent BF16 V, query format, attention and complete original BF16 O are unchanged. This is deterministic bias/representation selection, **not** a random unbiased coupling, pair-map sign sampler, feedback fit, query-aware assignment, or native kernel/timing claim. The matching is the corrected **layer-local** [`value-pair-covariance/pair-map.bin`](../value-pair-covariance/pair-map.bin), 1,568 B per layer; layer 0 and layer 1 never share pair indices or O columns.

## Frozen byte arithmetic and ledger

The original O files are SHA256 `803995a9d5abb24c72d3ddabd50f4e656fc5eff26efaf3b626f175fc706ab499` (layer 0) and `677e1de44f3a28a51b2e75e806a8ec68807ed96dfadc169729c1993181418f48` (layer 1), row-major BF16 `[1024,2048]`. For each pair `(i,j)` within KV head `h`, the two O columns for coordinate `i` are `(2h)*128+i` and `(2h+1)*128+i`, similarly for `j`, **from the same layer**. [`common.py`](common.py) sums both column dot products in FP64, rounds each `Gii,Gij,Gjj` once to FP32, and writes a little-endian [`metric.bin`](metric.bin): `8 heads × 64 pairs × 3 FP32 = 6,144 B per layer`, 12,288 B for both model layers. The independent [`aggregate.py`](aggregate.py) regenerates every stored metric from the two SHA-checked O images and compares FP32 words. This is static model-specific memory alongside the unchanged O; preparation scans 1,024 output rows for each selected pair's three two-head dots once per model revision, not per token. The pair map and metric total **7,712 B per active layer**, shared across sequences and not repeated per sequence.

The decoder levels are exactly `FP32(low + FP32(step * digit))` with separate product and addition from the **original actual FP16 fields**, four levels per coordinate. At V33, `e=FP64(original_BF16_value)−FP64(actual_FP32_decoded_level)`; evaluate `Gii*ei² + 2*Gij*ei*ej + Gjj*ej²` in FP64 using the actual stored FP32 Gram fields. The metric is not rebuilt from model weights during the online assignment. Each flush has 64 disjoint pairs/head ×16 candidates =1,024 scalar energy evaluations/head (plus four levels per coordinate); across all eight heads and 224 V flushes that is **1,835,008 evaluations per 256-token sequence**, and exactly one deterministic changed V2 record per original flush. Source extrema and FP16 fields remain the original emitted words. The literal builder allocates a 2,048-B temporary decoded four-level table (128 coordinates ×4 levels ×FP32), 128 B of candidate digit scratch and bounded pair/energy scalars in addition to the existing recent BF16 source; these are producer scratch, **not** persistent cache. This is a CPU cost model, not measured device latency. Q/K/V producer arrays and checkpoint, original O, teacher, snapshot logs, independent audit and full attention temporary matrices are common/offline and not disguised as resident savings.

Candidate per-sequence peak remains the original **304,768 B** pre-query serialized K2/V2 cache; final **249,856 B**. With layer static cost: **312,480 B** one-sequence combined peak, **257,568 B** final; shared static cost amortizes for multiple sequences. The sole nearby-state control keeps *original K2/V2 payloads and codes*, but postpones each original V flush four positions from V33 to V37; post-query retains 36 recent V records (before-trigger 37), with each displaced 48-B aged V replaced by its 256-B recent BF16 record. Its per-sequence peak is **311,424 B**, final **256,512 B**, no new static bytes. Both causal streams score every query *before* its scheduled after-query flush. The unchanged K2/V4 and FP32 moment receipts are linked by SHA in the summary and not rerun.

## Independent replay and provenance

[`build.py`](build.py) consumes only the saved original BF16 arrival/source fields, unchanged donor K and V events, and static map/metric. It emits actual timestamped candidate events, t128/t256 pre-query images, final images and 256 pre/post hashes per KV head per window. [`audit.py`](audit.py) independently parses all emitted bytes; checks source BF16 V original FP16 fields and original digits, actual candidate FP16 fields, exhaustive 16-way pair argmins/ties, K equality, recent raw words, donor prefix bytes/hashes, candidate every-phase/final bytes, delay4 chronological payloads, and the full 16Q/8KV original-O output at **every contextual query** and eight retained layer-0 positions. It compares original output hashes/SSE with the existing complete-output receipt. `aggregate.py` pins original source, metric, pair map, all program bytes and unchanged original/moment/K2V4 receipts. No forward/capture, teacher regeneration, GPU, parameter sweep, precision ladder or permutation search occurs. Source-only BF16 K/O reduction sensitivity remains part of the original contextual boundary, not subtracted from errors here. The retained held inputs have only t128/t256 Q/teacher, so this does not assert unrecorded held outputs or a full-model rollout.

Run with the already-installed one-thread Python environment, each window in its own sub-55-second call:

```sh
cd research/isa-quantization/kivi-pair-value-codes
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
PY=/path/to/workspace/data/fish-s2-pro/venv/bin/python
$PY common.py                          # only when rebuilding static metric from pinned O
$PY build.py train 0; $PY audit.py train 0
# likewise train 1..7, validation 0..3, held 0..3
$PY aggregate.py
```

The on-disk images/logs are evidence, **not** additional online cache buffers. The per-sequence 2-B position count, common original model weights and application allocator are outside both cache ledgers. Model-static pair/metric placement, CPU producer work and observer scratch are stated separately; no unsupported native time or code-size result is inferred.
