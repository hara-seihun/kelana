# First matched-byte control for weighted input pairs

**Frontier question, not a Q4 rejection.** A smaller image can reasonably lose more response accuracy than the 8,704-byte Q4 image. The [linear](../full-pair-covariance/README.md) and [affine](../affine-pair-covariance/README.md) universal certificates prove only that weighted pairs cannot reach *that larger Q4 image's particular error* on the captured train panel. This study pays **exactly 6,848 and 7,104 bytes** for local conventional scalar controls and selected weighted-pair readers at each matched rate. It replays eight serialized images independently, retaining both the original GPTQ-style grids and full-response-refitted grids. At **7,104 bytes**, the exact universal affine-pair floor is **above** the strongest local conventional control's captured-train error: no member of that specified pair family can beat this equal-byte control **on captured train error**. At **6,848 bytes**, the universal linear-pair floor remains below its equal-byte control; that frontier comparison is open. The tested paid pair choices lose at both rates. This is not joint error/storage/work dominance: pair input maps have fewer nominal coefficient terms, and native work is unmeasured. Using the original 16,384 unique source coefficients as the denominator, these paid payloads are **3.34375 and 3.46875 effective BPW**, versus **4.25 BPW** for the larger 8,704-byte Q4 image. The changed number of stored carrier/readout fields does not change that comparison denominator.

## Actual existing comparator and unavailable exact-boundary control

The strongest available first-party calibrated scalar converter is [`q4-diagnostic/calibrated.py`](../../quantization-discovery/q4-diagnostic/calibrated.py): full-covariance damped inverse-Cholesky sequential GPTQ-style error compensation, affine FP16 scale/origin grids and actual packed output images. Its 197-image whole-model 4.251313 BPW conversion reached test NLL 3.795795, unlike plain rounded Q4. Existing images live at `/path/to/workspace/data/kelana-subbit/q4-diagnostic/calibrated/`; they cover **full original Qwen matrices**, not a packed and charged 128×128 q_proj slice at these two byte budgets. The [`producer-screen`](../producer-screen/README.md) 8,704-byte Q4 local image is genuinely exported but uses a different, weaker row-grid fit and a larger budget. The [full-scalar](../../quantization-discovery/subbit/full-scalar/README.md) packed Q2/Q4 controls are calibration-independent least squares, not a strong covariance-aware baseline.

The [comparator map](../../quantization-discovery/subbit/frontier/README.md) names **QTIP/QuIP#** as strong low-bit structured methods, NanoQuant for sub-bit PTQ. No QTIP/QuIP# implementation or stored image for this exact 128×128 captured boundary is available in the local projects/data/workspace census. Implementing its source-specific transform/codebook or trellis, storing and charging every descriptor/codebook/scale and independently decoding the local image is the missing integration before a structured-method comparison. The existing [stock GGUF analysis](../../quantization-discovery/q4-diagnostic/STOCK-GGUF.md) scores complete external models with imatrix preparation and separate embedding/head copies: its nominal bit labels and full-model payload denominators cannot be substituted for this local 128×128 image. **This study measures a local calibrated GPTQ-style control, not a named SOTA winner.** A stronger same-budget conventional/structured image could change the observed local frontier.

## Four paid images on identical train/held producer states

The local GPTQ adaptation uses the exact 128×128 BF16 teacher and full 2,048-row train covariance, 1% diagonal Hessian damping, three initial clipping ranges, four affine least-squares grid alternations, FP16-rounded grid parameters, and the sequential inverse-Cholesky error updates from the existing `calibrated.py` method. Each row chooses its lowest *train response* error among three starts. A second control freezes those sequential codes and solves the **two-parameter full-covariance normal equations** for that row's scale/origin, rounds both to FP16, and retains whichever stored grid scores lower on train. This changes neither code precision nor bytes and is a structural fixed-code response fit, not another code-search iteration. The same refinement is applied to paid pair output grids. A Q3 base row uses 48 packed code bytes, FP16 scale and FP16 origin; a Q4 row uses 64 code bytes and the same two FP16 parameters. Only training states select which 11 or 27 rows upgrade to Q4. One 16-byte row-mode bitmask is fully charged. The fixed 128×128 format needs no separate shape descriptor; container bytes are excluded for every arm.

The pair image uses the **previously selected** greedy 32-edge free-ratio program from [`weighted-input-pairs/results.json`](../weighted-input-pairs/results.json), rounds each ratio to stored FP16, refits an arbitrary real 96-carrier output readout on train, then quantizes all 128 output rows to packed affine Q4 with the same local damped-Hessian procedure. The affine arm centers its training response and 96-carrier features, and stores an FP16 output intercept fitted after output quantization. That is a *single selected program*, not a global pair optimization. Each pair has two uint8 source indices, each singleton one uint8 index. All are explicitly stored, as are 32 FP16 ratios. The selected pair's **free-real train floor after ratio rounding** is measured separately, so code-fitting loss is visible.

The 6,848-byte linear universal floor is **.000222852 below** the strongest measured matched scalar error; an as-yet-unfound pair map might beat it. At 7,104 bytes, the affine universal floor is **.000123705 above** the matched scalar's captured-train error. The independent image decoder reconstructs the scalar error as an **exact rational** from the stored FP16 grids and exact dyadic producer/teacher, then strictly compares it with the affine-pair certificate's exact rational floor. Thus *every* 32-disjoint freely weighted pair map with arbitrary real affine readout loses to this particular equal-byte local scalar image **on the captured train panel**, even before paying codes. The selected paid pair images also lose on held states, but the universal train certificate is not a held-state lower bound. No isolated local response number is full-model NLL or native latency.

For the scalar 6,848-byte arm 11 rows have Q4 codes (`11×64 +117×48 =6,320` bytes); for 7,104 bytes, 27 rows have Q4 (`27×64 +101×48 =6,576`). The 96-carrier pair readout uses 128×96 Q4 codes, exactly 6,144 bytes. Bitpacking is little-endian per row; row modes, source indices and ratios have fixed order in the documented decoder. Those totals exclude common executable code/framing, not a secret uncharged lookup table. The hypothetical weighted input program also pays 32 ratio multiplications and 32 additions before 12,288 output terms; an FP16 affine intercept adds 128 output additions. The scalar path consumes 16,384 coefficient terms; storage is matched but native runtime is **not measured**.

[`fit.py`](fit.py) writes all eight finite packed images, using only train rows and the prior pair selection. The initial images remain unchanged for method comparison. [`replay.py`](replay.py) is an independent decoder: it imports none of the fitter's packing, selection or quantization methods, verifies the fixture and all eight pinned image hashes, checks byte totals, masks, complete disjoint source coverage and finite FP16 metadata, and scores the *stored bytes* on train and 1,024 held states. For the winning 7,104-byte scalar control it also imports the independently maintained exact Gram builder, reconstructs the exact rational train error, binds the affine certificate hash and asserts its floor is strictly larger. [`results.json`](results.json) binds each image SHA256, charged field sizes, upgraded rows, response errors and this strict exact comparison. Existing fixture and prior certificates remain with their owners; no new capture/model checkpoint or GPU is needed.
