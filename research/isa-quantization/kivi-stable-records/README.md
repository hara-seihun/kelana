# Stable-slot, locally maintained exact KIVI2 state

This is one frozen CPU-native representation, **not a new quantizer, another pass over the model, or a claim of attention latency**. `stable.cpp` consumes only the existing arriving BF16 K/V bytes, appends them, exposes the complete pre-query state, performs the original K32/V33 flush locally, then exposes the post-query state. Its physical V dictionary slots remain at fixed addresses while live, and recent slots are reclaimed by reference count. The logical chronological order is in paid reference arrays; canonical first-use serialization order is not maintained. At every one of 6,144 phases in the 12 immutable windows, `audit.py` independently compares the ordered K and V records **byte for byte** to original quantized donor events. No hash replaces record equality, no source arrays/model/teacher/quantizer fitting or GPU work is used. The earlier complete 16Q/8KV full-O quality receipts apply through identical ordered original bytes; this experiment adds no latency measurement.

The parent [address-coordinate foundation](../value-record-quotient/ADDRESSES.md) and `Kelana/StableRecordCoordinates.lean` explain why chronological decoding survives arbitrary live address renaming, local dead-slot insertion and last-reference reclamation. They do not formally verify this C++ implementation. The previous [flat resident GPU program](../kivi-resident-cache/README.md) is an independently completed, slower physical placement, not the native execution of these stable slots.

## Declared fixed capacity and admission

This design fixes capacities at **148 quant V slots × 384 B**, **33 recent V slots × 2,048 B**, and **eight K head slabs × 18,944 B**. The 148-slot panel bound was public before this design (previous interner max active quant unique 148); this is **panel-bounded admission**, not an all-input 256-token guarantee. Arbitrary BF16 inputs can create more than 148 distinct quant records and are rejected at the instant of admission rather than silently spilling or allocating another image. The [source-admissible witness](../value-record-source-capacity/README.md) subsequently establishes actual rejection on a valid181-token ID history, rather than hypothetical arbitrary BF16 inputs. Recent capacity 33 covers every possible recent position, including all-distinct inputs. K slab 18,944 B covers seven 1,536-B chunks and 32 recent 256-B tokens before the final flush; previous K chunks are never moved, and flushing overwrites the current 8,192-B BF16 slab with its 1,536-B packed chunk, leaving inaccessible slack until the next append. All 148/33 slots and this slack are **reserved**, not charged only when observed occupied.

The exact fixed array bill is K 151,552 B + quant slots 56,832 B + recent slots 67,584 B + q/r positional references 224+33 B + q/r u8 reference counters 148+33 B + arriving record 4,098 B + quantization scratch 4,096+512+1,536 B = **286,648 B**. `u8` counts can represent at most 224/33 references respectively. Other native scalar globals/alignment raise compiled ELF `.bss` to **286,880 B**, plus `.data` 16 B and initialized writable ELF support sections. `g++ 15.3 -std=c++20 -O2 -Wall -Wextra -fstack-usage` shows a largest local flush frame of **784 B**; allowing a full **4,096-B stack page** for the bounded native call chain, separately rounding the `.bss` and writable initialized data to 4-KiB pages gives **299,008 B** (290,816 + 4,096 + 4,096), below the original 304,768-B cache-state peak by **5,760 B** on this conservatively rounded writable-state comparison. This is not a universal capacity guarantee or a process RSS dominance claim: the executable `.text` is **4,826 B** and its three read-only/executable LOAD segments occupy four additional 4-KiB pages (total **315,392 B** including those code pages and rounded writable/stack pages), excluding shared loader/libc pages. Code is shared across instances, not a free cache record; no matched whole-process baseline is supplied. `stable` has no application heap, allocator, shadow K/V image, full next image, or resident transition log. The Python verifier, original donor streams and output pipe are offline acceptance resources.

An arrival writes eight K slices in place, then scans up to 33 live recent slots using **exact 2,048-B equality** and writes at most one new slot. A V33 flush quantizes only the oldest live 2,048-B BF16 record using the original 4 groups/head; it scans up to 148 live quant slots with **384-B exact equality**, appends one quant reference, removes the oldest recent reference and decrements its slot's count. A zero-count slot is reusable; no record bytes move on reclaim or reuse beyond the one newly admitted record. A K32 flush quantizes eight local 8,192-B slabs and writes eight 1,536-B chunks in place. There are at most 33+148 slot-header checks, and at most 33×2,048 B and 148×384 B of equality scan per respective admission; actual memcmp may stop early. Fixed-size slots have no external fragmentation, but unused slots, dead stale bytes and K-tail slack remain charged in the fixed bill. Quant slots cannot be reclaimed within this 256-token horizon because no old quantized position expires. For a longer rolling context this policy needs explicit quant reference removal and a separately stated capacity contract, not an inferred guarantee.

A query dereferences the **same chronological records**: each of up to 224 quant positions fetches a one-byte `qrefs` slot index and adds `384*slot + 48*KVhead`; each of up to 33 recent positions fetches one byte from the circular `rrefs` and adds `2048*slot + 256*KVhead`. It pays up to 256 reference loads and 256 indexed record fetches per KV head per query, or up to 4,096 reference operations if repeated independently over 16 Q heads; no free grouping/reuse or measured reader speed is presumed. FP reductions must still follow original positional order.

## Acceptance and retained evidence

`audit.py` implements its own stable-slot decoder (slot IDs, positive counts, ring-order references, unique occupied bytes and exact head slices) and separately reconstructs the conventional original per-head state from immutable donor K/V event logs and the arriving stream. It checks donor per-phase SHA/length as additional integrity, but compares every decoded K/V record's actual bytes to that independent state. The native producer does not read quantized donor events or hold a whole encoded state. It streams variable-length snapshots in segments; the verifier retains **all 512 actual snapshot digests**, the **literal final encoded snapshot**, and a per-window work receipt. The immutable BF16 arrival streams are in `../kivi-value-intern/*-events.bin`, pinned by SHA256 in each receipt; with `stable.cpp` and the empty initial state they are a lossless compact transition history. These final snapshots plus histories and receipts are retained here without storing twelve redundant full 512-image streams.

Across 8 train + 4 held windows: **6,144/6,144 phases**, **7,275,264 independent ordered original record checks**, **148/33 maximum occupied slots**, largest emitted snapshot **263,761 B**, **207,659 exact-record comparisons** (190,674,944 B is the full-record-width *upper bound*, not actual memcmp traffic), **12,636,288 B of key/record writes** including arrivals and K32 rewrites, and **12,589,056 B of arrivals read**. No whole-cache suffix shift is present. Peak emitted snapshot includes slot ID+count overhead and is not reserved capacity; the latter is the fixed 286,648 B arrays plus native code/stack above. Hashes and final snapshots are in the twelve `*-result.json` and `*-final.bin` files; `summary.json` aggregates their ledger. The bounded admission succeeded for all windows. The original maximum 304,768 B is a cache-state baseline, not a measured process/RSS or runtime comparator.

Reproduction, from this directory:

```sh
g++ -std=c++20 -O2 -Wall -Wextra -fstack-usage -o stable stable.cpp
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python audit.py held-0
python aggregate.py
```

Substitute each of `train-0`…`train-7` and `held-0`…`held-3`; each window finishes individually well under one minute. `stable` and `.su` are generated and ignored. No first-party files outside this directory are modified by these commands.
