## Fixed causal map and receipts

The owned [`../kivi-two-bit-causal/`](../kivi-two-bit-causal/) images/events are **unchanged**: K per-channel 2-bit codes for each 32-key chunk, FP16 channel origins/steps; V per-token four 32-coordinate groups of 2-bit codes and FP16 fields; BF16 recent K/V, K flush on arrival of its 32nd recent key **after** current query, V oldest flush on 33rd recent value **after** current query. Same original Qwen BF16 source, RMSNorm/γ, RoPE, Q16/KV8, causal softmax, V and full 1024×2048 original O. Source fixture SHA256 `389e5f8c17ac151070b12094849f450130ab9c1684f51b402d59fd4e7ac2008f`; checkpoint revision `c1899de289a04d12100db370d81485cdf75e47ca` and SHA256 `f47f71177f32bcd101b7573ec9171e6a57f4f4d31148d38e382306f42996874b`. No producer fit, source change, retuned bits, new model fields, activation-cache storage or future-key access. Two Q heads in each group share one KV cache but **prepare distinct live query labels**.

For Q head `h`, existing quantized K chunk `c`, source channel `d`, code `i[t,d]∈{0,1,2,3}`, FP16-stored/FP32-read origin `o[c,d]`, step `s[c,d]`, dynamic normalized/rotated FP32 query `q[h,d]`, set `f[d]=FP32(q[h,d]·s[c,d])`. Partition `d` into exactly **four contiguous groups of 32**. For each group `g`, compute `a[g]=max_d |f[d]|/127` in FP32; if the maximum is zero use `a[g]=1` and all q bytes0. Set `b[d]=clip_{[-127,127]}(round_to_nearest_even(f[d]/a[g]))`, as signed int8. The **per-chunk** FP32 origin bias `B[c,h]=Σ_d q[h,d]·o[c,d]` is kept; it cannot be erased as a globally common softmax shift. Score for a quantized token is `(B[c,h]+Σ_g a[g]·int32_dot_32(b[g],i[t,g]))/√128`. Each 32-coordinate dot is mathematically exact in int32: `|dot|≤32×127×3=12,192`, and the observed largest magnitude on this panel is2,923 (train) /2,683 (held). Only the query folding/quantization, FP32 scale/bias/reduction and its native rounding are approximate; key code labels themselves remain identical. Recent BF16 K still use a real dot. Original packed KIVI2 V decoding, score softmax, V reduction and full O are unchanged, not elided because only the K dot changed.

[`map.py`](map.py) independently consumes each original timestamped event when it becomes available, checks **every one of 256×8 pre/post serialized cache hashes**, every available-source flush field/digit, final paid image bytes and original donor hashes; it forms integer group dots without expanding quantized real K in its changed arm. A **separate audit arm** expands ordinary original KIVI2 keys and verifies exact reproduction of each frozen owner's O numerator and every Q-head KL; its FP32 expansion is not an input or resident state of the proposed changed consumer. The two arms share *only* V decoding/probability-weighted value/O and the original source. [`aggregate.py`](aggregate.py) insists on all eight train and four held source windows, actual image/event hashes and original owner denominators. Result files contain all head KL, maxima, query-preparation counts and actual SSE numerators.

## Complete gfx1151 query compilation and accounting

[`consumer.hip`](consumer.hip) compiles **two** complete packed-state readers with the same 8-state pointer array, dynamic 16×128 already-normalized/rotated queries, original full BF16 O, and one 32,768-B FP32 8×1024 group-partial-output buffer plus 4,096-B final output. There is **no expanded K or V device matrix**. Each of eight first-stage CTAs handles its two query heads and shared K/V, scores all current causal tokens, executes stable softmax and original packed V/recent readout, then multiplies the **entire original O** columns for its two heads; one common second-stage kernel sums eight O partials. The conventional arm does FP16-field on-the-fly K2 unpack/dequant-dot within each score. The changed arm prepares FP32 `q×step` per channel, four maxabs scales, 128 signed query bytes and an origin bias per chunk/Q-head in CTA LDS; it does **not** fold per-query data into a persistent model image or ignore chunk-dependent offsets. In its inner loop, one existing 2-bit-code byte holding four digits is expanded to four unsigned byte lanes by `u=(c|(c<<12))&0x000F000F; w=(u|(u<<6))&0x03030303`, exhaustive **all-256-byte** finite check, then one mixed-signedness `__builtin_amdgcn_sudot4` per quartet with the prepared signed-int8 Q bytes. This expansion is paid in emitted instructions; the compiler actually used a different multiplication/or/mask schedule with 32 static `v_dot4_i32_iu8` sites. No 128-entry lookup table or prepared full K matrix is assumed. Both kernels retain FP16 field loads, recent BF16 work, full V readout and O. This compile-only device implementation was **not** numerically launched; small native FP32 rounding differences from the CPU map remain a boundary.

[`build.sh`](build.sh), [`assembly-gfx1151.s`](assembly-gfx1151.s), [`compile-receipt.txt`](compile-receipt.txt), [`opcodes.py`](opcodes.py) and [`opcode-receipt.json`](opcode-receipt.json) retain the exact emitted code, symbols/descriptors and static counts with ROCm HIP7.2.53211. Each first-stage body is shared by every KV head and sequence, not replicated eight times in the executable. In a standalone arm, both have the same 372-B second-stage body, 64-B device descriptor for each body, 32,768-B O scratch, 4,096-B O output, 64-B array of eight cache pointers, common Q/K/V/O/gamma source weights and **304,768-B paid KIVI2 cache**. This is a code/state ledger, not an entire HIP runtime/library census.

First-stage LDS includes 4,096 B scores/probabilities, 1,024 B mixed V, 512 B reduction scratch; changed adds 512 B factors, 2,048 B signed query bytes, 256 B 8×2×4 group scales and64 B chunk/Q-head biases. Its scales and bytes are **dynamic per query/chunk/head**, stored only in LDS; eight simultaneous CTAs allocate 8×8,512 B LDS rather than a single free 8,512-B global table. At t256 preflush, **8 KV heads ×7 chunks ×2 Q ×128=14,336** folded FP32 products, as many signed-byte round/scale operations and origin products, plus **448** group maxabs/scales; the actual 32-coordinate maximum scans are serial in four lanes and each 128-coordinate bias sum in one lane, repeated per chunk/head. Changed quantized K inner loops have `16 Q×224 aged K×128/4=114,688` dynamic dot4 quartet operations plus unpack expansion/field loading, versus conventional `16×224×128=458,752` K scalar dequant-and-dot contributions; there are additionally **65,536** common recent-K terms, **456,704** quantized-V terms, **67,584** recent-V terms, up to4,096 softmax exponentials, and **2,097,152** original O product terms at t256. Query prep cannot be counted once per model or amortized across unrelated sequences. The CPU audit's expanded FP32 K/V scratch likewise is not part of either device kernel. Peak cache+query+finish bodies/descriptors are **318,092 B conventional versus319,956 B byte-dot** before common source weights and working state: a **1,864-B code increase** for the same cache and slightly worse held quality; bigger VGPR/LDS and serial preparation make a blanket execution win unwarranted. No native speedup claim follows from fewer scalar K FMAs.
