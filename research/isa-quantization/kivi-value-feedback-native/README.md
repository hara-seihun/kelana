# Frozen KIVI2 value-feedback resident realization

**Completed:** four held windows pass 4,096 actual device pre/post physical frames, including 16,384 feedback residual phase/head SHA checks, and all 16 actual complete-O guards (eight each arm). Four fresh, order-balanced timing rounds/window give 32 matched t128/t256 boundary pairs. Feedback's median paired event ratio is **1.084×** (slower), with 2/32 faster pairs; median event spans are **87.321 µs conventional** and **92.897 µs feedback**. Its eight actual teacher SSEs pool to **0.580495991** versus **0.832657475 conventional**. Thus the original-O gain survives exact resident implementation, but this one placement costs additional resident bytes and measured boundary time. It is not a full-model or average-token speedup.

This is the one conventional/feedback native resident program for the chronological [value-feedback donor](../kivi-value-error-feedback/README.md) (`da88542`) and the CPU-exact [encoder donor](../kivi-value-feedback-encoder/README.md) (`51089a6`). It uses the accepted [stable-resident](../kivi-stable-resident/README.md) conventional Control layout and unchanged packed query/O reader. Both arms share the same V33 flush body; only feedback has a separately initialized 8×128 FP32 residual. This is a layer-0, four-held-stream, eight-paid-Q-position experiment, not a full-model inference result. No Q fit, source replay, alternative geometry or changed consumer.

## Frozen placement and state

The original BF16 arrival at each t is uploaded and appended to eight K32 slots and eight V33 recent rings. At t128/t256, before the post-query K32/V33 flush, an existing direct ordered 16Q/8KV GQA reader produces a complete original-O projection. The common V producer reads oldest source V at t33…256, produces source-derived FP32 minima, binary64 `(max−min)/3`, stored actual FP16 origin/step, FP32 division and nearest-even/clamped digits. Feedback adds resident FP32 residual to each source before digit assignment, separately rounds decode multiply and add from the **stored FP16** fields, then writes the new 512-B/head residual. Conventional uses the identical producer with feedback disabled and no residual allocation. K records, source arrays, Q, O, and query format are not changed.

All globals are sequential-arm allocations, not overlapping programs: 305,156 B mutable Control, 4,096 B feedback-only residual, 4,096 B arrival, 8,192 B Q, 4,194,304 B immutable O, 32,768 B partial output and 4,096 B complete output. Totals: conventional **4,548,612 B**, feedback **4,552,708 B**. Persistent logical cache peak is 304,768 B conventional / 308,864 B feedback, while the physical Control reserves 305,156 B in either arm. An initialized cache and O H2D are preparation; all arrivals are 4,096-B H2D, and the only Q transfers are the two retained 8,192-B Qs. Acceptance snapshot D2H copies and host image compression are audited overhead, excluded from the separate timing traces. CPU held-arrival/Q/teacher/O/manifest files and eight prepared 4,096-B feedback CPU maps are host evidence, not cache or device persistent state. No global decoded-vector staging buffer is used; producer target and decoded temporaries remain in VGPR.

`compile-receipt.json` pins the gfx1151 binary/source/assembly hashes and ten compiled kernels: 52,932 B bodies plus ten 64-B descriptors. The included stable-resident module's unused stable-slot bodies are charged to the compiled module rather than silently ignored. Actually launched common append K 468 B/0 LDS, append V 4,108 B/44 LDS, K32 8,344 B/4,608 LDS, common runtime-arm feedback/conventional flush 2,432 B/0 LDS/50 VGPR/14 SGPR, unchanged control query 13,968 B/5,632 LDS, O finish 372 B/0 LDS. Every body has zero private scratch; LDS is per CTA, not a global allocation. The encoder additionally reads/writes 1,024 B residual per feedback flush (8×224×1,024=1,835,008 B sequential logical traffic/held stream) versus conventional, with no query-time feedback state read.

## Reproduce and acceptance contract

`bash build.sh` compiles only. `g++ -std=c++20 -O2 -w ../kivi-stable-resident/cpu.cpp -o cpu-reference` plus `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 /path/to/workspace/data/fish-s2-pro/venv/bin/python cpu_precheck.py held-N` synthesizes physically placed control and feedback frames and exercises **the same independent audit** without GPU; its four receipts are `cpu-audit-held-N.json`. `score.py prepare` decodes only eight already-paid feedback cache images into complete 1024-float CPU maps, verifies their hashes against donor receipts and saves them for both device acceptance and timing guards. `prelaunch.py prepare` checks all SHA-pinned arrivals, original O, Q, teacher, original conventional CPU maps, prepared feedback maps, donor manifests, CPU physical receipts and compiled resource identity. It never invokes the GPU.

Before any device stage, a parent reviews source, bill, checks and schedule. For the single authorized stage, write the exact `prelaunch-receipt.json` source hash followed by `accept|timing` and `held-N` to ignored `launch-approved.sha256`. `bash run-stage.sh accept held-N` consumes that one-use approval **before** nonblocking admission, takes the Kelana measurement lock and `gpu-run --host-mib 1024 --gtt-mib 512` for at most 45 seconds foreground; it preserves the same nonzero live Bonsai PID. Each accept starts both arms empty, saves every raw pre/post physical state and the four actual full O outputs. `audit.py` checks all 1,024 device frames/window against original and feedback chronological full-record bytes, original/donor logical prefix hashes and 4,096 feedback residual-state SHA/window, then retains a lossless `.zst` stream and hashes. `score.py` compares both arms to their original/donor CPU maps with max-absolute and relative-L2 ≤.005 and pins actual teacher SSE. No failed stage is quietly retried or retuned.

Only after all four acceptances are independently revalidated may `bash run-stage.sh timing held-N` start, with fresh empty state for **four fixed rounds per window**, both arms per round, alternating first arm by `(window+round)%2`. Only t128/t256 boundary steps are timed; the 32 matched pairs retain raw event, input-transfer, compute-span and host-wall µs plus round/order labels. Every timing output is again guarded against its own CPU map; no acceptance-state import. The `summarize.py` reduction publishes medians and every original paired row. These are K32/V33 flush-boundary timings, not full-256-query or mean-token throughput. Each command is bounded by the host's 55-second foreground limit.

## Native receipt

All eight guarded stages returned zero on their first attempts, with Bonsai `bonsai-halo.service` active at unchanged PID **145247** before and after each. Four losslessly compressed `.zst` raw physical streams retain **314,585,088 uncompressed B each** and SHA in `audit-held-N.json`; the independent device audit checks 1,089,536 chronological original/donor records and 4,096 residual/head phase SHA per held window. All 16 full-O comparisons to retained CPU maps have max coordinate difference ≤**9.537e−7**, well below the fixed .005 maxabs and relative-L2 guards. Both CPU maps are complete 1,024-float original-O projections; feedback CPU map hashes are original donor receipts, not a new Q/model fit. `accept-held-N-receipt.json` pins each actual output's SHA and teacher SSE, the complete receipt hashes and the source/binary identity; `results.json` retains all 32 raw matched timing pairs and the reductions. Device pooled SSE is **0.832657474839 conventional** vs **0.580495991390 feedback**; original CPU donor feedback pooled **0.580496474**, with tiny expected reader-order variation. The original K2/V4 held control remains better and has greater paid cache state; this native result only compares conventional K2/V2 to first-order feedback.
