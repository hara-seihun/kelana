# Frozen one-sweep O-aware KIVI2 values — paid source and eight retained complete observers

**Scoped result.** The prespecified, single ascending-coordinate sweep changes only KIVI2 V two-bit digits. Over the four held 256-token source arrival streams it reduces the independently recomputed sum of represented per-record squared two-head O projections from **5388.304681 to 5083.034810** (7,168 flushed V records; 50,716 changed digits). At exactly the eight already retained `t128/t256` complete 16-Q/8-KV post-O states, its teacher-relative squared error is **0.002808129**, versus **0.003068937** for unchanged, same-serialized-cache KIVI2. Unchanged KIVI4 reconstructed from its separately paid event logs scores **0.0000426253** at those same states. This is a local frozen discriminator, not a full-window or full-model score, speed result, native benchmark, or quality guarantee for the O-aware surrogate.

**Byte distinction:** serialized KIVI2 cache is unchanged at **304,768 B preflush peak /249,856 B final** per full layer. A prepared FP32 O Gram costs **524,288 B additional resident state**, so **cache plus Gram peaks at 829,056 B** per one sequence, *not* the original 304,768 B. The unchanged stronger KIVI4 control has **419,200 B peak**. Same-byte means solely the KIVI2 packed cache format; the candidate has a much larger paid whole-program state for one sequence. Its complete-output error improves **8.50%** over KIVI2 (six of eight states), but is **65.88×** KIVI4's error while using more cache-plus-prepared state. That is a one-sequence error/state rejection of this prepared realization, not a latency comparison or a rejection of every O-aware encoder. With one shared Gram pool and N256-token sequences the state formula is `524288+N*304768`; at N=5 it is2,048,128B versus KIVI4's2,096,000B, reversing those storage axes. No multi-stream throughput or changed-context quality is inferred. The common original BF16 O (4,194,304 B) and other common source weights are shared, not charged to one arm alone. Actual encoder preparation materializes an FP32 copy of O (8,388,608 B) while constructing eight stacked FP32 head blocks (another8,388,608 B). The O copy then dies before Gram construction; the blocks die after it, leaving the524,288B Grams. This is a16MiB transient O/block preparation inventory, not16MiB steady encoder state. The independent verifier separately retains O, blocks and Gram simultaneously. A streamed preparation is possible but is not the implementation measured here.

## Frozen arithmetic and provenance

Original Qwen3-0.6B layer0 common BF16 O is [`../kivi-two-bit-dot-native/original-o.bf16`](../kivi-two-bit-dot-native/original-o.bf16), whose SHA256 is `803995a9d5abb24c72d3ddabd50f4e656fc5eff26efaf3b626f175fc706ab499`. For each KV head h, B stacks the original two 1024×128 O column blocks into 2048×128. Before reading candidate outputs, this arm fixed `G_h = float32(B_h.T @ B_h)` and its initial KIVI2 min/max digits. At each causal V flush, the source is the *arrived* BF16 128D V record; decoding uses the original stored FP16 origin/step. With `e=decode−source` and `r=G_he`, a single sweep j=0…127 evaluates `2δr_j+δ²G_jj` for all four represented digit levels, chooses the lowest code on a tie, and updates `e_j` and `r += δG[:,j]`. K fields, K bytes, BF16 recent K/V, V origin/step, source weights, group32/recent32 timing, and after-query flushing remain untouched. No fit, rotation, scale, damping, extra pass or attention/Q-derived objective was used. This is the finite-grid `D=0, U=stacked O` specialization of [`../../../Kelana/LowRankCodeUpdate.lean`](../../../Kelana/LowRankCodeUpdate.lean); its exact-arithmetic nonincrease is **not** a proof of the realized FP32 decisions or packed results.

The entire source is immutable paid arrivals [`../kivi-value-intern/held-*-events.bin`](../kivi-value-intern/), each token carrying eight original BF16 K and eight original BF16 V, and original paid KIVI2 per-head event logs and prefix ledger [`../kivi-two-bit-causal/`](../kivi-two-bit-causal/). [`encode.py`](encode.py) does not load any checkpoint, invoke source projections, call `source.arrays`, recapture Q/O/teacher, or use GPU. The emitted actual per-head `held-*-head*-events.bin`, `held-*-head*-final.bin`, eight-state `held-*-t{128,256}-kv*.bin`, and SHA/chronology [`held-*-manifest.json`](held-0-manifest.json) are in this directory. Original K event bytes and every original FP16 V field stay identical. Original BF16 arrivals remain source only, not additional resident cache.

The preparation of G costs **8×128²×2048 = 268,435,456 multiply-accumulates once** for the common model O; keeping it resident uses 524,288 B. The code-choice algorithm needs an initial128² matvec and up to128 coordinate updates of128 gradient entries, four scalar candidates per coordinate: an upper count of **32,768 multiply/add pairs per record**, or58,720,256 per window, plus scalar digit/field/packing work and a serial dependency through128 coordinate decisions. In the actual four-stream run only50,716 coordinates change, so the initial matvecs and incremental gradient updates total **123,932,160 multiply/add pairs** across7,168 records. The literal offline encoder additionally computes diagnostic initial/final energies with two extra Gram matvecs and two dot products per record; those add234,881,024 matvec multiply/add pairs plus1,835,008 dot terms. They are verification/receipt work, not credited as free encoding. Neither nominal count is an ISA instruction or timing measurement. Source BF16 arrival and original V extrema/step are still computed and paid; copying K logs in this experiment is not a substitute for the unchanged original K quantizer's production work. The eight snapshots' independent reader expands K/V into FP32, computes two causal Q heads per KV group, softmax, V reduction and complete 1024×2048 O projection. Query format, KIVI2 decode and query work are unchanged; no Gram is consulted at query time. This is arithmetic/byte accounting, **not** a measured speedup.

## Independent byte acceptance and comparisons

[`verify.py`](verify.py) replays all 256 arrivals chronologically; checks every original K event byte and timestamp, each original V min/step and minmax digit against BF16 source, every candidate V field and independently recomputed four-level Gram decision, all emitted event lengths/hashes, every before/after prefix SHA and final image. Separately it recomputes actual projected residual objectives directly through stacked O, including a direct-projection coordinate sweep as a floating-point discrepancy check. It finds **zero direct-projection digit differences** from the Gram sweep and **zero records whose independently projected final objective exceeds initial**, over the observed 7,168 records. The encoder's Gram sums differ from independently projected sums by about 0.0006 per window because FP32 reduction paths differ. These are observed finite-precision checks, not formal monotonicity. The retained KIVI2 control output is independently decoded from original paid before-query images and compared to the already retained conventional CPU output (maximum per-state absolute difference recorded in `held-*-result.json`; acceptance threshold 0.001).

[`kivi4_control.py`](kivi4_control.py) reads the same already-paid BF16 arrivals, KIVI4 group0 event/image from [`../kivi-causal-cache/`](../kivi-causal-cache/) and original other seven group event/images from [`../skvq-global-gqa/`](../skvq-global-gqa/). It checks **every original KIVI4 prefix SHA, event timestamp, final image** and reads only the same eight retained Q/O/teacher files from [`../kivi-two-bit-dot-native/`](../kivi-two-bit-dot-native/). It does not re-encode KIVI4 or substitute its prior 256-query full-panel result. [`aggregate.py`](aggregate.py) adds original state SSE and denominator sums, rather than averaging per-state ratios; exact state SSEs, hashes, direct-check discrepancies and the scope are in [`results.json`](results.json), `held-*-result.json`, and `held-*-kivi4-control.json`. Parent integration added [`inputs.py`](inputs.py), now called before encoding or either reader, to check216 identities against the original snapshot/arrival/donor manifests, including Q/teacher/O and the retained conventional CPU reference. [`inputs.json`](inputs.json) is its additive hash-only custody receipt; successful candidate/control output computations were not rerun. The independent NumPy reader's maximum original-control difference from the retained Torch CPU map is7.153e−7; its different accumulation order explains the tiny difference from the earlier attribution's pooled.003068938. The reported same-reader.003068937 is the paired control used here.
