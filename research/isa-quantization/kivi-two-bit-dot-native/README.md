## Frozen source, snapshot and numerical boundary

[`prepare.py`](prepare.py) consumes the immutable [`../kivi-two-bit-causal/`](../kivi-two-bit-causal/) full16Q/8KV source images/events and CPU [`../kivi-two-bit-dot-query/`](../kivi-two-bit-dot-query/) maps; it neither changes model codes nor fits another quantizer. Four original held windows × `t=128,256` yield **eight distinct actual pre-query-flush states**. Each has eight paid per-head packed images, a current original FP32 16×128 normalized/rotated query, original BF16 1024×2048 O (one common 4,194,304-B image), independent CPU conventional/byte full-1024-output targets and teacher output. Per-KV-head state is **25,808 B at t128** (three K chunks, 32 recent K, 95 quantized V, 33 recent V) and **38,096 B at t256** (seven K chunks, 32 recent K, 223 quantized V, 33 recent V); complete cache states **206,464 B and 304,768 B**. [`snapshots.json`](snapshots.json) pins all original per-prefix and event SHA256 identities, Q/O/output hashes, exact lengths and causal counts. Source fixture SHA256 `389e5f8c17ac151070b12094849f450130ab9c1684f51b402d59fd4e7ac2008f`; original O bytes SHA256 `803995a9d5abb24c72d3ddabd50f4e656fc5eff26efaf3b626f175fc706ab499`. The largest **CPU byte-versus-conventional output coordinate difference** across these eight snapshots is `0.001124604`; this is **not** GPU acceptance.

The native harness `#include`s the **unaltered** compiled study's [`consumer.hip`](../kivi-two-bit-dot-query/consumer.hip), SHA256 `3421c092a8a3ba07d0899582683d0e84ae8cfe4f9614a1aa275220af600b189f`, and calls its already-frozen `launch_conventional`/`launch_byte_dot`. No retile, quantization, codebook, precision or kernel repair. Each mode launches eight KV-head first-stage CTAs for all16 Q scores/softmax/unchanged V and original O partials, then the common O finish kernel. The changed mode alone prepares dynamic int8 Q group scales and signed bytes, expands original unsigned2 codes in the query kernel and executes mixed signedness dot4; common BF16 recent K/V, FP16 fields, per-chunk origin bias, all O columns and decoder work remain. This is a **single current query**, not generation or a whole-model benchmark. Initial numerical acceptance, before any timing, compares each native 1024-vector to its corresponding frozen independent CPU map, requiring **both max absolute coordinate error ≤0.005 and relative L2 error ≤0.005 per arm/snapshot**. A failure exits before timing, retaining numerical lines and stderr; it cannot inherit the CPU quality result as native validation.

## Memory, launches and measured timing boundary

At t256 the harness allocates eight **maximum-sized** 38,096-B packed state buffers (**304,768 B**) even when t128 fills only 206,464 B, the common O **4,194,304 B**, Q **8,192 B**, first-stage O partial scratch **32,768 B**, final output **4,096 B** and eight device state pointers **64 B**: **4,544,192 B** of explicit GPU allocations, before HIP runtime/event/driver allocations. Two kernels per mode, two kernel descriptors per independent deployment; compiled first-stage query bodies are conventional **12,824 B** versus byte-dot **14,688 B**, common finish **372 B** (frozen compile receipt). Measurement binary includes **both** readers and three device descriptors for the alternating comparison; it does not add a decoded full K/V matrix. Host keeps the eight prepared CPU snapshots/targets and one O source; their transfer and compilation are **outside timing**, not free operational work. Production would also pay source Q/K/V projections, norm/RoPE, packed insertion/flush, and any H2D traffic if not already resident.

[`native.hip`](native.hip) first validates every state/arm in a separate pass, rejecting nonfinite coordinates, invalid norms and either numerical threshold failure before any timing begins. The integration review strengthened this host-only guard; neither frozen device kernel nor its tolerance changed. It then gives four fixed warmup launches per arm/snapshot, then **four rounds × two alternating modes** with mode order rotated by snapshot index and round: exactly **32 raw event and 32 raw wall samples per mode**, split evenly across t128/t256. Every event spans **both** the query kernel and finish kernel. The wall stopwatch starts before recording the first event and stops after synchronization of the last, therefore includes dispatch, event recording and host wait; it excludes H2D setup and D2H validation. This short shape samples real distinct source states, no giant repeated token batch inside a kernel. [`summarize.py`](summarize.py) refuses incomplete/failed numerical runs and requires exactly all16 numerical receipts +64 timing samples, preserving raw samples and both medians. The parser also rejects nonfinite/negative numerical receipts and nonpositive/nonfinite timings. It produced the accepted [`timing-results.json`](timing-results.json) from this separate attempt.

[`run-probe.sh`](run-probe.sh) takes `/tmp/kelana-gpu-measure.lock` **nonblocking**, then requires an active live original Bonsai PID before invoking `gpu-run --host-mib 1024 --gtt-mib 512 ./native .`; no process/service is killed. The host budget includes GTT. The wrapper compares serving PID afterward and fails if it changed.
