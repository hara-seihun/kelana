## Source, precise mathematics and frozen preparation

Primary source: Zandieh et al., [*TurboQuant: Online Vector Quantization with Near-optimal Distortion Rate*, arXiv 2504.19874v1, §3 Algorithms 1 and 2](https://arxiv.org/html/2504.19874v1#S3). The [source audit](../current-kv-comparators/README.md) found no official public implementation, so this is an **explicit finite-storage CPU port of the paper**, not an official serving-code reproduction. The authors' mathematical quantizers are stated for unit vectors; our fixed finite adaptation uses the actual Qwen BF16-produced vectors `x` and pays **FP32 radius** `ρ=||x||₂` per K and V. A zero-radius case is rejected (none occurs here). For each source vector `u=x/ρ`, use two independent shared random orthogonal matrices `ΠK,ΠV∈R^{128×128}` generated by Gaussian QR with R-diagonal sign correction, then stored as FP32. The **data-independent** shared four-centroid codebook numerically solves the exact one-coordinate spherical law `f(z)∝(1−z²)^((128−3)/2)` symmetric Lloyd/Voronoi equations with deterministic lower-index tie rule, stores `[-.13304151595,-.03999159485,.03999159485,.13304151595]` as four FP32s, and quantizes each coordinate of `Πu` to its nearest centroid. Each MSE decoder reconstructs `Πᵀc[index]`; the V reader multiplies by its paid original radius.

For K, the original Qwen **post-Knorm/gamma, post-RoPE FP32** teacher is rounded to **BF16 for source insertion** *before* normalization and quantization—matching the frozen KIVI cache's insertion boundary. This post-RoPE placement was fixed before any source encoding/score; **it is not the pre-RoPE SKVQ choice**. Let `m=ΠKᵀc[index]`, residual `r=u−m`, and a third independent FP32 matrix `S` with iid `N(0,1)` entries. Encoder stores `sign(Sr)∈{−1,+1}^{128}` (nonnegative maps +1) and **one FP32 residual norm** `γ=||r||₂` per K. For the current canonical rotated query `q`, Algorithm 2's *asymmetric* inner-product estimate is

`score(q,K) = ρ [q·m + γ sqrt(π/2)/128 (S q)·sign(S r)] / sqrt(128)`.

This is **one residual norm factor**, not `γ²`: Algorithm 2's line 11 already includes it. Both `ΠK q` (or equivalent `q·ΠKᵀc`) and `S q` may be prepared once per current query/head and consumed against all previous K; the CPU acceptance reader decodes `m` and computes the equivalent `q·m`, not a symmetric MSE-only score. All eight KV heads are shared by their corresponding two Q heads; causal logits/softmax use the decoded V cache and the original full 1024×2048 O. This is genuine QJL sign-correction work rather than treating reconstructed MSE keys as if the published unbiased-product claim applied to them directly. Gaussian unbiasedness/real-valued distortion theorems do **not** imply our fixed stored FP32 realization is unbiased or accurate on this Qwen window.

[`prepare.py`](prepare.py) freezes **one NumPy PCG64 seed `20260924`**, independent sequential Gaussian draws for `ΠK,ΠV,S`, FP64 QR preparation (then FP32 matrix storage), and a symmetric exact-beta Lloyd solve independent of model data (56 iterations to threshold `.08651655772`). [`program.fp32`](program.fp32), SHA256 `6aa9d5a62e4763b434f8e59ee1d79322dfda8e7146846748d77bc619f171a1cf`, is a literal packed row-major FP32 image of the **three distinct dense 128×128 matrices (3×65,536=196,608 B) plus one generic shared 4×FP32 codebook (16 B)**, total **196,624 B**. [`program.json`](program.json) pins type, layout, numerical solve, RNG, values and hash. No random generator, learned metadata, centroid table or residual projection is passed off as free at inference. Matrix/codebook storage is shared once across eight KV heads; their general algorithmic code is shared implementation outside this per-model prepared-asset bill. Offline QR/codebook preparation and BF16 source projection use more RAM/time than stored bytes and are distinct from causal resident state.

Each arrived **one-KV-head** K image is exactly 32 B of ordered 2-bit MSE indices (first code in the top two bits of each byte) +16 B big-endian bit-packed QJL signs +4 B FP32 source radius +4 B FP32 residual norm = **56 B**. V is 32 B 2-bit indices +4 B FP32 source radius = **36 B**. No newer-token buffer, sink, per-token min/max, entropy-coding or special outlier channel is present. With all 8 KV heads, **8×(56+36)=736 B/position**, hence **188,416 B** causal packed cache at256; add the single **196,624 B** full shared program image ⇒ **385,040 B** counted combined peak and resident. The source Q/K/V/O weights and Q/K gammas total **12,583,424 B** common to both arms; source RoPE configuration is common as well, not a separately learned table. Current-position counter/bookkeeping is common, not included in either displayed cache bill. A generic reader may keep input/output/key decode scratch far above this compact state: the CPU acceptance implementation holds full decoded key/value arrays and full teacher/logit arrays. No native latency, SIMD register census or fused reader throughput is claimed.
