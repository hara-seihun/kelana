# Shared four-level V alphabet: frozen experiment contract

One shared four-FP32-level table per layer replaces only the original K2/V2 G32 reconstruction alphabet. Train-only fitting uses eight original windows, only their 224/head/window V33-flushed source BF16 coordinates, and original donor FP16 low/step. For positive step, z=(v−a)/b in FP64 and weight b² times the sum of squared FP32 columns of the **original** full O for the two Q heads paired to that KV head. Both layers are fitted independently; layer 0 uses original arrival records and original KIVI2 events, layer 1 uses frozen contextual CPU source and original KIVI2 events. No train Q, teacher or held source fits the table. Zero-step records have constant error and are omitted from fitting.

## Frozen numerical algorithm (before scores)

Sort finite positive-weight z by ascending FP64 value, aggregate equal z in ascending order with FP64 weighted sums, and compute prefix sums W, WX, WX² in that order. Four contiguous nonempty clusters minimize C(i,j)=Σwz²−(Σwz)²/Σw on inclusive sorted unique indices i…j. The recurrence D(k,j)=min over k−1≤i<j of D(k−1,i)+C(i+1,j), with D(1,j)=C(0,j), uses monotone divide-and-conquer row optimization (smallest split index on exact floating ties). Each row is computed in increasing recursive interval order, candidate splits increasing; for equal computed costs use the smallest split. Prefix sums and costs are IEEE binary64 NumPy/Numba scalar arithmetic; no exact-rational optimality certificate is claimed, and finite precision can violate exact Monge structure or cancel small segment costs. The implementation records boundaries, centroids, numerical objective and source counts. Within each cluster centroid is its binary64 weighted mean from the same prefix sums; round once to IEEE FP32 nearest even and store four little-endian FP32 words (16 bytes/layer). No alternate starts, alphabet, seeds or precision sweep.

At each original after-query t33…256 flush, copy original 16 FP16 field bytes per V token and enumerate all four *actual* decode values, `float32(float32(a) + float32(float32(b)*level))`. Compare each to source BF16 decoded to FP64, choose minimum squared scalar error in FP64, smallest label on ties. Pack 128 labels in 32 bytes. For b=0 all four equal, select 0. K chunks/events, recent BF16 K/V, all timestamps and complete original O are unchanged. The shared static table adds 16 bytes/layer, not 16 per sequence: dynamic peak/final cache remain 304768/249856 bytes. Producer calibration/sorting/DP and four-way assignment, and reader four-word lookup/multiply/add are separate costs. Original K2/V2 (16 B smaller), moment, delay2, K2/V4 are already owned controls; no new buffer control.

Only one candidate is paid: all 12 layer-1 contextual train/validation CPU windows at each of 256 queries, and eight retained original layer-0 held t128/t256 queries. Evaluation is full Q→K2 attention→V2 decoded levels→complete original O against the respective original teacher. Source-weighted diagonal fitting objective is distinct from paid finite full-O error (cross-coordinate covariance and rounding can reverse it). This source study used no GPU, fresh Q capture or full forward. The separate [complete resident native study](../kivi-value-alphabet-native/README.md) now preserves the9.52% layer0 quality gain on actual device outputs, with16B extra explicit global data, but is1.144× slower at32 matched t128/t256 update/query/flush steps. This is not a contextual native or full-model result. Logs, tables, packed event/final images, query receipts and exact byte ledger are held here. Validation is previously inspected, not a new blind set.

`fit.py` checks original donor FP16 fields against the original BF16 V extrema before calibration. `produce.py` copies each original K event/field and flush chronology while paying four-way FP32 decoded-level comparisons. `read.py` independently checks all 232 K/V events/head/window, every original source field/digit, all 224 four-way V labels/head/window, every pre/post query prefix SHA and size, both retained images, final bytes, table and source/Q/teacher/O hashes, and the complete-O observer; it retains every query output SHA and FP64 SSE in the per-window results. Layer 0 reads original interner arrival events, original KIVI2 events and original retained Q/teacher/O snapshots; layer 1 reads the frozen contextual CPU source, **contextual original KIVI2 events**, and original contextual O. An early execution mistakenly used layer-0 donor fields against layer-1 source and produced invalid files; the independent source-to-field check exposed it. Those files were replaced by a corrected contextual-only refit/producer/reader before these results. No alternate alphabet was explored.

There are 224 V flushes and eight K chunk flushes per head per window; 128 four-way FP32 decode candidates and FP64 scalar comparisons are paid per V token. A straightforward producer evaluates 4×4 FP32 group-level products/adds and 128×4 FP64 scalar distances plus label packing per flushed token, over and above original extrema/field generation. The reader pays one static four-word level lookup and one FP32 multiply/add per quantized coordinate; K and recent BF16 paths are unchanged. Sorting, duplicate grouping and four DP rows are offline train calibration, not hidden in cache latency. Dynamic cache is 304,768 B peak and 249,856 B final for all eight heads, unchanged from original; 16 B per layer is shared static configuration (the original literal `{0,1,2,3}` requires no table), so one-sequence total is 304,784 B peak and 249,872 B final. The 16 B is *not* an extra per-sequence buffer or native timing claim. The CPU evaluation expands cache scratch and loads original O; they are not resident-cache savings. [`ledger.json`](ledger.json) hashes and sizes physical outputs separately from this storage model.
