# Exact shared-program frontier at bounded future-use width

The previous [shared-frontier example](../shared-frontier/README.md) has a Pareto image unsupported by every nonzero linear weighting. Consequently an opening rule for weighted objectives cannot enumerate the complete error/bytes/work frontier. Here an **exact separator decomposition** avoids enumerating all globally installed program sets when each model-specific code/table has a narrow span of regions where it can be used. It retains vector costs and installed identities only while future choices can still observe them. This is path-decomposition variable elimination applied to *paid executable artifacts*, not a new general algorithm for arbitrary long-range sharing.

## Rule and proof

Each region `i` has a finite menu of executable choices. A choice incurs a nonnegative vector `(response error, per-region serialized bytes, online work, additional prepared resident bytes)` and needs a set of installed assets; needs may contain several assets, e.g. one model-specific bank and one generic reader. Every asset `a` has one setup vector (compiled model-specific code, serialized dictionary, resident preparation) paid **once**, and is legal only at some declared region support. Let `first(a)` and `last(a)` be the earliest and latest legal region. Gaps inside the span are harmless: legality is still checked for each actual choice.

At region `i`, decide which assets with `first(a)=i` are installed and pay their setups. Select one legal choice whose required assets are installed. After finishing `i`, forget every asset with `last(a)=i`. For each retained crossing-asset bitset, keep **all nondominated four-vectors** and one witness per vector. The maximum number of simultaneously crossing spans in this ordering is `w`; there are at most `2^w` installation signatures at a cut, not `2^M` sets of all `M` assets. If at most `K` region choices and at most `F` labels per signature survive, transitions are bounded by `O(n 2^w K F)` apart from dominance work (the simple implementation uses quadratic pairwise pruning) and witness storage. This is output-sensitive, not a polynomial guarantee.

Why exact? Any concrete image has a unique set of *used* assets. Install each at its first legal position and follow its tile choices, so the DP includes its cost. Conversely every DP path is a feasible image, possibly with unused paid assets; deleting those only improves it. At a cut, a previously introduced asset usable by a future choice must have `last(a)` beyond the cut and therefore remains in the bitset. All other previous identities can be forgotten: future assets are selected afresh and future choice availability and setup bills are identical between histories with the same bitset. With independent-region additive error, bytes and work, a no-more-expensive vector remains no-more-expensive under the same future suffix. `Kelana/SharedProgramSeparator.lean` proves future multi-asset option eligibility from the crossing agreement and coordinatewise dominance under a common suffix. The Python implements the finite recurrence and checks small instances against an *independent assignment oracle* that unions actual used assets before charging them.

This rule is not valid merely because two partial images have equal observed outputs. Shared numeric table contents, future program legality, registers and consumers must be in the separator state. A complete-region nonlinear loss coupling choices on different tiles must carry sufficient consumer state instead of summing local squared errors. If the same code path is legal at every tile, its span is global and contributes a crossing bit; a large number of genuinely global choices defeats this reduction. Reordering independent regions to shorten spans can help, but this experiment keeps the declared order.

## A paid, falsifiable grammar

[`search.py`](search.py) builds `n` independent four-input regions cycling through target responses `A=(0,1,0,1)`, `C=(0,1,0,2)`, `L=(0,1,2,3)`. Distortion is the exact sum of squared response errors. Every region may choose the best fitted one-byte integer constant (one work unit), the best fitted two-byte integer affine map on `s,b∈[-3,3]` (two units), or an exact four-byte direct response table (two units). Their installed generic reader codes cost respectively 1, 2 and 2 bytes, once each for the whole image. The affine fit searches the entire stated grid rather than rounding a teacher coefficient. Direct tables are exact; a less accurate table with the same physical layout and work cannot improve this frontier.

Each adjacent pair `(j,j+1)` also permits one bank-specific program variant, whose four-byte response is the first region's table. It costs **four serialized bytes, four extra permanently resident prepared bytes**, and one selector byte plus two online units per tile that uses it. All banks share one three-byte reader code, charged once if used. A bank identity is genuinely local by the stipulated region/bank legality, even if another bank happens to store equal numeric entries; regions outside its pair cannot call it. Prepared bytes here are *dedicated per installed bank for image lifetime*, not a reusable peak scratch count. The search charges bank setup once and retains its installation decision until after its last legal region. This is a toy cost grammar, not measured machine-code size, native time, or evidence that trained models exhibit adjacent motifs.

For seven regions an independent oracle evaluates **50,000 complete menu assignments**, charges the union of actual assets and gives exactly the same nine frontier vectors as separator elimination. Its vector `(8,19,11,4)` uses a paid adjacent bank and survives alongside strong direct/affine/constant images. The 48-region run has 47 distinct adjacent-bank assets but still only six crossing identities: it does not enumerate their `2^47` subsets. [`results.json`](results.json) records vectors, a concrete witness, counts and timings. Time is Python orchestration on this host, not decoder latency. The long run's witnessed costs are independently replayed from the selected tile choices and *actual used* asset union.

## Limitation that matters before scaling

Small separator width does **not** imply a small full frontier. With no shared assets at all, tile `i` may choose either `(error,bytes)=(2^i,0)` or `(0,2^i)` at equal work and preparation. The `2^n` binary subset sums yield every vector `(k,2^n−1−k)` for `0≤k<2^n`; no two distinct vectors dominate each other. The Lean `binary_tradeoff_antichain` proves the pairwise non-dominance step for arbitrary total and bounded `k`. Thus any method explicitly outputting the complete frontier can require exponential space even at `w=0`. Bounded error/byte budgets, compact symbolic frontiers or query-specific certificates are separate routes, not consequences of path width. Unsupported points in the earlier study also forbid using only linear-weight supported labels as a shortcut.

Reproduce from the Kelana root:

```sh
python3 research/isa-quantization/shared-program-search/search.py
lake env lean Kelana/SharedProgramSeparator.lean
```

Both are CPU-only and complete well below one minute here. The scripts print compact JSON and check the seven-region oracle, final witness replay and Lean separator lemmas. This is an **exact frontier for the declared finite additive grammar** and a general sufficient separator rule; its small code/work numbers are assumed costs, not an ISA lowering. Real deployment needs measured code union, table residency, reader continuation and an actual incidence map before the width estimate means anything.
