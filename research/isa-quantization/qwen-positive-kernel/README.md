# A positive-feature prefix on the actual Qwen layer-0 GQA group

**A complete finite source consumer, not just a score-rank toy.** We fixed one generic 64-feature positive exponential map before measuring the actual layer-0 Qwen3-0.6B two-query-head / shared-K/V GQA group. The program replaces each key/value token cache with a single denominator/numerator prefix accumulator and reads both original Q heads into their original O columns. It computes no per-query attention matrix or stored Q/K vector in its **inference prefix state**. On all eight 256-token train windows and four inspected-held windows, however, this particular 64-feature map loses badly: held two-head post-O relative squared error **1.53503**, versus **.65695** for a paid nearby-size per-token affine Q6 K/V cache and **.92367** for a *smaller* Q4 K/V cache. Its head-0 held attention KL is **851.196**, versus Q6 **1.442** and Q4 **1.671**. Stabilization removes exponential overflow; the outcome is a poor approximation at this source geometry, not a failed unscaled implementation. No rank/seed sweep, fit, held selection, GPU or new capture occurred. This is no exclusion of source-centered, structured, jointly changed-value or other approximate complete programs.

## Source, program and online state

Source checkpoint: Qwen3-0.6B BF16 revision `c1899de289a04d12100db370d81485cdf75e47ca`, SHA256 `f47f71177f32bcd101b7573ec9171e6a57f4f4d31148d38e382306f42996874b`. The [pinned producer fixture](../quip-full-row-slab/README.md) SHA256 `389e5f8c17ac151070b12094849f450130ab9c1684f51b402d59fd4e7ac2008f` provides 2,048 train and 1,024 inspected-held original 1,024-input positions (8+4 original 256-token causal windows). Its first 128 Q weight rows equal the checkpoint elementwise; both actual 128-dimensional Q heads are read from the checkpoint here. K/V are their original shared 128×1,024 BF16 weight heads; O is the original 1,024×256 block for the two heads. Q/K gamma and the unchanged BF16 projection, FP32 RMSNorm, BF16 roundings and position-dependent RoPE match the [canonical consumer](../quip-complete-head-observer/README.md). The **complete original shared affected-group static state is 1,573,376 bytes** for two Q heads, K, V, O and Q/K norm gamma, the same in every arm. No Q, K, V or O weights are compressed or refit in this study. Teacher is the original BF16-rounded exact-score causal attention of both heads, not full-model NLL or a continued generation rollout.

Let `u_i=RoPE(Qnorm(q_i))/128^(1/4)`, `v_j=RoPE(Knorm(k_j))/128^(1/4)` and `a_j` the original BF16-rounded V vector. The exact teacher score is `u_i·v_j`; each `v_j` is known at its **actual causal insertion time**. The frozen generic table [`gaussian-features-64x128-f16.bin`](gaussian-features-64x128-f16.bin), SHA256 `c79b3d345a0bfc6a1b2e4a6e8f04246e5b7750e885ae17f3eb36ad66d53d86f5`, has 64×128 FP16 Gaussian entries generated with seed `20260924`, and costs **16,384 bytes once per reader pool** (charged once to this standalone group). For a feature row `ω_f`, set `φ_f(z)=exp(ω_f·z−||z||²/2)>0`. A continuous standard-Gaussian expectation of `φ_f(u)φ_f(v)` is `exp(u·v)`; the actual committed finite FP16 table makes **no unbiasedness guarantee**. Both Q heads use the same table, key features and value moments.

The online state for each feature `f` is a denominator `Z_f`, a 128-value numerator `N_f`, and a log scale `M_f`. At insertion with key `v_j`, compute `l_f=ω_f·v_j−||v_j||²/2`, `M'_f=max(M_f,l_f)`, `c_f=exp(M_f−M'_f)`, `b_f=exp(l_f−M'_f)`, then `Z'_f=c_f Z_f+b_f`, `N'_f=c_f N_f+b_f a_j`. For query `u`, compute `t_f=ω_f·u−||u||²/2+M_f`; subtract the common maximum `max_f t_f`, and return `Σ_f exp(t_f−max t) N_f / Σ_f exp(t_f−max t) Z_f`. Every term is positive in the denominator. This computes the finite kernel's normalized prefix response without retaining individual K/V. Dynamic `M_f` is **necessary state and update work**, not a free preprocessing trick; the same global query maximum cancels only within its one query. `measure.py` actually uses FP32 `Z,N,M` and checks its streaming value against a separately materialized dense kernel probability reader (max disagreement across windows is in the receipts, roughly `1e−5`). The dense scores/keys are **diagnostic transient acceptance arrays, not inference state**. RoPE's absolute-position dependence is paid when preparing each new key; the feature kernel is stationary on these *already rotated* coordinates, not on raw token IDs or unrotated keys.

At length256 the moment state costs `64×128×4=32,768 B` numerator, `64×4=256 B` denominator and `64×4=256 B` per-feature log scales: **33,280 B live**. The generic table plus standalone live state is **49,664 B** across distinct static/live axes. A common 2-byte position counter (256 positions) and original Q/K/V/O static weights appear equally in every arm and are not silently subtracted. The table is 16,384 B of read-only generic data resident if the reader uses it; compiled reader instructions, exponent code and transient registers are *not measured*, so 49,664 B is not a device-footprint total or an effective-BPW claim. At each insertion: 64×128 key feature dot products, **128 exponentials** (64 current-key contributions and 64 log-scale decay factors), 64×128 value-moment multiply/add updates, plus 64 per-feature scale adjustments of 128 numerators. At each query: 64×128 feature dot products and 64 exponentials **per Q head**, two 64×128 numerator reductions, denominators and O projections. Thus per token at two heads, roughly 24,576 feature-table multiply/add terms, **256 exponentials**, 8,192 numerator update terms and 16,384 numerator readout terms, plus rescale, normalization/RoPE and shared source projections/O. No native ISA timing or complete latency claim follows from counts.

## Paid strong conventional K/V controls at the same boundary

The conventional group keeps source Q heads unchanged and caches each token's actual **post-Knorm/RoPE 128-coordinate K** and original BF16-projected 128-coordinate V. After the same source projection/norm/RoPE, [`cache_fit.py`](cache_fit.py) independently selects each token/vector's affine unsigned Q4 or Q6 grid by **minimum vector MSE** over three declared clipping starts (`0,.01,.04` quantiles) and four fixed-code scale/origin least-squares alternations, then FP16-rounds fields, reassigns codes and selects the lowest-MSE grid. This is a capable *per-token, per-128-coordinate-vector source-response-blind scalar cache preparation*, **not per-channel K quantization**, GPTQ, a SOTA K/V cache or an optimum over attention error. An asymmetric per-channel K control may be substantially stronger and is not evaluated here. It is an ordinary online per-token preparation: no future context, held calibration or cross-window state enters the codes. [`cache_replay.py`](cache_replay.py) separately parses **actual serialized bytes** and feeds decoded K/V through original causal Q/K score, softmax, V and O; it imports no fitter packing/quantization routines. Each panel window has two tracked paid cache images and SHA manifests. The reader checks every byte span and field, the fixture SHA and model Q equality. One 256-token standalone group costs:

| Dynamic cache | Key and V codes | FP16 origin/step (512 vectors) | Total live serialized state |
| --- | ---: | ---: | ---: |
| BF16 raw K+V exact-score reference (K norm/RoPE on read) | 131,072 B | 0 B | 131,072 B |
| FP32 prepared rotary K + BF16 V exact-score reference | 196,608 B | 0 B | 196,608 B |
| per-token affine Q6 | 49,152 B | 2,048 B | **51,200 B** |
| per-token affine Q4 | 32,768 B | 2,048 B | **34,816 B** |
| positive feature rank64 | 32,768 B moment numerator | 512 B denominator/log scales | **33,280 B**, plus 16,384 B shared table |

The Q6 cache is **1,536 B larger** than feature state plus the once-billed generic table; the Q4 cache is **14,848 B smaller**. Original static weights, query preparation and O apply to all; Q4/Q6 pay their 3-start/4-alternation code preparation and scale fields, plus coefficient unpack/dequantization for every query. BF16 raw K/V stores two 128-coordinate BF16 projections per token and must perform K norm/RoPE from that cache for a query; alternatively a prepared FP32 rotary-K/BF16-V cache consumes 196,608 B at 256 positions. Comparing only 33,280 B to 51,200 B would improperly omit the feature table. Comparing only state bytes ignores feature exponentials and cache reads; there is no native execution result here.

## Complete observed behavior

Head KL averages over all query positions. O relative squared error sums squared output numerators/teacher denominators across all windows; the **two-head GQA** contribution includes both original O column blocks. Original BF16 K/V with source Q is the exact replay teacher and has zero relative error by construction. For context, the separately frozen [50,320-byte scalar-H Q image](../quip-complete-head-observer/README.md) with **unchanged BF16 K/V** scored held GQA post-O `.00224412`, and 50,322-byte QuIP root-H scored `.00285930`; those are **Q-head representation edits on a different static image budget**, not cache-size-matched controls. The present K/V replacements change both heads and are compared at their paid cache rates.

No method monotonically orders every per-head post-O metric: Q4 has lower head0 O error than Q6, while Q6 wins pair O and both KLs. There is no quality/size dominance claim between Q4 and Q6, but **both paid scalar caches beat the frozen feature program on pair O and attention KL**, and Q4 uses materially less total counted table+state. The feature reader additionally performs many exponentials and moment rescalings; no compensating measured work advantage is available. The failure occurs on train as well as inspected held, so it is not ascribed to held selection or train→held transfer.

### Why this particular closure fails

**This variance is not invariant under an exact score-row gauge.** Replacing every stored key `v_j` by `v_j−c` shifts all scores for one query by the same `−u·c`, so exact softmax probabilities do not change, while the positive Gaussian estimator's variance exponent becomes `||u+v_j−c||²`. Source-informed centering can therefore change this conclusion, and is not fitted or tested in this frozen arm. The randomized positive-product estimator has ideal iid continuous-Gaussian per-score relative variance `(exp(||u+v||²)−1)/64` at rank64, before finite-FP16-table truncation. This is a property of **this uncentered estimator**, not a lower bound on every positive feature map or on normalized output error (numerator/denominator may correlate). [`geometry.py`](geometry.py) evaluates only the first fixed train and held source windows after the real producer, normalization and RoPE. Scaled key squared norm ranges **893–12,238** on first train window (median **2,304**); query squared norms are **17–55** for head0 and **30–162** for head1. Even the minimum causal `||u+v||²` is **912** (head0) or **930** (head1), so the iid rank64 relative-variance exponent after dividing by 64 is at least **908** or **925**. The teacher score itself only ranges about `−9.3..12` for head0, but the *sampling estimator's* huge key norm makes the finite table's rare-event representation untenable. The first held window has the same geometry (minimum exponent ~989/1011). Actual stored-table program's `log φ(key)` ranges to about `−7982` on train and `−9548` on held. Per-feature log-max rescaling computes finite outputs and dense/prefix agreement despite that range, so underflow is **not** used as the failure explanation. The actual poor response and KL are directly measured. A source-centered feature design, alternative positive kernel, changed V/O or different source-law approximation remains an open research route; this experiment neither evaluates nor excludes it.

This whole-source result complements [attention-prefix-state](../attention-prefix-state/README.md): the algebraic numerator/denominator quotient is small when a good positive map exists, but the paid feature geometry and source error decide whether one exists cheaply here. It also respects [live-value-transfer](../live-value-transfer/README.md): K/V and odds might be co-designed, whereas this frozen arm changes only the attention kernel representation and retains original values and O.

## Reproduction

```sh
cd /path/to/workspace/projects/kelana
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
PY=/path/to/workspace/data/fish-s2-pro/venv/bin/python
$PY research/isa-quantization/qwen-positive-kernel/table.py
for i in 0 1 2 3 4 5 6 7; do
  $PY research/isa-quantization/qwen-positive-kernel/measure.py train "$i"
  $PY research/isa-quantization/qwen-positive-kernel/cache_fit.py train "$i"
  $PY research/isa-quantization/qwen-positive-kernel/cache_replay.py train "$i"
done
for i in 0 1 2 3; do
  $PY research/isa-quantization/qwen-positive-kernel/measure.py held "$i"
  $PY research/isa-quantization/qwen-positive-kernel/cache_fit.py held "$i"
  $PY research/isa-quantization/qwen-positive-kernel/cache_replay.py held "$i"
done
$PY research/isa-quantization/qwen-positive-kernel/geometry.py
$PY research/isa-quantization/qwen-positive-kernel/aggregate.py
```

**Each individual command**, not the entire loop, takes less than a minute on existing CPU1. No GPU, new capture or external model inference is needed. The table is regenerated byte-for-byte and checked by SHA in the feature reader; all 24 dynamic cache images are checked by SHA through per-window manifests. [`results.json`](results.json), [`geometry.json`](geometry.json) and twelve feature / twelve control window receipts give the per-window provenance and counts. Generic reader code size, native registers, resident feature table placement, long-context overflow policy beyond these windows and full-model task quality are not measured; the reported state ledger is scoped to the actual 256-token GQA consumer.
