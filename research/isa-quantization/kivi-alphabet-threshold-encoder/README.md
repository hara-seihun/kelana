## Frozen arithmetic

`threshold_core.hpp` is compiled by both the CPU parity encoder and HIP. Per group it computes four **actual** decoded levels using separately rounded FP32 `product=b*table[c]` then `level=a+product`, in the original field's decoded FP16 `a,b`. It computes three adjacent sums `double(level[c])+double(level[c+1])` once/group, then classifies `2.0*double(source_bf16)` against those sums with `<=`: equality chooses the lower level. The first index of each repeated actual level is precomputed for the three possible selected upper labels; all-equal and partial-duplicate groups return the smallest matching label. Original mode 0 retains its conventional quantizer. This is the one fixed expression, not an outcome-selected alternate decoder or a different table.

The formal exact-rational strict-level argument is [`Kelana/AlphabetThresholdDecision.lean`](../../../Kelana/AlphabetThresholdDecision.lean); the actual FP32 decode and FP64 midpoint operations are separately audited here. Binary32 level pairs do **not** have an arbitrary-input guarantee that their sum is exact in binary64. `encoder.cpp` converts actual source and level words into exact signed integer times power-of-two values, compares all three boundaries exactly, records rounded-sum and changed-decision counts, and checks least-squared-error and the frozen candidate event bytes independently. Synthetic all-equal and partial-duplicate midpoint/tie cases pass; the 16 frozen windows themselves contain no repeated actual levels. The smallest **nonzero exact** observed margin `|2x-(li+li+1)|` is `5/33554432 ≈ 1.49011612e−7`, from layer-1 train-4. There are zero exact midpoint ties, zero rounded adjacent sums, zero decision disagreements and zero packed-byte mismatches on the observed domain. This is a source-word observation, not a theorem of floating-point exactness for all future inputs.

## Complete frozen-source parity

The source owner is `../kivi-value-alphabet`: four layer-0 held and eight layer-1 contextual train plus four layer-1 contextual validation candidate windows. `parity.py` reads independently saved BF16 V source (`kivi-value-intern` arrivals for layer 0; hashed contextual source NPZ for layer 1), original donor event fields/K, both original 16-B layer tables and the candidate event logs. No new source generation, scoring or teacher output occurs. The CPU parity path takes the original accepted FP16 fields as inputs rather than regenerating extrema/fields; it independently checks those field bytes equal the candidate's, and encodes fresh digits from the saved BF16 source. Unchanged HIP field generation is inherited byte-for-byte from the accepted source, not newly device-accepted here. The CPU encoder checks **28,672 48-B V records**, **3,670,016 coordinate codes** over the 16 windows, and audits **11,010,048 exact adjacent threshold comparisons**. It checks every packed code byte against all 128 frozen candidate event streams and retains window-by-window source/table/event hashes, exact margin and rounding counters in `*-parity.json`. All 16 pass. Only four layer-0 held windows have completed candidate logs; no absent layer-0 train candidate is invented. `summarize.py` pins all receipts and resources in [`results.json`](results.json).
