# Independent KIVI2 codes with a query-visible V-error moment

**Result:** With every original independent K2/V2 code, FP16 field, BF16 recent word, query and O unchanged, a 4,096-B FP32 cumulative V-error moment reduces pooled original-teacher output SSE on the declared CPU observers from **209.016698 to 204.115581** for all 2,048 layer-1 train queries and **107.923584 to 104.977831** for all 1,024 layer-1 validation queries. It also reduces the eight separately retained layer-0 original-Q/teacher/O states from **0.832658 to 0.608755**. It beats original K2/V2 on 1,522/2,048 train, 817/1,024 validation, and 7/8 held queries. It does **not** beat higher-rate K2/V4 in pooled SSE, and the layer-0 temporal-feedback control beats this moment arm in pooled SSE. This is a complete state/reader comparison, not a native timing, model rollout, or pointwise guarantee. Validation had previously been inspected.

The parent [moment identity and positive-weight reversal](../kivi-value-error-feedback/MOMENT.md), formalized in `Kelana/ValueErrorMoment.lean`, fixes the exact-arithmetic interpretation and its limitation. Here the concrete FP32 implementation follows the single arithmetic/observer contract frozen before any scores. No fitted gain, center, coefficient, group-size, code precision, changed route or selected query subset is introduced.

## State transition and paid read

At every query the V cache has `m=max(0,t−33)` already-quantized original V tokens. At the **after-query** V33 flush, take the oldest arriving BF16 source vector, decode its **unchanged** original independent V2 G32/R32 record from the actual FP16 fields and packed digits by FP32 field-step multiplication followed by separate FP32 origin addition, form FP32 `source−decode`, and add it in FP32 to the persistent 128-coordinate moment for that KV head, initially zero. The original K events, V records, recent BF16 arrays, and flush order are not changed. All eight KV heads retain 4,096 B of FP32 moments, without a per-token residual bank or a separate index.

At the preflush query, use the original K2 FP32 logits/softmax and ordinary mixed decoded V. Each of 16 Q heads reduces its *own actual* softmax probabilities at the first `m` aged positions in fixed chronological order using FP32 additions. For `m>0` it divides this mass `P` by FP32(`m`), multiplies the corresponding KV head's moment coordinatewise in FP32, adds that vector in FP32 to ordinary mixed V, then applies the original full O map. For `m=0` the correction is zero. The two Q heads sharing a KV head use the same stored moment but distinct aged probability masses. Finite arithmetic defects, source BF16/K errors and O mixing are part of the output, not suppressed by the ideal mean-error identity.

Per sequence the logical peak is **308,864 B**, final **253,952 B**: unchanged original cache 304,768/249,856 B plus 4,096 B moment; **768 B more** than the unchanged-code V34delay2 control (308,096/253,184 B). The higher-rate K2/V4 peak is 361,856 B. Per KV head per V flush there are **512 B moment read +512 B moment write =1,024 B state traffic**, 128 FP32 stored-field decode multiplications and separate additions, 128 subtractions and 128 accumulator additions. The unchanged original quantizer's 128 digits/group extrema are not charged as a new operation. The reader adds the chronological aged-mass reductions (up to `16×m` FP32 probability additions per full query), 16 scalar FP32 divisions, 2,048 FP32 moment multiplications and 2,048 FP32 mixed-value additions, plus a shared **4,096 B moment read** if each KV vector is loaded once for its paired Q heads. The straightforward flush carries a 512-B decoded vector and a 512-B FP32 error vector (reusable), in addition to original source/digit buffers. The reader carries up to 16×256 FP32 probabilities (16,384 B), a 16×128 FP32 mixed vector (8,192 B), and decoded K/V expansion of up to 2,097,152 B in this CPU replay. This scratch is neither free nor persistent compressed cache state. This is an operation/byte ledger, not a native speed claim.

## Provenance, replay and reproduction

The 12 immutable contextual source NPZs, original K2/V2 event logs/cache images and baseline receipts belong to [`contextual-value-feedback`](../contextual-value-feedback/README.md). Its teacher-forced original layer-0 residual → CPU layer-1 Q/K/V/teacher boundary, original BF16 O and source-only BF16 K sensitivity are unchanged. The common source-only BF16-K/reduction-boundary sensitivity from that owner is 0.038507522 SSE train and 0.018142388 validation; it is not subtracted from any arm's SSE or assigned to this moment. All arms share the same saved teacher, Q, original K2 encoder and unchanged BF16 full O weights; thus source bias, K quantization, K-weighted probabilities, O mixing and their cross terms remain in the complete output errors. The layer-0 arrival events and original paid event streams belong to [`kivi-value-intern`](../kivi-value-intern/README.md), [`kivi-two-bit-causal`](../kivi-two-bit-causal/README.md), and the retained Q/teacher/O to [`kivi-two-bit-dot-native`](../kivi-two-bit-dot-native/README.md). Temporal-feedback/delay2 receipts come from [`kivi-value-error-feedback`](../kivi-value-error-feedback/README.md), higher-rate controls from [`kivi-kv-rate-exchange`](../kivi-kv-rate-exchange/README.md). This work neither regenerates missing Q nor performs a source/model forward or GPU calculation. The original code's state bytes are reused by reference, not recopied as a new arm.

[`build.py`](build.py) reads only the paid original donor events and source V, emits **actual 512-B FP32 moment images** per KV head at t128/t256 preflush and after t256 final, and stores SHA256 for every before/after moment across all 256 phases/head/window. Each manifest pins source/donor SHA, each head's unchanged event-log SHA, and peak/final paid state. [`replay.py`](replay.py) independently reconstructs every donor K/V cache byte and recent BF16 word, checks original K source quantization and V field/digit identity, source V flush chronology, independent scalar FP32 stored-field decode/error/accumulation and every before/after moment SHA, exported moment bytes, before/after donor cache SHA, retained original image and final image. It separately computes all 3,080 complete CPU Q→softmax→mixedV→original O outputs using actual prequery moment images and pins each output SHA; every contextual ordinary output matches its existing immutable original SHA. [`aggregate.py`](aggregate.py) links all result and comparator receipt hashes and checks the immutable held exchange controls. Exported moments are reader state; event logs, source files, receipt JSON and CPU decoded K/V scratch are not resident-cache savings.

From the repository root, each individual command completes under 55 seconds with one CPU thread (run `build` then `replay` for each `train 0…7`, `validation 0…3`, `held 0…3`; run `aggregate` last):

```sh
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
PY=/path/to/workspace/data/fish-s2-pro/venv/bin/python
$PY research/isa-quantization/kivi-value-error-moment/build.py train 0
$PY research/isa-quantization/kivi-value-error-moment/replay.py train 0
$PY research/isa-quantization/kivi-value-error-moment/aggregate.py
```
