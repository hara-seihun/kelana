# Whole-layer Qwen GQA: global-cluster SKVQ source transfer versus full KIVI

**Result.** At the *complete* Qwen3-0.6B layer0, all **16 query heads, 8 shared KV heads, 128 coordinates/head, original 1024×2048 O** and all 256 causal positions, one predeclared global-channel SKVQ source transfer (2-bit K/V, nominal G32, W64, sink5, α=.92) gives inspected-held **0.003048783 complete-O relative squared error**, versus **0.0000630017** for the fixed original KIVI 4-bit G32/R32 at the *same full-layer observer*. Its causal high-water is **439,934 B** including all model descriptors versus KIVI **419,200 B**; final resident **436,639 B** versus **372,736 B**. Train is 0.002922229 versus 0.000049574. This negative result is a **single local Qwen CPU/teacher-forced source comparison**, not a ranking of the published methods on their model/task/throughput benchmarks. No settings or clustering changed after any output. The source-only head-local study in [`../skvq-causal-correspondence/`](../skvq-causal-correspondence/) is *not* the named method's correct global grouping boundary; it remains a separately labeled local experiment and is not substituted for this complete one.

## Official source correspondence and explicit Qwen transfer

Duanmu et al., [SKVQ (COLM 2024), §3](https://arxiv.org/html/2405.06219v3) and [official code `cat538/SKVQ@fdfc7ec315c16293f68dd771850b47f5199787fc`](https://github.com/cat538/SKVQ/tree/fdfc7ec315c16293f68dd771850b47f5199787fc) are the pinned source. [`calibration.py:get_reorder_indices`](https://github.com/cat538/SKVQ/blob/fdfc7ec315c16293f68dd771850b47f5199787fc/calibration.py#L241) fits separate 2D `(min,max)` KMeans across **the whole layer's KV-channel dimension**, with nominal group32 ⇒ **32 clusters per 1024 K and 1024 V coordinates**. It sorts channel IDs by labels and retains *actual unequal cluster boundaries*; this Qwen study fits on the existing **2,048 train-only source rows** with official `n_init=10` and fixed `random_state=0` (official unspecified seed), never held. Official training collects pre-norm projection K for Llama/Mistral; Qwen3 has **K RMSNorm before RoPE**, so this source transfer calibrates the actual **BF16-projected, post-Knorm+gamma, pre-RoPE** K used for quantization. V is BF16 projected. This architecture/calibration transfer is named, not silently passed off as upstream Qwen support. No model download or new capture.

Crucial upstream wrapper mismatch: [`ModelKVCacheManager.create`](https://github.com/cat538/SKVQ/blob/fdfc7ec315c16293f68dd771850b47f5199787fc/KVcache_manager.py#L334) infers `hidden=cfg.num_key_value_heads*cfg.hidden_size//cfg.num_attention_heads`, i.e. **512** for Qwen (`8×1024//16`), but Qwen's independent `head_dim=128` and actual K/V projection width are **1024**. The unchanged Llama wrapper would fail its width assertion; we explicitly use the actual checkpoint projection shapes and config `head_dim=128`. Source Q/K/V/O BF16 static weights **12,582,912 B** plus **512 B common Q/K gamma =12,583,424 B** are identical in both paid cache arms. The RoPE inverse-frequency/config belongs to the same original model; it is not a hidden additional learned table.

The selected configuration was sent before fitting: **K/V 2/2 bit**, nominal **G32**, **recent64**, **uncompressed first five sink**, **pre-RoPE cache K**, uniform **α=.92** from official [`eval_needle.py` parser](https://github.com/cat538/SKVQ/blob/fdfc7ec315c16293f68dd771850b47f5199787fc/eval_needle.py#L558), FP16 group origin/step, no FP8/smooth/eviction. Its bit/window/group choices are supported by upstream, but not the same config as its README full-model example G128/W128; our CPU mathematical port is **not** an upstream-native deployment or a claim to reproduce its paper evaluation. [`KVcache_manager.py:SlidingKVCacheManager.forward`](https://github.com/cat538/SKVQ/blob/fdfc7ec315c16293f68dd771850b47f5199787fc/KVcache_manager.py#L158) ages one token after the first5+last64, **before its current query**; old K/V are *both* per-token grouped, not KIVI's per-channel K slabs. [`kernels/csrc/quant.cuh`](https://github.com/cat538/SKVQ/blob/fdfc7ec315c16293f68dd771850b47f5199787fc/kernels/csrc/quant.cuh#L75) clips both half extrema by .92, clamps half scale to1e−5, rounds/clamps to0…3, packs four 2-bit codes high-significance-first **separately within every cluster** (including padded last byte), and stores half origin/scale. [`replay.py`](replay.py) independently reconstructs this field arithmetic, code packing and inverse permutation; the original official evaluation defaults to fake quantization, whereas these are paid packed images. The official `reorder_weight` helper is not called in its evaluation; no static folded replacement weights/permutation have been assumed free.

The global KMeans actually yields code **K275 B, V270 B** per old token, plus K/V **32×two FP16 fields each =256 B**, total **801 B per aged token**. Its exact [`global-descriptors.bin`](global-descriptors.bin) (SHA256 `ab3aa60bafda9ad741a3dc6f4e544e6d3af08bbf600e861fb70a34d76ef6ad26`) contains **two 1024×int16 permutations (4096 B)** and **two 33×int16 cluster boundaries (132 B)**: **4,228 B counted once**, not amortized away. [`global-descriptors.json`](global-descriptors.json) pins all indices/widths/training features and exact source policy. **17 K and 26 V clusters cross KV-head boundaries**; a one-head table cannot be encoded without other heads under this global rule. Although nominal G32, actual cluster widths/padded code lengths are the source result, not forced equal32.

Counters/position bookkeeping are common and outside both displayed cache sizes (count them for a complete process); event logs and source receipts are **not simultaneously live cache state**. The current CPU readers expand all decoded FP32 K/V at prefix256 (up to **2,097,152 B transient arrays**), materialize logits/mix, and compute RoPE sine/cosine; they are **not** 440 KB complete CPU processes. Pre-RoPE SKVQ decoding re-rotates every older decoded key at its original position, touching `8×128×Σ(t=1…256)t=33,685,504` K coordinate rotations per window in the literal reader, versus once per inserted key for KIVI's post-RoPE storage. A reusable BF16 256×128 cosine+sine grid would cost **131,072 B live scratch** if retained, shared over KV heads; computing it on demand trades memory for transcendental work. This work difference prohibits a speed claim based on bytes/error alone. No native SIMD/ISA reduction, GPU or model deployment is claimed.

[`source.py`](source.py) independently projects **full** Q16/K8/V8, uses the canonical BF16 normalization/gamma and position-RoPE, all 256×16×256 causal logits/softmax, original V and full O. For the first shared KV group, its Q/K/V/O/teacher log-probability are **exactly identical** to the original KIVI producer, confirming the group mapping. The Qwen transfer stores post-Knorm/pre-RoPE **BF16** recent K rather than the official Llama FP16; original teacher retains the FP32 gamma product. Re-RoPE and full uncompressed attention/O after that cast differ by only **1.04018e−6 train /1.06956e−6 held** complete-O relative squared. Thus source round-trip drift is reported separately from low-bit error, not hidden.

[`prepare.py`](prepare.py) emits and pins one global descriptor, never held-derived. [`build.py`](build.py) emits a paid serialized final full-layer SKVQ image per window, every before/after-aging SHA/size, selected boundary byte images, and a timestamped causal K/V flush-event log. [`replay.py`](replay.py) independently reads the **actual global paid descriptor and binary image**, verifies each available-token 2-bit code/FP16 field and all prefix hashes, applies pre-RoPE after decoding, and recomputes all16 Q heads' complete V/O. Its uncompressed source is separately compared with the unchanged teacher. For matched KIVI, [`kivi_build.py`](kivi_build.py) reuses the original immutable group0 KIVI event log/final image and emits only the **seven missing KV groups** using the unchanged 4-bit quantizer; [`kivi_replay.py`](kivi_replay.py) independently consumes all eight groups at their original *after-query* flush chronology and checks emitted codes/fields against available source. It applies the original complete16-head O, **not a sum of separately computed squared errors**. [`aggregate.py`](aggregate.py) insists on all 8 train +4 inspected-held windows, original group0 donor hash, all other images/events/descriptors, equal complete-O denominators and actual numerator/denominator aggregation.
