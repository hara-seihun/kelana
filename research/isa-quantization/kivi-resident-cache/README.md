# A single device-resident KIVI2 append/query/flush program

**Completed scoped device-resident acceptance and timing, September 25, 2026.** Both programs pass all 4,096 device-state phases and 16 complete-output guards on four held arrival traces. The dictionary saves **24,768 B of explicit global buffers**, but is slower at all eight measured causal steps: median matched-state event ratio **5.100×**, with **11,620 B** more device code and **2,056 B/CTA** more query LDS. This is a bounded correctness/global-buffer result and a negative latency result, not a better serving frontier.

The pinned experiment is exact full-eight-KV-head value-record sharing under one causal serving lifetime, compared with an independently resident conventional KIVI2 append/query/flush control. Both receive only the currently arriving recorded BF16 K/V (4,096 B) and original normalized/rotated Q (8,192 B) as chronological inputs. Both use the same original BF16 1024×2048 O image, K2/V2 G32/R32 quantizer, packed fields/codes, BF16 recent records, 16-Q/8-KV heads and complete 1024-coordinate output. The new dictionary is not a new quantizer, fit or program search. No conventional host shadow, expanded GPU K/V, full-cache H2D upload or future event is a serving input. Frozen original source receipts live in [`../kivi-two-bit-causal/`](../kivi-two-bit-causal/README.md), the independent first-use interner in [`../kivi-value-intern/`](../kivi-value-intern/README.md), and the separate CPU native-maintenance witness in [`../kivi-value-intern-maintenance/`](../kivi-value-intern-maintenance/README.md).

## Frozen layout and capacity

The candidate device allocation is one **266,240-B** contiguous dictionary arena. Its five-byte header (`u16 t, phase, quant-unique, recent-unique`) precedes eight head-major original K chunk/recent runs; then position-major 384-B full-eight-head quantized V records, u8 positional references, 2,048-B full-eight-head BF16 recent V records and u8 references. It uses first-use order and reclaims unreachable recent records after V33 flush. There is no heap allocator, freelist, application page table, hash table or extra dictionary pointer array. The arena's largest used original panel prefix is **263,429 B**; **2,811 B** remain unfilled in the fixed arena at that prefix. The finite observed panel fits; worst-case unique values in an arbitrary 256-step context need not fit this allocation. A capacity violation fails, not reallocates. The candidate owns an additional **20,480-B** transition scratch allocation: 12,288 B eight K chunks, 2,048 B swap, 4,096 B quantization codes, 512 B quantization FP16 fields, 128 B float values, and 1,408 B of padded unused capacity. Both dictionary append and flush are one-lane serial GPU kernels; this is a real cost, not an assumed parallel maintenance speedup.

The independent control owns eight **38,096-B** per-head fixed slabs (304,768 B total) with the original `[quantized K][quantized V][recent K][recent V]` packed layout. The head address array is an additional **64 B**. It needs **6,656 B** mutation scratch: 1,536-B K chunk / V record staging, 4,096-B codes, 512-B fields, 128-B float values and 384-B padding. It quantizes K32 and V33 directly from its stored BF16 recent bytes, rather than receiving free offline donor quantized events. It also uses one-lane serial append/flush kernels. These are independently implemented, not a dictionary expanded into the original reader.

| Device buffer category | Dictionary B | Conventional B |
| --- | ---: | ---: |
| Persistent mutable cache allocation | 266,240 | 304,768 |
| Mutation scratch | 20,480 | 6,656 |
| Head pointers | 0 | 64 |
| Shared immutable O (paid once per active program) | 4,194,304 | 4,194,304 |
| Arriving K/V input buffer | 4,096 | 4,096 |
| Current Q input buffer | 8,192 | 8,192 |
| Query O partial output | 32,768 | 32,768 |
| Final output | 4,096 | 4,096 |

| **Explicit device global allocations** | **4,530,180** | **4,554,948** |

This global-buffer advantage is **24,768 B**, before runtime/driver allocator rounding, host source arrays and model producer weights. All control and candidate buffers are paid even if a shared harness sequentially allocates one arm at a time. `compile-receipt.json` pins source hashes and gfx1151 per-kernel code size/resources. Candidate body bytes: dictionary append 6,060, flush 33,128, frozen grouped query 15,852, O finish 372 = **55,412 B** across four descriptors (4×64 B). Control: append 7,336, flush 23,260, original conventional query 12,824, O finish 372 = **43,792 B** across four descriptors. The candidate has **11,620 B** more device body, before descriptors shared between instances or host/runtime code. The grouped query uses **7,688 B LDS per CTA**, the conventional query **5,632 B**; eight simultaneous head CTAs require 61,504 versus 45,056 B *distributed on-chip LDS*, not an additional global-memory allocation. Both compiled query arms have zero private scratch. These independent resource categories do not produce a single scalar ordering without a chosen code-sharing/concurrency model. Shared O and source/model work do not vanish; per-cache marginal global buffers are candidate 335,876 B including mutation, arrival, Q, partial, final, error, versus control 360,644 B.

## Transition, frozen queries and acceptance

At each t=1…256 the host sends exactly one recorded arriving BF16 K/V; device append mutates the resident cache, the already-retained original Q is sent and complete query computed **only** at t128/t256 in each of four held windows, then scheduled K32/V33 quantization/flush mutates the *same* resident cache from stored BF16 recent K/V. Queries are read-only. Skipping unknown-Q queries at other t does not alter this fixed-arrival state trace, but it is **not** complete 256-step output acceptance or closed-loop model generation. Only these eight original Q/teacher/CPU output snapshots are retained in [`../kivi-two-bit-dot-native/`](../kivi-two-bit-dot-native/README.md); `source.arrays` is not called. The immutable fixture SHA256 is `389e5f8c17ac151070b12094849f450130ab9c1684f51b402d59fd4e7ac2008f` and original O BF16 SHA256 is `803995a9d5abb24c72d3ddabd50f4e656fc5eff26efaf3b626f175fc706ab499`; per-window arrivals, K/V flush events, Q, teacher, original packed images, compiler source and emitted kernel resource receipts are hash-pinned in the linked manifests and local `capacity.json`/`compile-receipt.json`. Original eight train/four held arrival streams are immutable in `../kivi-value-intern/*-events.bin` and original donor events/phase hashes are retained in `../kivi-two-bit-causal/`. The CPU-only [`reason.py`](reason.py) checks every stream hash/chronology, every original reference size, the 266,240-B observed capacity bound and retained eight Q/teacher shapes. Its [`capacity.json`](capacity.json) is the frozen panel receipt.

An acceptance trace starts *empty* for each arm and window, executes all 256 resident appends and flushes, captures pre/post device state to a host-owned audit file and computes all eight available complete O outputs. [`audit.py`](audit.py) independently reconstructs original logical K/V from immutable arrivals and per-head flush events; each original per-head prefix SHA, dictionary parsed/decode bytes, canonical first-use uniqueness/order and independently retained interner phase SHA are checked. Conventional bytes are compared directly against the independently reconstructed per-head packed image. The final O is compared to the retained original independent conventional CPU output (max coordinate error and relative L2 ≤0.005) before any latency is accepted; source teacher provides unchanged original KIVI2 quality, not a new source/model evaluation. Numerical and exact-byte failures are retained as failures, never fitted away.

After **all four held-window acceptance/audit invocations** pass, a fresh trace starts empty for every window/arm; it does not reuse an already-mutated measured state or import a prebuilt image. Timing records the actual t128/t256 transition event window: K/V and Q H2D transfers, append kernel, complete query+O kernels, flush kernel. The host-visible wall time is separately reported. The immutable O H2D transfer and allocation/init/untimed 127/255 preceding resident steps are preparation for that measured boundary, explicitly declared; they are not counted as the t128/t256 step and are not claimed free across full lifetime. No repeated replay timing of an unchanged offline query is substituted for causal work. Before timings there are only exact event-state and source-output checks; if they fail, retain source/build/audit artifacts and report numerical or update-closure failure. The GPU lane requires separately granted admission; `build.sh`, `reason.py`, `audit.py` and this document by themselves launch no GPU kernels.

## Native result

Eight one-attempt stages completed under the measurement lock and `gpu-run`, all with Bonsai active at the same PID **145247** before and after. All four complete acceptance traces and independent audits passed before the first timing trace. Every pre/post phase of both resident encoders matched the original immutable logical records and canonical image bytes exactly; K/V quantized events were generated on the GPU from its own stored recent BF16 records. The largest full-O difference against the independent conventional CPU map was **7.153e−7**, relative L2 **8.530e−7**. The eight actual output pairs are retained as `.f32` files. Their teacher-normalized SSE aggregates are **0.003068935818** conventional and **0.003068935757** dictionary. These eight-position aggregates are not the all-1,024-held-query metric of the earlier study.

Input spans are approximately 21 µs for both. Both sampled positions trigger K32 flush, so these are **flush-boundary costs**, not average per-token latency or the full trace's throughput. The one-lane mutation placement includes repeated flat-image copying and serial quantization; it is not a strong parallel encoder baseline. Earlier query-only microsecond results exclude this work and cannot substitute for these millisecond complete-step results. Dictionary/conventional matched-state event ratios have median **5.100**, with all eight above one. Each state has one measurement per arm, conventional first; this is a fixed-placement discriminator, not a repeated randomized speed estimate.

[`results.json`](results.json) and [`summarize.py`](summarize.py) retain all per-state observations and resource categories. Each original device phase file is stored losslessly as `held-N-snapshots.bin.zst`; its decoded SHA matches the independent `audit-held-N.json` receipt. `zstd -d held-N-snapshots.bin.zst` reconstructs it for `audit.py` without a device/model rerun. The raw acceptance and timing JSONL, eight admission receipts, compiler assembly, program hashes and actual query outputs are all retained. Acceptance event durations contain audit traffic and are excluded from timing aggregation.

## Prelaunch repairs and host correspondence

Review repaired a downward-overlapping recent-V move in the conventional K32 flush (forward copy is required), the audit export of fixed-stride control slabs, and the empty dictionary phase. Both device encoders must round the original binary64 step directly to binary16, not through binary32. ROCm 7.2's attempted direct `_Float16` conversion produced an illegal gfx1151 low-half register operand; [`step_bits.hpp`](step_bits.hpp) implements the required nonnegative binary64-to-binary16 nearest-even conversion using integer bits instead. [`check-step.cpp`](check-step.cpp) compared 126,980 boundary cases to host direct conversion with zero differences (`rounding.json`). This fixes this maintained reader's lowering; it is not a claim that the compiler defect itself was fixed.

The identical serial transition source also compiles with [`host-shim.hpp`](host-shim.hpp) and [`host-replay.cpp`](host-replay.cpp). One bounded held-0 host replay passed all 1,024 pre/post phases across both arms against the independent immutable-record audit (`host-held-0.json`). This is host correspondence, not device acceptance. No source model or teacher was run. Complete phase semantics are explained by the parent [residency note](../value-record-quotient/RESIDENCY.md).

## Operation and custody

From this directory `bash build.sh` compiles one HIP executable and emits [`compile-receipt.json`](compile-receipt.json) and retained device assembly; generated headers extract precisely the selected existing query bodies with duplicate unused arms removed. `python3 reason.py` is CPU-only and writes `capacity.json`. Rebuilding invalidates the timing gate.

The frozen schedule has eight separately bounded stages: `bash run-stage.sh accept held-N` for N=0…3, **all four passing before** `bash run-stage.sh timing held-N` for N=0…3. Each invocation makes one nonblocking lock/admission attempt and runs the device trace under a 45-second timeout, preserving an immutable attempt receipt. A failed or denied stage stops this experiment; there is no alternate placement or automatic retry. Acceptance independently audits every state and saves the actual eight full-O pairs. `gate.py` verifies all four successful device audit receipts, 16 output guards and current program hashes before allowing a fresh timing trace; the executable also requires its gate marker. Timing is one trace per window/arm, in conventional-then-dictionary order, not repeated/rotated statistical sampling. Event output separates H2D input span from append/query/flush span; acceptance event spans include host audit traffic and are not latency results.

Host audit snapshot files, CPU references, source logs, developer loader/ELF, HIP runtime and Python audit allocations are **measurement infrastructure**, not uncharged resident device cache. The shared machine [GPU admission handbook](/path/to/workspace/machine/gpu-jobs.md) controls each bounded probe. The wrapper preserves the live Bonsai process with the same nonzero PID before and after `gpu-run --host-mib 1024 --gtt-mib 512`. It never uses Bonsai's exclusive service-stopping lease. The frozen device schedule completed without a retry, placement change, source rerun or service interruption. Running `python3 summarize.py` regenerates the report from retained receipts; completed `run-stage.sh` invocations refuse repetition while their attempt receipts exist.
