# Official QTIP bitshift trellises at the full-input Q-head boundary

This is a **second named structured comparator**, distinct from QuIP#: [QTIP](https://github.com/Cornell-RelaxML/qtip) at upstream commit `e90c6688c8dfae326a3a81b5eb032db7c6680ec0` (NeurIPS 2024, GPL-3.0; upstream terms included in [`LICENSE`](LICENSE)). Both published 3-bit codebook families are executed on the original first 128 q-projection outputs **across all 1,024 input coordinates**. The stronger official **HYB** configuration (`L=16,K=3,V=2,Q=9`, symmetric quantized lookup, 16×16 trellis tiles) gets its natural 53,394-byte standalone image. The table-free official **3INST** (`L=16,K=3,V=1`, 16×16 tiles) gets a 49,298-byte image. This is not an invented trellis variant or an artificial equal-byte padding exercise.

| QTIP image | Codes | Signs / scale | Generic lookup paid **once** | Total bytes | Train response error | Held response error |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| [HYB 3-bit](qtip-hyb-full-row.bin) | 49,152 | 128+16+2 | 4,096 FP32 | **53,394** | .024889625 | **.030333041** |
| [3INST 3-bit](qtip-3inst-full-row.bin) | 49,152 | 128+16+2 | zero (3-instruction computed codebook) | **49,298** | .025865532 | **.031089737** |

The HYB table is generated from upstream's `1<<20` iid Gaussian pairs, `scipy.cluster.vq.kmeans` of 512 initial Gaussian centers, and the upstream fixed `0.9682458365518543` normalization, using the predeclared seed `20260924`. It is **not fitted to this Qwen matrix or the inspected held states**. Its complete 512×2 FP32 realization is billed once in the standalone image after the signs/scale; another matrix sharing exactly this table could amortize it once per reader pool, not once per matrix. The generic fixed HYB state-to-index/sign calculation and 3INST arithmetic are code, not hidden model-specific tables or predecoded weights. Sign vectors are fully stored in 144 bytes; their preparation seed is not needed at inference. The codebook generated by a random training corpus must be stored or exactly regenerated; the latter is not assumed free. No HYB finetuning or per-model learned LUT is present; any such adaptation must pay its parameters separately.

The full BF16-source target and fixed train/held producer are `/path/to/workspace/data/kelana-subbit/fixtures/qwen3-0.6b-wikitext/layer00-self_attn_q_proj.npz`, SHA256 `389e5f8c17ac151070b12094849f450130ab9c1684f51b402d59fd4e7ac2008f`: weight `(2048,1024)`, train `(2048,1024)`, held (`validation`) `(1024,1024)`. Reported error is `||X(W_hat-W)^T||² / ||XW^T||²` on the original 2,048 train and 1,024 held captures. Only train states enter the damped Gram; held is decoded/scored once at the end. The **same fixed** sign seed, `.01` mean-diagonal Hessian damping and `scale_override=.9` (the upstream **2-bit example's explicitly supplied** setting) apply to both arms; no held-tuned hyperparameter selection or fit sweep was performed. The upstream CLI parser's default `--scale_override=-1` is **not** what this fit used; upstream `finetune.py` divides RMS by the provided argument without internally substituting `.9`. This positive override was chosen before held scoring, not presented as the upstream 3-bit model-release recipe. The scale is fitted from transformed source weights and fixed codebook second moment, then FP16-rounded in the paid image. Hadamard incoherence is applied on both axes; 16-column block LDLQ proceeds backwards. Every 16×16 tile uses upstream's two-pass circular Viterbi: a half-rotation first pass seeds an overlap, followed by an initial/terminal-state-constrained full pass. **HYB has `has_kernel=True` even when the CPU kernel itself is unavailable:** upstream `ldlq.py` permutes each 256-value tile with `_PERMUTE = arange(256).reshape(2,8,2,4,2).permute(1,3,2,0,4).flatten()` before Viterbi and inverse-permutes reconstructed values. The CPU fitter and independent image reader perform this exact tile permutation; omitting it produces a different, non-upstream fit and an invalid HYB comparison. 3INST has `has_kernel=False` and quantizes the unpermuted row-major tile. The backwards 16-column block-LDLQ ordering, inverse within-block factor, and later-column error correction follow upstream `lib/algo/ldlq.py` and `lib/utils/math_utils.py`; each group of 16 output rows can be processed independently. Inputs are rounded to FP16 at Viterbi's boundary as in `bitshift_codebook.quantize`; weights and codebook contributions accumulate in FP32. The CPU adaptation builds the Gram/LDL in float64 then downcasts for the fitter, and uses NumPy instead of upstream Torch for the reproducible signs; it does not reproduce whole-layer QuIP-style fine-tuning, CUDA packing, TP or the authors' whole-model quality rows.

The independent [`replay.py`](replay.py) imports **no fitter or upstream module**. It parses every MSB-first tile stream, restores the circular final 13 (3INST) or 10 (HYB) bits, checks terminal/initial state consistency, computes the published 3INST arithmetic or the published HYB state map against the **image's** lookup, inverse-permutes HYB tile values, reverses both Hadamards and packed signs, and scores the entire frozen response boundary. It requires only a complete image and the canonical fixture, not the preparation cache. All 65,536 levels of both source codebooks were checked bitwise against the pinned upstream Torch `decode_3inst` / `quantlut_sym` by [`check_upstream.py`](check_upstream.py): zero mismatches. [`check_fit_parity.py`](check_fit_parity.py) extracts the pinned upstream class/function bodies, disables only `torch.compile` on its CPU `update` method, and checks an entire fixed 16×16 tile against each native CPU Viterbi: **zero/256 3INST state mismatches and zero/128 HYB state mismatches**, including the cyclic half-roll and overlap boundary. The independent permutation formula additionally matches upstream `_PERMUTE` on all 256 positions. These checks establish codebook and bounded Viterbi correspondence, **not** byte-identical entire upstream layer fitting or CUDA-interleaved packing. Upstream `lib/algo/finetune.py` calls `block_LDL(HRr,16)` and `LDLQ(...,for_kernel=has_kernel)`; `kernel_check.py` returns true precisely for this HYB shape, and upstream applies the 256-position permutation before each Viterbi call, inverse permutation after reconstructing values, then a CUDA-specific interleave after `pack_trellis`. Our CPU image stores those same trellis states in natural MSB-first tile streams without the CUDA interleave, and the independent reader explicitly undoes the tile permutation. The source H normalization/regularization and output/input Hadamards follow the same formulas; our float64 Cholesky-then-FP32 downcast and NumPy sign RNG can change marginal tie decisions compared with an upstream Torch/GPU fit. The complete original 2,048-row capture is used as a covariance, not original Llama layer Hessian captures or upstream whole-block finetuning. The pinned image hashes and field ledgers are in [`results-hyb.json`](results-hyb.json) and [`results-3inst.json`](results-3inst.json).

At this endpoint QTIP HYB is **not** a better local response-quality point than the 50,322-byte QuIP# residual-root image (`.013109790` held), even though it spends another 3,072 bytes; 3INST is smaller by 1,024 bytes than the 50,322-byte root and 1,022 bytes than its matched scalar (`.014627799` held), but has higher held error. These comparisons do not establish dominance over all cheaper alternatives: the methods have different decode work, no native matched timing here, and source-completed response or downstream attention can change the ranking. QTIP's paper's 3-bit full-model result and optional finetuning are not reproduced by this isolated no-FT row slab.

## Regeneration and resource ledger

```sh
cd /path/to/workspace/projects/kelana/research/isa-quantization/qtip-full-row-3inst
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
PY=/path/to/workspace/data/fish-s2-pro/venv/bin/python
g++ -O3 -march=native -std=c++17 trellis.cpp -o /tmp/kelana-qtip-3inst
g++ -O3 -march=native -std=c++17 hyb_trellis.cpp -o /tmp/kelana-qtip-hyb
/tmp/kelana-qtip-3inst lut "$PWD"
$PY build_hyb_lut.py                      # upstream 1M-sample kmeans: 35s on this CPU
/tmp/kelana-qtip-hyb lut "$PWD"
for arm in 3inst hyb; do
  $PY prepare.py transform --arm "$arm"
  $PY prepare.py ldl --arm "$arm"
done
for g in 0 1 2 3 4 5 6 7; do /tmp/kelana-qtip-3inst fit "$PWD" "$g"; done
for g in 0 1 2 3 4 5 6 7; do /tmp/kelana-qtip-hyb fit "$PWD" "$g"; done
$PY replay.py --arm 3inst --assemble
$PY replay.py --arm hyb --assemble
$PY replay.py --arm 3inst               # independent image-only playback
$PY replay.py --arm hyb
$PY check_upstream.py /path/to/managed/qtip-upstream-checkout
$PY check_fit_parity.py /path/to/managed/qtip-upstream-checkout 3inst /tmp/kelana-qtip-3inst
$PY check_fit_parity.py /path/to/managed/qtip-upstream-checkout hyb /tmp/kelana-qtip-hyb
```

Each command is bounded under one minute; one row-group fit took 0.44 s (3INST) and 1.57 s (HYB), and all eight groups were completed on CPU. The ignored `prepared/` and `prepared-hyb/` are reproducible caches: each has a 4 MiB FP32 block LDL matrix, 8 MiB FP64 Gram, 0.5 MiB transformed weights, and eight 6,144-byte tile chunks. At runtime a streamed reader can keep the image (53,394 or 49,298 B), one transformed input (1,024 floats, 4,096 B), one output scratch (128 floats, 512 B), and transition/lookup arithmetic; it need not materialize the decoded 128×1024 FP32 matrix (**524,288 extra bytes**). The C++ fit builds a temporary 65,536-state FP32 cost pair (524,288 B) and uint16 trace (262,144 B HYB or 4,194,304 B 3INST), which are **preparation only**, not runtime assets. An actual native compressed reader's instruction/cache costs and peak RAM remain unmeasured; upstream's 3-bit HYB CUDA kernel availability is not an AMD or CPU performance receipt.
