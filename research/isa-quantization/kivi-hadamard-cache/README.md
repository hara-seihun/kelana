# A fixed orthogonal Q/K cache gauge fails the KIVI causal train gate

**Decision: strictly bad on the declared train0 discriminator; no held evaluation.** A single deterministic normalized Sylvester-H128 transform applied to both query heads and the shared key **after source RoPE** preserves every unquantized attention score in real arithmetic, and the cache uses exactly the frozen KIVI 4-bit K/V, G32/R32, per-channel K / per-token V, FP16 origin/step, BF16 recent and causal flush policy. At unchanged **52,400 B preflush peak** the complete original two-head/unchanged V/O train0 pair post-O relative squared error is **0.00274992**, versus frozen KIVI **0.000145641** (18.9× worse); attention KL is **0.0862067 / 0.0350893**, versus **0.00370973 / 0.00118796**. We predeclared a gate of ≤1.2× KIVI train0 pair error **and** ≤1.2× each head KL before inspecting this image, and halted. No seed, rotation, code, bitwidth, quantizer, flush or loss iteration; no held window was opened. This is not a claim against optimized/randomized rotations, QuaRot, or all KIVI alternatives. The parent owns shared catalogue/synthesis.

## Construction and original source boundary

The strong original KIVI source/control, model provenance and twelve frozen windows reside at [`../kivi-causal-cache/`](../kivi-causal-cache/). Its train0 result/image/event log are the unchanged comparator. The source BF16 key is the **already Qwen-K-normalized, position-RoPE-rotated** key, rounded to BF16 exactly as in that control. Apply `H_128/√128` in seven fixed adjacent-stride passes `(1,2,4,8,16,32,64)` to this source BF16 key at arrival, **then** round to BF16 for the transformed recent cache and K-flush quantizer. Both live original FP32 rotary queries are transformed by the same H; original BF16 source V, V-flush bytes, Q/K projections and norms, source RoPE, two-head shared K/V, stable causal softmax, and original BF16 full O are untouched. The original teacher uses FP32 rotary K; the previous BF16 source K boundary is deliberately shared by both methods. The transform is orthogonal and symmetric, so `⟨Hq,Hk⟩=⟨q,k⟩` for arbitrary real q,k; FP32 and BF16 roundoffs remain paid numerical boundaries. `H` does **not** commute with RoPE in general: doing it after both complete source rotations avoids a false weight/source invariance claim. The deterministic transform is algorithmic with **zero trained or generic table bytes** and no calibration or running statistics. No future tokens are used for early queries.

Orthogonal online Q/K gauge plus cache quantization is prior art, not a novel gauge: [QuaRot, Ashkboos et al., NeurIPS 2024](https://arxiv.org/abs/2404.00456) uses randomized Hadamard rotations to tame outliers and quantize KV cache. This bounded **fixed nonrandom Sylvester** placement against already per-channel KIVI on a particular Qwen GQA source is deliberately narrower than QuaRot's algorithm/model claims and does not implement its optimized integration.

[`program.py`](program.py) source-encodes only the arriving transformed K. Every 32nd key is encoded per channel with KIVI's available-only min/max, unsigned nearest-even four-bit code and FP16 min/step; each V flush **copies the corresponding original KIVI event byte for byte** at that same causal time, rather than reoptimizing V. The train0 image [`train-0-final.bin`](train-0-final.bin) is 46,592 B postflush, SHA256 `fc7eaa3340eac414717c37408fa57943015053f551eb578a68d81b3bfa03a490`; [`train-0-flush.bin`](train-0-flush.bin) records the eight K/224 V chronological events as evidence, **not** retained inference state. [`train-0-prefixes.json`](train-0-prefixes.json) pins every 256 preflush cache hashes. [`replay.py`](replay.py) separately inserts current source values, consumes each event only after its own query, verifies every hash, 8 stored K field/code calculations, all 224 original V event bytes, final image and complete head score/softmax/V/O against the original teacher. Replay matches the initial encoder/reader's losses (last 3e−8 variation in pair error). No final-token image is used as the early causal cache.

## Gate diagnostic: it is score geometry, not an inexact orthogonal identity

[`train-0.json`](train-0.json) includes **unquantized transformed controls** using original FP32 rotary K and source-BF16 K transformed then rounded to BF16, without any four-bit flush. The former has head KL approximately zero (FP32 numerical noise), post-O SSE `1.8e−10 / 6.1e−10`, and maximum score difference `2.85e−5 / 4.66e−5`. The latter already has head KL `.000888 / .000885` from transform+BF16 recent rounding, but the quantized candidate reaches `.0862 / .0351`: the 4-bit transformed K is the dominant new error. At actual **t256 preflush** (seven packed K chunks, 32 recent K, 223 quantized V, 33 recent V), [`diagnosis-train0.json`](diagnosis-train0.json) decodes both actual paid states. Relative K-coordinate error is nearly identical, **0.000481665 original vs 0.000489065 rotated**. Yet the query-weighted score RMSE is **0.118→0.611** (head0), **0.166→0.942** (head1); maximum score errors **0.441→2.361**, **0.502→2.923**. Thus equal-looking isotropic key MSE is not an attention-quality guarantee: the original per-channel KIVI basis better preserves the directions probed by these two source queries. The unquantized transformed-BF16 t256 score RMSE is only `.0481/.0802`, and pure FP32-H roundoff `3.2e−6/5.5e−6`.

## Bytes, online work and limitations

At t256 preflush both methods have quantized K `17,920 B`, recent BF16 K `8,192 B`, quantized V `17,840 B`, recent BF16 V `8,448 B`: **52,400 B** total. Final postflush is `46,592 B` for both; original common source static two-Q/K/V/O/gamma bytes (`1,573,376 B`) and 2-B position counter are unchanged. K and V packing/flush still inspect the same 32×128 source key scalars per slab /128 source value scalars per token, respectively, but here the **transformed** K producer costs seven stages of **448 butterflies = 896 scalar add/sub operations and 128 scale multiplications** on each arriving shared K, plus the same per-query transformation for **each of two Q heads** (total 1,344 butterflies, 2,688 adds/subs and 384 scale multiplies per token+two-head query). This transformation is additional before otherwise identical nibble assignment and packed score reader; it cannot be hidden as offline preparation. There is no persistent matrix, reference or scratch beyond the KIVI state, but FP32 transform temporary registers and any future native code footprint must be paid. The Python acceptance program decodes full K/V arrays as **temporary CPU scratch** (up to 262,144 B), not as an advertised 52,400 B executable process; the original [`../kivi-packed-consumer/`](../kivi-packed-consumer/) is the conventional and direct packed-reader resource control. Because the quality gate already failed and the new producer adds work without reducing state, **no gfx1151 compilation or timing is warranted or claimed**. No GPU, new capture or source refit.
