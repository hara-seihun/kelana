# Fixed additive V coordinate translation: source-range certificate

This is a **source-only** screen of one frozen channel translation. No cache encoding, quantizer, held selection, consumer execution, GPU, model forward, or checkpoint is used. The [parent foundation](../value-coordinate-gauge/TRANSLATION.md) owns the general mathematics: `Kelana/ValueRangeTranslation.lean` proves the difference-constraint/flow certificate and `Kelana/ValueCoordinateGauge.lean` proves normalized-attention translation; the files here certify the concrete eight-window source instance. The existing G32 grouping is eight KV heads × four contiguous 32-channel blocks.

## Frozen source and objective

[`solve.py`](solve.py) reads precisely `../kivi-value-intern/train-{0..7}-events.bin`: 256 chronological 4098-byte arrivals per window, each `u16 t | 2048B K | 2048B BF16 V`. The 8 source SHA256 hashes are pinned in [`certificate.json`](certificate.json) and checked against the original interner owner's per-window event manifests, not merely against a newly generated certificate. Only V is interpreted. Total source read: **8,392,704 B** of existing chronological events, of which **4,194,304 B** are BF16 V. Extracting all BF16 values into a common exact integer unit **2^-29** is exact; signed int64 bounds are asserted before vectorized differences and dynamic programming. No additional source producer arrays are committed.

For group `g`, `A[d,e]=max_(all 2048 train arrivals)(v[d]-v[e])`, with both indices within the original 32 coordinates. Every exact entry is retained as little-endian int64 in [`source-maxima.i64`](source-maxima.i64) (**262,144 B**). An exact max-cycle-mean Karp recurrence (source vertex zero, exact rational max/min comparisons), followed by 31 simultaneous longest-path relaxations from all-zero potentials, yields `R` and `c` satisfying `A[d,e]-c[d]+c[e]≤R`. This tie/gauge rule was specified to the parent before reading any ranges. Each group's potential is shifted by `(min c+max c)/2`, without changing differences, and rounded **once**, ties-to-even, to the actual [`center-fp16.bin`](center-fp16.bin): **2,048 B**, head/group/channel order, SHA256 `143c78b481c35b7c14699825931e7ef68b8d7edbac4fa75775effdd095c7923c`. All 1024 centers are finite. The rational radius, rational midpoint-gauge potential and directed tight cycle for each group are in the certificate.

[`check.py`](check.py) independently reparses all eight original event files, independently recomputes **all 32,768 source maxima**, checks every one of **32,768 exact rational potential inequalities**, and checks each cycle's balanced vertex flow, total edge mass one, and exact edge-weight expectation `R`. Every individual cycle edge has mass `1/length` (repeated edges, if present, are accumulated). The primal feasible potential and dual balanced unit-mass critical cycle prove the exact optimum without trusting optimizer status. It additionally checks the FP16 image against each rational coordinate with exact-neighbor/ties-to-even comparisons, re-evaluates each group's exact optimum and rounded achieved maximum from its independently recovered source, and checks `R_rounded ≤ R+2||round(c)-c||∞`. Run from this directory with `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python solve.py` and then `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python check.py`; each command finishes within one minute. [`screen.json`](screen.json) holds exact-source-derived per-group maxima and eight-window distributions. The per-group original/rounded worst values and the distribution summaries are rendered decimals; all certificate comparisons use exact integers/rationals.

Rounded achievable ranges are verified separately rather than calling the exact `R` the paid-image range.

## Source-extremum connectivity

The separate [`pareto.py`](pareto.py) source check asks whether a nonconstant center could avoid worsening **every** original token-group range, rather than optimizing the maximum. An edge e→d records a real source row where channel e is a minimum and d a maximum. Nonincrease on that row requires c_e≤c_d. Inward and outward paths force all centers in a mutually reachable component equal.

[`range-edges.json`](range-edges.json) contains source-row-witnessed inward/outward trees covering all32 channels for **28 of32 groups**. `python pareto.py check` independently checks every recorded extremum and both tree reachabilities against the original source bytes, without rerunning the component search; it passed. On those28 groups, any shift that strictly improves a range must worsen at least one other source row. The remaining groups11,17,22,26 have reported component sizes31+1,30+1+1,30+1+1,and32 singletons; the full-group impossibility certificate is not asserted there. These are source-range constraints, not output/quantizer statements. The parent [Lean foundation](../value-coordinate-gauge/TRANSLATION.md#why-preserving-every-individual-source-range-can-forbid-any-change) proves the general path/equality implication. No center or consumer changed in this diagnostic.

## Preparation and inference boundary

Preparing `A` entails 32×2048×32² = **67,108,864** source pair comparisons; the checker independently repeats them. The offline A table is 262,144 B, the actual center image costs 2,048 B per full layer, and the compact JSON certificate/screen cost about 15/13 KB of research custody, not runtime state. To realize this coordinate change in a live model, the 1024 producer-channel translations and the single constant final output correction must be materialized or folded into existing weights/biases, and the changed BF16/FP16 arithmetic, changed quantizer decisions, state bytes, reader work and full-O error must all be priced. For normalized attention, `Σ_i p_i(v_i−c)=Σ_i p_i v_i−c`, hence the 16 Q-head O contributions of the eight KV-head centers can be summed into **one** output bias vector; this exact identity does not claim a free floating implementation. No follow-up consumer was run or selected here.
