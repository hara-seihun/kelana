# Same-byte transported coordinates by a changed Q4 grammar

**Result.** The five-angle transported-normalization construction in [the first study](README.md) admits a **standalone 8,704-byte image**, exactly the scalar Q4 control's block byte count. The 64 angle labels are carried in three FP16 sign bits per RoPE pair, *not* in an additional 64-byte table. This changes the image grammar and adds extraction/sign-restoration work; it is not a free relabeling of the original Q4 reader. Complete BF16-rounded two-query-head/shared-key causal replay from the newly serialized image gives held mean attention KL **0.0006783392** and combined V/O relative squared error **0.0001352847**, compared with exported scalar Q4's **0.000902435** and **0.000219897** and equal-budget freshly trained zero-angle Q4's **0.000872766** and **0.000221727**. Thus a *same-static-byte, better-local-quality point exists*; it is not a native speed or total paid-resource dominance claim. The image, CPU replay and its SHA256 live in [`q4-coordinate-embedded.bin`](q4-coordinate-embedded.bin), [`embedded.py`](embedded.py), and [`results-embedded.json`](results-embedded.json).

## The constrained image grammar

A Q4 row uses 64 nibble bytes, FP16 origin and FP16 step, i.e. 68 bytes. [`embedded.py`](embedded.py) checks **all 128 rows of this fitted image** at the exact FP16 fields *before* encoding: every origin is finite, strictly negative (range `[-0.439208984375, -0.0189666748046875]`), every step finite, strictly positive (range `[0.002582550048828125, 0.0450439453125]`). This is a finite witness for the train-fitted image, **not** a universal assertion that arbitrary Q4 rows or future fitted images meet the constraints. The encoder rejects any image outside this field domain. The exported scalar Q4 control independently passes the same field check (origins `[-0.44287109375, -0.0240020751953125]`, steps `[0.00325775146484375, 0.045257568359375]`). The canonical sign pattern is negative/positive on every row; its sign bits carry no additional scalar value *inside this declared grammar*. Nothing is silently replaced: the decoder recovers the exact original FP16 fields and all code nibbles before ordinary Q4 decoding.

For pair `p` with rows `p,p+64`, use signs of `origin_p`, `step_p`, `origin_(p+64)` for the three bits of label 0..4, leaving `step_(p+64)` canonical. The image writer XORs only selected FP16 sign bits with the code bits. The independent reader reconstructs the label from deviations from the required signs, restores all three scalar signs, rejects unused codes 5..7, checks the field domain, then decodes the exact Q4 scalars and nibbles. [`Kelana/EmbeddedAngle.lean`](../../../Kelana/EmbeddedAngle.lean) proves the Boolean sign-label roundtrip; the field-domain check and file-byte equality are executable rather than Lean certificates. The SHA256 of restored 8,704-byte Q4 payload is `3c610e34d48249811eb73e6c652fbacf022be68386d7462da8ff136cb051b322`, matching the original coordinate image's first 8,704 bytes. The embedded image itself is 8,704 bytes, SHA256 `839cc6878db104470aa64c3f9803c7a5b756e409ec5425b823b2c760f4d2512f`. Angle counts for `[0,-π/8,+π/8,-π/4,+π/4]` are `[20,13,13,6,12]`.

The original 8,768-byte image remains in custody as provenance. `embedded.py` regenerates its *train-only* selected Q4 rows/angles, serializes the sign-embedded image, **reads that file back**, decodes without access to the old angle table, asserts exact payload and label roundtrips and sends the resulting array/labels to the same complete GQA/O reader as the original study. It emits a separate `results-embedded.json` rather than changing the original result. The head-0 held KL is **0.001342611**, head-1 held KL is **0.000014293**; both live consumers count. The zero-angle refit uses the same 512 train tokens, row grid fitting and input-covariance objective as the five-angle search. No held attention or O target enters the fit. The image restores precisely the original selected row payload and angle choices. This follow-up also corrects the initial replay's storage rounding: the first report billed changed full Q/K weights as BF16 but multiplied FP32-transformed coefficients. Both results files now round the *stored* transformed full Q/K weights to BF16 before projection. Their corrected observer results coincide numerically; the initial committed result at `75adbf5` is retained in Git provenance, rather than silently used as a BF16-cost measurement.

The affected Q/K group stores two BF16 Q heads and one BF16 K head (786,432 bytes before replacing head-0 Q's 32,768-byte submatrix). Both changed and scalar images therefore have **762,368 bytes** in that scope: 786,432 − 32,768 + 8,704. Gamma fields are shared and unchanged, as are V/O matrices, so adding them to both totals does not alter the byte equality. Changed full Q/K weights replace, rather than duplicate, their original BF16 rows. Model-specific angle choices are wholly contained in the 8,704-byte serialized block. The source gamma and fixed five-entry angle vocabulary are needed to calculate transported metric coefficients; if persistently materialized as separate per-model arrays, those arrays must be charged. The live decoder additionally extracts 192 sign bits / 64 labels and restores scalar signs; each Q/K normalized token evaluates 64 transported quadratic pair terms instead of 128 plain squares (both query heads and shared K head), with extra cross products, coefficient arithmetic/loads and coefficient preparation. The numerical replay computes coefficients from stored labels and gamma at runtime; its simple per-head replay normalizes the shared K twice, while an optimized native consumer could reuse that K norm across both Q heads. It does not show a fused GPU kernel, native latency, model-wide distribution quality or improved speed. The equality is **static model byte count for this affected group**, not equality of CPU operations, instruction count, transient state or complete deployment costs. [The whole-group selection report](WHOLE-SELECTION.md#static-bytes-prepared-state-and-actual-reader-work) prices the actual replay's decoded labels/transient work and a concrete FP32 metric-table preparation alternative.
