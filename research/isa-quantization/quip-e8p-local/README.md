# QuIP# E8P12RVQ3B on the captured Qwen q-projection

**Named structured comparator, actual paid image.** The primary arm is [QuIP#](https://github.com/Cornell-RelaxML/quip-sharp) **E8P12RVQ3B** (2-bit E8P lattice plus 1-bit E8 residual vector quantization, rank zero), upstream immutable commit `1d8f873e9a2a8b86b12bb1064c312c5689b77d98`. This is a CPU port of upstream `lib/algo/quip.py` and `lib/codebook/latticee8_padded12_rvq3bit.py`, not a new learned vector dictionary. The eight-dimensional E8 and E8-residual grids, parity cosets, Hadamard incoherence, block-LDLQ, ten conditional coordinate passes, and upstream `sigma_reg=.01`, E8P12RVQ3B `opt_scale=.98`, residual scale `2.04` match source mathematics. A direct sample of 128 vectors gave **identical indices and decoded vectors** to the isolated upstream PyTorch quantizer. The fixed generic E8P table (SHA256 `efc2c03c60acd955dc812ff2bade9ec6cc31259807e48473506161f3a9a230ce`) is generated from that upstream source, not fitted to this model. Upstream code is GPL-3.0; this CPU port and its generated generic tables retain that source/terms provenance. The upstream checkout is a separate managed writer and is not vendored here.

The study fixes the actual BF16-derived 128×128 `layer00.self_attn.q_proj` slice and 2,048 train / 1,024 held producer states in `/path/to/workspace/data/kelana-subbit/fixtures/qwen3-0.6b-wikitext/layer00-self_attn_q_proj.npz` (SHA256 `389e5f8c17ac151070b12094849f450130ab9c1684f51b402d59fd4e7ac2008f`). Reference output is `X Wᵀ` for the same slice. Nothing here asserts whole-attention, model-loss, full-model state of the art, or native serving speed.

Code, signs, scale, row scales/origins and row mask are charged. Fixed image shape and generic program instructions are common and excluded; there is no paid per-model dictionary or uncounted learned transform.

The primary QuIP# 3-bit image is two bytes larger than the locally fitted 6,176-byte scalar image, and reduces held error by ~38.7%. It also improves over the 6,688-byte scalar point at less storage. That is a local structured-method comparison, **not** a SOTA quality claim or proof of performance dominance: the scalar is a strong local GPTQ-style control, and decoder work differs. Relative to the existing 6,848/7,104-byte pair programmes, this 6,178-byte point is a cheaper and more accurate achieved control, but neither its output nor their free-family certificates supplies a global optimality theorem. The weight slice is only one boundary, not a full model. The subsequent [standalone full-input slab](../quip-full-row-slab/README.md) charges both generic tables once to an actual 128×1024 region: lattice train error wins, but held error .013110 loses to the 54,416-byte scalar's .010423. Do not carry this small-tile win across that measured reversal. The [exact budget comparison](BUDGET.md) separately applies the existing all-cardinality covariance theorem to the achieved local image.

Primary image ledger: 128×16 uint16 E8P indices = **4,096 B**; 128×16 uint8 E81B residual indices = **2,048 B**; two 128-sign Hadamard vectors = **32 B**; FP16 global scale = **2 B**; total **6,178 B**, or **3.0166 effective bits/weight** over 16,384 original weights. The source stores `SU`, `SV` as FP16 and interleaves indices for its CUDA kernels; this local image packs the mathematically identical binary signs (16 B each), fuses uniform `SV` magnitude into a single FP16 scale, and keeps row-major indices. These are explicit layout/storage adaptations, not free metadata. Its generic E8P absolute table is 1,024 bytes; its fixed E81B table is 4,096 bytes as FP16. Both tables are identical across arbitrary layers and their code/lookup assets would be shared across a full model, not charged once per isolated layer; if **an isolated one-layer deployment** must purchase all codebook bytes afresh, its total static representation is **11,298 B**, and the 6,176-byte scalar is not size matched. `e8p-grid-part.bin` (43,712 B), its 2,732-byte abs map and 256-byte parity table are **quantization preparation**, not the inference reader. The CPU fitter also materializes a 2,097,152-byte FP32 E8P grid to validate its assignments, plus matrices, covariance, SVD intermediates; this is preparation RAM, not model bytes or a measured peak. No persisted model-specific preparation state is left out.

The 6,176-byte control consists of 5,648 coefficient-code bytes, 512 B FP16 row scale/origin, 16 B bitmask; all 97 upgraded rows are selected on train. The 6,688-byte control similarly consists of 6,160 code bytes, 512 B fields and 16 B mask. Both use the canonical [`matched-rate-frontier/fit.py`](../matched-rate-frontier/fit.py) full-Hessian compensated row fit and its fixed-code response-refit, with the row mix selected by train error. They are *not* QuIP#-quality or general SOTA scalar baselines.

### Execution and 2-bit rank caveat

A fused QuIP# 3-bit live reader needs one 128-element Hadamard on the input and one on the output (448 two-output butterflies, or 896 scalar additions/subtractions, per transform), 2,048 E8P code reconstructions, 2,048 residual table reads/additions, 16,384 coefficient contributions and 128 output scales/signs. The FP16 generic tables occupy 5,120 B, before the model image, inputs, accumulators, scratch or any code cache. A naive materialization of the FP32 decoded 128×128 weight would be another **65,536 B prepared runtime allocation**, not a model-serialization saving; the upstream path decodes/looks up during GEMV rather than requiring it. This study's row-major decoder is a CPU mathematical port. A separate [complete gfx1151 endpoint](../quip-native-endpoint/README.md) now directly reads both packed images, checks emitted FP32 output on eight real held states, and measures batch-1/8 device medians 9.879/9.720 µs versus scalar 11.840/11.879 µs. It uses 91 versus 21 VGPRs with no scratch and pays dynamic transforms and table access; neither kernel is claimed optimal. The full held-panel scores here remain ideal float64 matrix responses, distinct from the native eight-state numerical check. The alternative scalar has 16,384 coefficient contributions and per-row affine conversion, without Hadamards or codebook reads. The separate native result is local and warm-device, not a full-model speedup or standalone storage win.

Upstream `quip.py` provides optional `lora_rank`/`full_svd` fit and returns FP16 `A`, `B`. The repository's **E8P 2-bit** `QuantizedE8P12Linear.forward` at this commit accepts `rank,A,B` but never uses those factors; its **3-bit RVQ** forward explicitly does. Therefore the supplementary 2-bit rank-4/5 bytes in this study are decoded by the mathematically natural `(E8P × scale + A B)` reconstruction, **not** by the official E8P executable reader. They must not be treated as official QuIP# 2-bit serving comparisons. They are retained as evidence of this implementation distinction and are not the primary named control. Rank-zero E8P has no such discrepancy. The chosen 3-bit primary uses rank zero, so both its fit and reader avoid this issue.

Other bounded adaptations: Hadamard signs use NumPy's seeded generator, rather than upstream PyTorch's RNG; there is no optional `rescale_WH`, no model fine-tuning or fine-tuned linear correction; the captured train covariance is the calibration Hessian rather than upstream whole-model activation hook, and full 128-dimensional Hadamard avoids generalized non-power-of-two kernels. `LDLQ_buffered` and direct `LDLQ` are algebraically equivalent on this one 128-column block; the CPU port computes the direct block updates. These choices establish a credible **local** variant of the named official 3-bit quantizer, not a reproduction of published full-model QuIP# numbers.

## Reproduction

```sh
cd /path/to/workspace/projects/kelana
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
PY=/path/to/workspace/data/fish-s2-pro/venv/bin/python
$PY research/isa-quantization/quip-e8p-local/fit_rvq3.py
$PY research/isa-quantization/quip-e8p-local/fit_scalar.py
$PY research/isa-quantization/quip-e8p-local/replay.py
```

The primary result and the matching scalar image regenerate in bounded individual computations; `fit.py 0 4 5` regenerates the 2-bit auxiliary points. [`results.json`](results.json) records image SHA256 and independently decoded train/held errors. The reader pins all six image hashes and both inference-table hashes before decoding; missing controls fail rather than silently dropping an arm. Source and generic-codebook provenance are immutable above; no GPU or network access is needed to replay the stored images.
