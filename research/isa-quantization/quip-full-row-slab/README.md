# Standalone QuIP# 3-bit full-input q-projection row slab

**Result: the 128-input slice's local QuIP# win reverses on held full-input responses.** This study extends the [local E8P12RVQ3B comparator](../quip-e8p-local/README.md) to **all 1,024 actual input coordinates** of the first 128 q-projection output rows in Qwen3-0.6B. It puts both fixed generic codebooks **in the standalone image once**, not behind a hypothetical full-model amortization. Its 54,418-byte image scores train/held relative squared response errors **.003842229 / .013109790**. A 54,416-byte response-sensitive group128 Q3/Q4 image scores **.008801289 / .010423200**. The structured method fits the calibration responses more closely but loses held to a two-byte-smaller scalar control. There is no total frontier dominance claim because native execution work is not measured.

## Source, boundary, and preparation

The upstream named method is [QuIP#](https://github.com/Cornell-RelaxML/quip-sharp) E8P12RVQ3B at immutable commit `1d8f873e9a2a8b86b12bb1064c312c5689b77d98` (upstream GPL-3.0; this CPU port retains source/terms provenance). The original fixture `/path/to/workspace/data/kelana-subbit/fixtures/qwen3-0.6b-wikitext/layer00-self_attn_q_proj.npz` (SHA256 `389e5f8c17ac151070b12094849f450130ab9c1684f51b402d59fd4e7ac2008f`) has full weight `(2048,1024)`, train `(2048,1024)`, held `(1024,1024)`. The fixed observation is all 128 outputs of `weight[:128,:]` against **all 1,024 input coordinates**, on the original 2,048 training and 1,024 held states; no new capture or GPU is involved. Its metric is `||X (Ŵ−W)ᵀ||²/||X Wᵀ||²`. Neither number is full-model NLL, complete attention, or a published SOTA quality receipt.

The CPU fit uses upstream E8P and E81B codebook assignment, Hadamard incoherence, full 1,024×1,024 training covariance regularized by the upstream default `.01` mean-diagonal damping, block-8 LDLQ, ten upstream-default conditional refinement passes, `opt_scale=.98`, `opt_resid_scale=2.04`, and **rank zero**. Calibration and all scalar row/group-mode choices use training states only. This is the mathematically corresponding QuIP# quantizer on a supported power-of-two shape. The seed/generator is NumPy rather than upstream PyTorch; no optional per-coordinate pre-rescale, finetuning, or low-rank correction is used. Row-major 16-bit E8P and 8-bit E81B index packing replaces upstream CUDA-interleaved layout without changing decoded lattice values. The two binary Hadamard sign vectors are stored packed rather than as 1,152 FP16 sign bytes, and a common FP16 scale replaces equal-magnitude per-output `SV` fields. These are explicit local layout/serialization adaptations. Fixed shape and generic reader instructions are excluded for both images; this standalone image **includes** the generic decoder tables even though their mathematical values are fixed across models.

The matched scalar uses the canonical [`matched-rate-frontier/fit.py`](../matched-rate-frontier/fit.py) full-covariance damped inverse-Cholesky error-compensated quantizer, fitted separately in each group of 128 inputs. Each Q3 and Q4 group has three clipping starts and four grid alternations; its fixed-code scale/origin gets a full within-group response refit and FP16 rounding. Starting from 1,024 Q3 groups, an actual **whole 1,024-coordinate train-response covariance** computes the group upgrade gains including cross-group interactions and greedily selects 65 Q4 groups globally. Then all 16 scale/origin fields per output row are jointly refitted against that whole covariance and FP16-rounded, accepting only train-error improvements (128/128 rows). This is a strong bounded response-sensitive scalar control, not RTN. Per-group code search itself does not jointly revisit codes across groups; a stronger named structured or scalar fit could change the local frontier.

Effective standalone rates are `8×54,418/(128×1,024) = 3.321411` and `8×54,416/(128×1,024) = 3.321289` bits per original coefficient. The structured image's 49,298 model-specific bytes plus 5,120 once-billed generic table bytes are physically contiguous in [`quip-rvq3-standalone.bin`](quip-rvq3-standalone.bin), SHA256 `7234c67cc269f945b2826ad8686207336208ed531023ede0be7925c1c041ad43`. The independently parsed scalar image SHA256 is `78b66990378f3dcae85458c50f4db04bc4d1e2b40d748b4100b078bfb055aec1`. Both are actual 128×1,024 images, not proportional estimates. Their fixed-format reader depends on no separate serialized per-model shape or calibration Hessian. The distinct ~38.7% held advantage for QuIP# on the earlier 128×128 slice is therefore not a full-row conclusion: changing the input region changes fitted indices and calibration geometry, while charging tables changes only the paid rate.

## Work and live memory remain separate axes

A direct QuIP# reader must consume 16,384 E8P codes plus 16,384 E81B lookups/additions and 131,072 original-dimensional coefficient contributions per full response, along with a 1,024-point input Hadamard (5,120 butterflies / 10,240 add-sub operations), a 128-point output Hadamard (448 / 896), sign application and output scaling. Its two generic tables occupy 5,120 B and are already counted **once in the standalone serialized image**; preparation additionally builds the fixed E8P projection tables (43,712+2,732+256 B), a 2,097,152-byte FP32 E8P grid and 1,024×1,024 covariance/LDL matrices. The fitter's peak memory was not measured. At inference, materializing a fully decoded FP32 weight would cost **524,288 B extra live RAM**; the compressed-reader mathematics does not require retaining that matrix. The scalar path also has 131,072 coefficient contributions, paid group scales/origins, and no Hadamard or lattice lookup. Cache traffic, register pressure, emitted BF16/FP16 rounding, measured native latency and live peak RAM are not claimed by the ideal-precision independent replay. This full-row result is not a proof that the scalar dominates on the complete behavior/storage/execution frontier.

## Reproduction

```sh
cd /path/to/workspace/projects/kelana
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
PY=/path/to/workspace/data/fish-s2-pro/venv/bin/python
$PY research/isa-quantization/quip-full-row-slab/fit_rvq3.py
for g in 0 1 2 3 4 5 6 7; do $PY research/isa-quantization/quip-full-row-slab/fit_scalar_group.py "$g"; done
$PY research/isa-quantization/quip-full-row-slab/assemble_scalar.py
$PY research/isa-quantization/quip-full-row-slab/replay.py
```

Each individual fitting computation is bounded below one minute with one BLAS thread; eight group records are retained for provenance, not required by the inference readers. [`replay.py`](replay.py) independently parses the two images, checks exact byte totals and fixed codebook/fixture hashes, reconstructs complete 128×1,024 matrices and scores both train and held. [`results.json`](results.json) binds the images, field ledgers and errors. Retaining the train-vs-held reversal rather than tuning on held is the discriminating outcome.
