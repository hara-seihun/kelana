# Native full-row root-code reader versus frozen RVQ table and matched scalar

The exact [E81B root relabeling](../e8-root-program/README.md) deletes the 4,096-byte generic FP16 residual table without changing the 128×1,024 QuIP# map. This is its **first complete native gfx1151 execution test**, against the unchanged old table reader and the [two-byte-near mixed Q2/Q3 scalar image](../quip-root-matched-scalar/README.md). It uses the first eight distinct held Qwen3-0.6B producer states and all 128 response coordinates. No expanded matrix is prepared or passed to the GPU; no model service or inference engine adopts these kernels.

## Images, numerical boundary, and quality

| Reader | Full stored image | Generic assets included in image | Full 1,024-state held ideal relative squared response error |
| --- | ---: | ---: | ---: |
| Root-coded E8P12RVQ3B | **50,322 B** | E8P absolute 1,024 B; residual **0 B** | .013109790 |
| Original frozen E8P12RVQ3B | **54,418 B** | E8P absolute 1,024 B + residual FP16 **4,096 B** | .013109790 |
| Response-fitted group128 Q2/Q3 | **50,320 B** | no generic table; 4,096 B model-specific FP16 affine fields and 128 B mask included | .014627799 |

The root image SHA256 is `d39500d3a5fbfd3260f4139d064ab00654582e15e4fc461fc923502d841f907a`; old table image `7234c67cc269f945b2826ad8686207336208ed531023ede0be7925c1c041ad43`; scalar `e41d273bd2d5ea7ef497e6c2749bf6ac5b1529124f8e24d2ea2448132dfdfd15`. Both QuIP images keep 32,768 B E8P codes, 16,384 B RVQ/root codes, 144 B signs and 2 B global FP16 scale. The stored original and root image decoders are independently checked for equal full weights in the root owner's study. Only the residual code labels and table residency differ. The scalar control has 833 Q3/191 Q2 groups and was selected on train only.

[`prepare.py`](prepare.py) pins all three image hashes and the SHA256 of the original full-input capture, decodes the old table image with the **independent CPU reader**, and reconstructs the scalar packed image independently. It writes eight real FP32 inputs and corresponding 128-output targets from the stored images plus teacher. The root target is this old target because the root owner's exhaustive 256-code bijection establishes complete decoded-weight equality; it does **not** pass an expanded decoded matrix into the native kernel. Every GPU output is copied back once outside timing and compared with its stored-image target; maximum absolute error across eight states is **4.77e-7**, under the declared `5e-5` FP32 guard. The guard allows distinct FP32 reduction orders over 1,024 inputs; the measured discrepancies, not the guard threshold, describe numerical fidelity. On the eight-state subset the root/old native teacher errors are **.001195516/.001195515** and scalar **.006128136**. These subset numbers do not replace the full 1,024-held-state ideal-precision quality scores above.

## Complete consumer and measured work

The [`native.hip`](native.hip) root and old kernels have exactly the same one-block-per-state / 128-lanes design: each lane gathers eight dynamically signed input floats, and all lanes perform the **full 1,024-element input Hadamard** (5,120 two-output butterflies, 10,240 scalar add/sub). Each output lane reads 128 E8P codes, 128 residual bytes, the paid absolute lookup and global scale, decodes 1,024 E8P coefficients and reduces against transformed input. The old lane additionally reads eight FP16 residual coefficients per byte and accumulates their 1,024 contributions. The root lane instead handles two indexed transformed-input entries for the nonzero integer/axis root (7,533 total image codes), no entries for zero (53), or eight signed entries for the half root (8,798), with per-code parity and branch. Finally both apply the **128-element output Hadamard** (448 butterflies, 896 add/sub) and output signs; nothing is computed offline for a particular dynamic input. Both use **4,608 B LDS per block** (4,096 input +512 output), 44 VGPR/35 SGPR per lane, and **zero scratch** in the emitted [`assembly.s`](assembly.s).

The scalar kernel reads its mode mask, computes each row's variable byte offset *in the kernel* (no uncharged prepared row offsets), extracts every 2-/3-bit coefficient from the stored image, applies all 1,024 contributions and each group's FP16 scale/origin times its dynamic input sum, then writes all 128 outputs. It uses 36 VGPR/24 SGPR, no LDS or scratch. It has no Hadamard. All three read warm device-resident model images and dynamic input; the output buffer is device resident. Input (eight FP32 rows) is 32,768 B and output is 4,096 B, plus temporary 4,608 B LDS per QuIP block. For batch1 only 4,096 B input and 512 B output are active. Benchmark harness holds **all three images and the old 4,096-byte table at once** for adjacent dispatches; that joint measurement residency is not the deployment cost of one arm. In particular, the root kernel is compiled without dereferencing the residual-table pointer (see assembly), though the harness keeps the old table resident for the frozen old control.

Complete emitted device code is committed, not inferred: `llvm-nm -S` on the `-save-temps` device executable gives scalar kernel **8,344 B**, old kernel **2,744 B**, root kernel **3,056 B**, and shared out-of-line input-transform helper **10,872 B**; output transform is inlined. A separate single-arm build would need its own copy of common code. Root saves **4,096 B static data** but its emitted kernel body is **312 B larger** than the old one here; code, host HIP runtime and kernel descriptors are distinct from model-image bytes. The source `.s` is 180,360 B text, not device instruction footprint. These counts are for this exact `hipcc -O3 --offload-arch=gfx1151` lowering, not universal ISA bounds. Adding the displayed image and required device-code bodies gives 64,250 B root, 68,034 B old table, and 58,664 B scalar, before common runtime/descriptors. Thus root and scalar are near-equal *data-image* sizes, not equal single-arm data-plus-code footprints. In a shared reader pool, the table and code costs are charged once, not per matrix. The root/table net saving on this measured data-plus-code ledger is 3,784 B; the model-specific coefficient/sign/scale description is unchanged.

[`timing.txt`](timing.txt) preserves 48 raw event and wall samples **per mode and batch shape**, in 16 rounds that rotate three adjacent launches per mode. Each dispatch computes one complete response for **one or eight distinct actual held states**; no synthetic repetitions are inserted into one kernel. Mode verification and 16 warmups precede timing; event times include one complete launch's actual GPU work, while wall times also include recording events, dispatch and synchronizing. They exclude one-time compilation, preparing targets/images, H2D transfers and D2H acceptance copies. Median microseconds per complete invocation:

| Actual held-state batch | Old table event / wall | Root event / wall | Scalar event / wall |
| --- | ---: | ---: | ---: |
| 1 | **22.440 / 36.019** | 31.120 / 45.170 | 62.120 / 81.309 |
| 8 | **22.440 / 36.120** | 31.120 / 41.809 | 62.159 / 81.529 |

**A native size/work tradeoff, not a speed win over the old table:** this straightforward full-response lowering is ~39% slower on GPU events than the table reader at both measured small batches despite the exact 4,096-byte table deletion. Branch/selection and indexed activation work defeat the saved hot table loads in this implementation. It is still faster than the particular packed scalar lowering, which must decode 131,072 low-bit coefficients and affines. The old reader's larger static image is not equal-rate with the root or scalar; and this local kernel comparison does not prove globally optimal GPU implementations, full-model throughput, or deployed latency. The old generic table may remain in cache, so this result does not price uncached model-wide table residency. The scalar kernel's variable-offset mask scan is faithful to its image but not a claim that 62 µs is the best possible scalar route.

The GPU ran under the exclusive `/tmp/kelana-gpu-measure.lock` model-start admission lease and bounded `gpu-run --host-mib 1024 --gtt-mib 512`; Bonsai resident serving remained active at the same PID **203054** before and after, without teardown. That reservation prevents engine *startup* overlap and provides bounded probe admission; it does not exclude already-running serving requests during samples.
