# Source-admissible V-slot capacity witness

**Result:** The fixed 148 aged-quantized-V-slot admission contract of the [stable-slot program](../kivi-stable-records/README.md) rejects a valid Qwen3-0.6B layer-0 token-ID history at length 181, even though every one of its twelve captured 256-token windows fits. This is a source-domain *admission* counterexample, not a new cache image, attention-output measurement, generation score, or full-layer/context quality claim. No model forward pass, quantization fit, GPU, new capture, or `source.arrays` was used here.

Let `v(id)` be the original token embedding → layer-0 input RMSNorm → original V projection/BF16 arrival → the frozen per-token KIVI2 group32 two-bit quantizer's entire 384-byte eight-head record. The [token producer](../quip-token-producer/README.md) establishes the token-ID source map on the captured IDs, and the [original KIVI2 donor](../kivi-two-bit-causal/README.md) quantizes each V token independently. A token's preceding history affects K/RoPE/attention, but not this layer-0 V map. Repeated observed token IDs have identical BF16 arrival bytes and identical whole-eight-head quantized V bytes at every aged donor occurrence across the panel. This assertion is checked by byte equality in [`witness.py`](witness.py), not by hash equivalence.

For a nonempty repeatable token-ID source with **M distinct reachable aged records**, horizon `T`, and recent-retention `R`, after the query's oldest-V flush there are `n=max(0,T-R)` aged positions. Their maximum possible distinct-record occupancy is **`min(M,n)`**: no more distinct records than positions or reachable records; choose that many IDs with pairwise distinct records for the first aged positions, then repeat any admitted ID to fill the rest. Before the current query's flush at arrival `T`, the aged count is `max(0,T-(R+1))`, because the before-query recent side temporarily contains `R+1` arrivals. In the initial short prefix it instead contains all `T` arrivals. This is a maximum over valid histories, **not** a prediction of linguistic frequency, observed-panel occupancy, or a lossless packed-memory advantage. The integrated [`Kelana/ValueRecordCapacity.lean`](../../../Kelana/ValueRecordCapacity.lean) proves the full finite-label occupancy upper bound, independence from enumeration order, attainment by a distinct prefix plus repetitions, fixed-capacity rejection when below that maximum, and the one-record phase increment. The source-label interpretation and actual byte manifest remain separate empirical premises; this theorem does not prove the particular C++/HIP allocator.

[`witness.json`](witness.json) retains **149 pairwise distinct 384-byte quantized records**, each with its actual token ID, original window/position, original V flush time, all eight byte offsets in the donor event logs, SHA256 of the complete 2,048-byte BF16 V arrival and whole 384-byte V event record. It pins all twelve 1,049,088-byte arrival streams, 96 original per-head event logs, token-file and source-producer receipt SHA256, plus concatenated actual arrival/record digests. Selection is deterministic: first 149 distinct aged *records*, scanning train-0…7 then held-0…3 by position. It does **not** select 149 merely distinct token IDs. The complete donor scan found **1,120 distinct aged token IDs and 1,120 distinct aged records**; every repeated aged ID agreed byte for byte, including the 2,048-byte BF16 arrival. The first 149 actual token IDs in manifest order, followed by 32 repetitions of any existing token ID (e.g. the first ID), form an admissible length-181 token history on the original source. No assumption is made about whether such a sequence is likely natural text.

After arrival `t=181` but before that query's V flush, positions 1…148 have aged, and positions 149…181 are the 33 recent records. Hence the pre-query quant occupancy is **148**. After the same query the oldest recent position 149 flushes into the quant side: positions 1…149 contain **149 pairwise distinct records**, beyond the 148 slots. Admission fails at that post-query transition. If the state could continue, before query `t=182` it would retain those same 149 quant records and have 33 recent positions again. A window stopping before the t181 flush would miss the rejection. This witness is independent of the 32 suffix tokens' V identities; they only supply chronological recent positions. The program's K work remains its original separate operation, with no claim that arbitrary K bytes equal a donor window's K stream.

## Consequence for the fixed-slot global-buffer ledger

At horizon256 and R32, the reachable source has at least1,120 distinct aged records, so the general law gives a worst-case aged occupancy of **224**, not148. The previously tested recent reservation33 already covers all distinct recent positions. Merely making that same typed-slot layout total over this source would reserve76 additional384-B records plus76 additional u8 reference counters: **29,260 B**. Keeping its other fields, padding and allocations unchanged would increase persistent state276,428→**305,688 B**, versus the matched conventional control305,156 B, and explicit globals4,520,268→**4,549,528 B**, versus4,548,996 B: **532 B larger**. This is an exact layout calculation, **not** an implemented second cache setting, a native experiment or a timing estimate. The existing148-slot measured point remains intact as a partial-admission point.

This does not prove every total representation costs more than conventional. Variable-size physical allocation, ordinary-record escape representations, a source-coded decoder, model-shared tables or cross-record coding change the premise and must pay their own metadata, reserved capacity, transitions and query work. Nor is a slot-count bound an information-theoretic lower bound on arbitrary encoded states. It rules out promoting the particular measured fixed148-slot savings into source-wide admission at the same reservation. Exact phase simulation is conditional on successful allocation; this witness supplies a reachable failure of that condition.
