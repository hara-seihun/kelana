# One complete grouped V-record query consumer

**Finished compile-only discriminator, not a native speedup.** [`PLAN.md`](PLAN.md) fixed the single implementation and reduction placement before any numerical run. [`consumer.hip`](consumer.hip) compiles two complete gfx1151 full16Q/8KV single-query readers from the *actual fixed five-byte-header KIVI2 dictionary image*: one direct per-position V reference/dictionary read, one per-Q-head typed-record probability-mass reduction then unique-record V mix. Both retain the original K bytes, conventional FP32 Q·K scores, max-subtracted softmax, KIVI2 FP16 quant fields/2-bit codes and BF16 recent values, all 1024 O coordinates and the common eight-partial O finish. One 128-lane CTA per KV head processes its two Q heads; the two Q heads share record addresses but have separate probability arrays and masses. No expanded K/V matrix, new projection, quantizer, fit, GPU launch or runtime claim. The existing [Lean value-record quotient](../value-record-quotient/README.md) establishes the exact-real identity, not bitwise FP32 identity.

## Independent numerical correspondence

[`cpu.py`](cpu.py) replays original events and source arrivals, checks the intern owner's SHA256, byte length and full component ledger **at every before/after causal phase**, checks final image byte equality, and sends each actual before-query image to the independent packed-image parser and FP32 direct/grouped arithmetic in [`reader.cpp`](reader.cpp). This reader imports none of the image generator's layout/decoding functions. Both complete mixed 2048-vectors are independently projected by the unchanged original O; the output is compared to the original teacher on all 12 windows ×256 query states ×16 Q heads. Image generation uses the frozen interner to replay the original immutable byte stream rather than refitting; its output is required to match all 6,144 independently retained phase-image hashes and ledgers. This CPU script calls the owning `source.arrays` helper, which recomputes the unchanged Q/K/V producer and teacher tensors. That source work is offline replay preparation, not query timing or a new fit; future native acceptance can reuse the already retained eight native Q/teacher/O snapshots without rerunning those stages. Original K/V event digests, fixture SHA256 `389e5f8c17ac151070b12094849f450130ab9c1684f51b402d59fd4e7ac2008f`, and O SHA256 `803995a9d5abb24c72d3ddabd50f4e656fc5eff26efaf3b626f175fc706ab499` are checked. Each per-window JSON retains source/manifest/event/final-image identities, complete t1…256 cardinality and position counts, absolute output difference, L2 output difference, both SSEs, teacher denominator and original paid owner's SSE. ## Real compiled resources and allocation boundary

[`compile-receipt.txt`](compile-receipt.txt) and emitted [`assembly-gfx1151.s`](assembly-gfx1151.s) pin HIP 7.2.53211/gfx1151 source/assembly SHA256 and exact ELF symbol/descriptors. The direct body is **13,888 B**, grouped **15,852 B**, shared finish **372 B**. Each kernel has its own **64-B descriptor** (three descriptors when compiling both comparison arms, two in a single-arm deployment). Direct query: **5632 B LDS, 23 VGPR, 48 SGPR, zero private scratch, 32-B kernarg**. Grouped query: **7688 B LDS, 27 VGPR, 48 SGPR, zero private scratch, 32-B kernarg**. Common finish: 0 LDS, 12 VGPR, 4 SGPR, zero private scratch, 272-B kernarg. LDS increment **2056 B** consists exactly of separate typed masses `[2][224]` and `[2][33]` FP32; pre-existing score/prob/mix/reduction remains. First-stage grouped serial mass reduction is implemented by one lane per Q head, **256 dependent additions** at t256, not a hypothetical zero-cost histogram. It zeroes dictionary masses across lanes and synchronizes around reduction and mixing; record fetch/address work and `u8` reference fetches remain paid. Counted V-coordinate products do not price cache behavior or GPU cycles. No GPU launch was assigned, so no native numerical acceptance/timing claim follows from a successful compile.

At the largest t256 image **263,429 B** (the precise causal serialized peak), a single-reader device allocation requires image 263,429 + Q 8,192 + O 4,194,304 + eight O partials 32,768 + final output 4,096 = **4,502,789 B** explicit buffers, excluding allocator alignment/runtime/driver and source projections. Both arms can sequentially reuse these same explicit buffers, but neither host encoder's conventional shadow nor its transient old/new images is counted as overlapping native-query live data: maintenance is separate and [its in-place owner](../kivi-value-intern-maintenance/README.md) pays its own peak. The current maintainer is a CPU process, while these query kernels expect device-resident images. No device append/flush implementation or zero-copy combined lifetime has been measured: a host-to-device composition must count both live allocations and transfers, rather than claiming that the smaller host writable-state ledger is automatically a smaller GPU serving peak. No permanent device dictionary address table, unpacked K/V matrix or mass global scratch is hidden. The compiled kernel's LDS mass arrays are resident during the query and cannot be treated as saved global RAM. Source Q/K/V projections, chronological insertion/flush, any transfers, final O and original model state remain paid. Serialized image savings are the interner's result, not a new total-working-RAM claim here.

Earlier [`subbit-value-exact-labels`](../../catalogue/subbit.json) records signed-byte row deduplication, token IDs and histogram/paired-row counts, with append/histogram/O/native scheduling unpaid. This is a distinct frozen **KIVI2 typed 384/2048-byte V-record image** with original 16Q/8KV and complete O, not a claim of a new mathematical method or a signed-byte dot speedup. The resource increase and serial mass reduction make latency unknown; this experiment ends at the honest no-launch boundary. The [separate frozen three-arm native probe](../kivi-grouped-value-native/README.md) is now complete: all24 numerical guards pass, but t256 event medians are68.237µs conventional,88.777µs direct dictionary and86.916µs grouped. Grouping improves27/32 paired samples versus direct, yet both dictionary readers lose against conventional. These measured outcomes belong to that owner, not this compile-only receipt.
