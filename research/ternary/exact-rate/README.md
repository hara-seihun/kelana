# An exact page-addressable scale coordinate for the complete ternary pilot

[The later complete 256-row bitplane/byte-plane comparison](bitplane.md) finds only 2,010 bytes of free-selector opportunity beyond the selected min/delta scale pages; its saved tagged hybrid costs 16,182 bytes more than the selected complete code-page image. It is not a serving candidate.

The selected Qwen3-0.6B `expanded-scale384` image has 197 radix-243 matrices, 4,656,128 FP16 group scales, rotation signs and BF16 norms. A 64-output-row page, separately for each 128-input-coordinate group, stores its minimum **FP16 bit pattern**, an 8-bit delta width and bit-packed unsigned differences. A per-matrix 32-bit page-offset table permits direct addressing without decoding preceding pages. This is a complete saved replacement image: 197 `.tern` files contain shape, rotation block, unchanged code and sign bytes and the new page stream; `norms.bin` contains unchanged norms in sorted key order. The file names and model architecture identify tensors, just as names in the original NPZ do. No original scale array is required.

| --- | ---: | ---: | ---: | ---: |
| Selected radix-243 / raw FP16 scales | 9,312,256 | 128,678,649 | 1.72708553 | 4.646432 |
| Exact page-coordinate image | **6,715,820** | **126,082,213** | **1.69223696** | **4.646432 (identical decoded image)** |

This saves **2,596,436 bytes, 2.018% of the complete selected payload**, without another quality/rounding trade. The 72,752 pages include 291,796 bytes of offset tables (one end offset per matrix), plus three-byte page headers and bitstreams; 32 constant pages need zero delta bits. All 4,656,128 reconstructed FP16 words were compared as integers against the selected image. Trit bytes, rotation signs and norms are copied byte-for-byte. The original quality forward expands that image into BF16. Thus the same decoder fed the recovered words gives the **same complete model and held loss by equality**, rather than an independent noisy NLL estimate. This changes the stored coordinate, not the FP32 operation/reduction schedule. The saved physical files sum to exactly 126,082,213 bytes excluding the operational receipt and filesystem allocation. Source-image, source-manifest, produced-file and code hashes are in [the complete 197-matrix receipt](/path/to/workspace/data/kelana-subbit/ternary/exact-rate/receipt.json); the images are beside it.

A random scale access loads a 32-bit page offset, then a three-byte header, then at most **three consecutive bytes** of deltas (width at most 13, bit offset at most seven), instead of the original contiguous two-byte scale. The offset and delta addresses are dependent. A sequential grouped consumer can share the page offset/header across up to 64 output rows, but a routed/sparse consumer may request a page for only one row. There is no GPU measurement or native packed reader: **this is a paid capacity/rate improvement, not a throughput improvement**. On a resident Bonsai block, the related [native paged-scale experiment](../../quantization-discovery/representations/entropy-execution/README.md) saved 2.38% but slowed sparse dot reads by about 2 ns/row. A reader port for this Qwen pilot requires a measured full-model speed/quality case rather than treating a smaller image as faster inference. The pilot's larger unresolved deficit remains BF16's 3.6392 NLL versus ternary's 4.6464; recovering language quality matters more than another scale-only byte saving.

Run the CPU construction from Kelana with `OPENBLAS_NUM_THREADS=1 python3 research/ternary/exact-rate/measure.py`. It uses no GPU; data stays under `/path/to/workspace/data/kelana-subbit/ternary/exact-rate/`. The decoder's address arithmetic is checked against every scale, including short tail pages. The layout and its 64-row access unit, not an entropy estimate or a compressed NPZ container size, define the paid bytes. `--image`, `--output` and `--page-rows` select a different complete source and physical page geometry without changing this historical image. [The fresh recovery's paid-image study](../fresh-page-rate.md) applies the same checked format at 256-row pages and establishes better complete-model held loss at exactly equal physical rate against its immediate predecessor.
