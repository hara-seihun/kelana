# How much does a better code-byte model buy?

The complete frozen `fresh-duration32` Qwen3-0.6B image has 119,196,989 radix-243 code bytes across 197 matrices. The checked, independently addressable 16-KiB zlib-1 image spends **116,219,148 bytes** on codes, flags and page offsets; the other 6,756,736 paid complete-model bytes are unchanged. The full image is **122,975,884 bytes / 1.650544760 BPW** and decodes the same model whose disjoint held NLL is **4.498337**. The subsequent exact shared-sign coordinate separately saves 35,456 bytes; this calculation holds those signs in the original format to isolate code coding.

The table evaluates an *oracle coding model*, not a candidate image. Let `n_s` be observed symbol frequencies; `H(n)=Σ_s n_s log2(N/n_s)`. Within the declared family of static arithmetic codes that assign one probability distribution to each specified context, the maximum-likelihood bit length is `H`. Decoder model probabilities, precision, page endpoints and termination are granted for free; a real paid implementation must include them. A symbol-by-symbol IID distribution has `H0`; one preceding code byte as context has `H1`, resetting at every existing page boundary. All 197 source NPZ hashes are checked against the paid-image receipt; every code byte is counted. First-order transition tables are fitted *once per matrix*, not per 16-KiB page: fitting separate 59,049-context distributions to short pages would manufacture a severe in-sample entropy gain.

| Coding family and oracle knowledge | Ideal code bytes | Gap below current paid codes | Ideal complete BPW with existing other bytes |
| --- | ---: | ---: | ---: |
| Global static IID distribution | 115,504,998.23 | 714,149.77 | 1.640960 |
| Per-matrix static IID distribution | **115,452,885.80** | **766,262.20** | **1.640260** |
| Per-page static IID distribution | 115,289,588.58 | 929,559.42 | 1.638068 |
| Per-matrix first-order transitions, page resets | 114,315,372.55 transition bits only | 1,903,775.45, *before* first symbols/model | 1.624993, *understated* |

The first-order line excludes each page's first symbol: at least 7,360 first-symbol observations remain, and a paid model has up to 243×243 conditional probabilities per matrix. Its gap is not an achievable saving without an explicit economical model representation and decoder. Similarly, the per-page IID line grants 7,360 probability tables at zero cost. Even the **free per-matrix IID model** can save at most another 766,263 bytes, **0.010285 BPW** on this complete image relative to existing zlib pages (with integer bit accounting). This is a grammar-relative rate ceiling, not an ISA-independent lower bound on compressing one finite string: context modeling, dictionaries, cross-matrix coding and changed trits are outside it. A model can also exploit page correlations; do not label this an entropy bound on all exact encodings.

This measured bound changes the code-page question. A second static IID byte codec cannot buy material complete-model capacity even before charging 197 models and random access. The current CPU native cold consumer costs 303.819 ms versus 15.457 ms for raw code observation, so shaving at most 0.77 MB with another offline byte-frequency scheme is not a speed route. To improve inference, construct a direct page-local compressed-label consumer and price its entire boundary; to improve quality, change the ternary code/scale image with complete-model training and held loss. Qwen3.6 MoE transfer needs its own actual routed producer-based paid image.
