# Complete-model ternary scale extrapolation at unchanged image format

**Result.** The selected Qwen3-0.6B 197-matrix ternary image was trained by complete-model gold loss first for 128, then another 256 steps on additional text. Let `s128` and `s384` be the two saved FP16 scale arrays. Keeping **all trits, rotation signs, tensor shapes and norms unchanged**, the fixed extrapolation `round_fp16(s384 + 0.5*(s384-s128))` produces another complete image of exactly **128,678,649 bytes / 1.72708553 BPW**. The saved physical 64-row paged version is **126,102,765 bytes / 1.69251280 BPW**, exactly decodable, with 197 `.tern` files and unchanged BF16 norms. This is a quality improvement, not an inference-speed claim.

The selected image scores **4.572739 vs 4.593977** control NLL on 16 new disjoint WikiText test windows (4,080 next-token predictions), a paired improvement **0.021239 ± 0.005618 nats** (window standard error), 13/16 windows improving. The eight windows reserved after coefficient choice improve by **0.021326 nats**. The control is the previously selected `expanded-scale384` image measured *on the identical new windows*; do not subtract its older 4.646432 score on a different test panel. The original BF16 benchmark is still much better (3.6392 on that older panel). This is a paid complete-model quality/rate point, not a claim to match Bonsai 27B quality.

## Selection and image contract

The experiment froze 16 new test windows with seed 2026092413 *before* scoring; their starts avoid the prior pilot, fresh-evaluation and ternary test windows. On windows 0–7, alpha 1.5 scores 4.667228 vs 4.688379 control; the predeclared alpha 2.0 alternative scores 4.680509, so alpha 1.5 was chosen. Windows 8–15 were not inspected until that choice: 4.478249 vs 4.499576. No held text changes the scales. This is a fixed linear continuation of existing **whole-model-trained** scale coordinates, not local matrix reconstruction or another optimizer run. It extrapolates 4,473,974 scale words that changed between checkpoints and checks for FP16 overflow (zero). The selected radix-243 trit arrays and signs agree with the earlier checkpoint for every matrix; source and output images, per-window results, token starts and hashes are retained under `/path/to/workspace/data/kelana-subbit/ternary/scale-extrapolation/` and `/path/to/workspace/data/kelana-subbit/ternary/scale-extrapolate-1.5/`. [The aggregation receipt](/path/to/workspace/data/kelana-subbit/ternary/scale-extrapolation/summary.json) links the fixture, evaluator, Python executable, source manifests, five raw per-window quality receipts and page image.

The existing [exact page codec](../exact-rate/README.md) independently reconstructs and checks **all 4,656,128 FP16 scales** against the selected new source image. Its byte count is 20,552 above the original `expanded-scale384` paged image, because the extrapolated scale bit patterns span somewhat wider 64-row pages. At matched old *raw* rate, loss improves; at the paid page rate, the new quality/rate point is 1.692513 BPW/4.572739 new-panel NLL versus 1.692237 BPW/4.593977 new-panel control. Random page access pays an offset and dependent delta fetch; no native reader, throughput, MoE runtime or resident service was changed.

Run `fixture.py` once before any quality panel, `build.py --alpha 1.5` and `--alpha 2`, then under Bonsai's GPU wrapper run `evaluate.py --name NAME --offset 0|8 --windows 8`. `summarize.py` consumes the receipts without GPU; `page.py` builds the physical selected image with the shared exact codec. Each quality run used `tools/run-batch-compare --runtime-max 48s --memory-gib 16 --host-reserve-gib 4 --exec` and restored `bonsai-halo.service`; the GPU lock is free. These quality forwards expand weights to BF16, so the measured NLL does not measure packed inference time.

**Next question.** Fit a longer scale-only trajectory on *new training text*, select only on fresh train/validation windows and freeze a separate held panel. This one-dimensional continuation earns a small complete-model gain but does not close the ~one-nat BF16 gap. A native page reader would first have to pay the two dependent scale reads and demonstrate whole-model TPS rather than extrapolate from smaller bytes.
