# Longer fresh-text complete ternary recovery

Sixteen additional gold-loss scale updates to Qwen3-0.6B's **complete 197-matrix** packed ternary image improve eight newly frozen selection windows from **4.872097 to 4.864839 NLL**, and the untouched eight-window test half (2,040 predictions) from **4.343739 to 4.330215 NLL**. Held paired gain is **0.013524 ± 0.002129 nats** (window standard error), favorable on **8/8** windows. These are matched source/candidate evaluations, not subtraction across panels. The source `fresh-scale8` was itself trained for eight steps on disjoint earlier train text. The new `fresh-duration16` image keeps all trits, signs, norms and shapes unchanged; only scales change. Its complete raw payload remains **128,678,649 bytes / 1.72708553 BPW**. [The independently encoded complete physical image](paid-rate.md) costs **125,953,533 bytes / 1.690509855 BPW**, just 96 bytes above the predecessor's independently encoded 125,953,437-byte image. Every scale word decodes bitwise; there is no native reader/timing.

The new steps read `expanded-tokens.npz` train rows 456–471 (previous run consumed 448–455, earlier recovery ended at 447), sixteen Adam steps at learning rate .0001 and train-only checkpoint selection at steps 8 and 16. The selected checkpoint is step 16 (score on train rows 456–459, 5.103684 → 4.932786). There is no use of validation or test tokens in optimizer updates. A 16-window test fixture was frozen before the two image evaluations with seed 2026092431, excluding the earlier pilot, extrapolation, fresh evaluation, and fresh-recovery test windows. The first eight newly frozen windows select the candidate; the last eight were not read until that selection was made. These contiguous sorted-by-start halves are not independent random split assignments; the held result is conditional on this specific text partition.

The [receipt](/path/to/workspace/data/kelana-subbit/ternary/fresh-duration/summary.json) gives full source/candidate manifest, training, fixture, evaluator and four per-window result hashes. The complete packed images and failed/positive windows remain under that data owner. `run.py summarize` verifies all 197 images' non-scale fields and byte counts against the source and writes the paired result. Evaluation expands the saved image to BF16; it is a complete-model quality comparison, not compressed inference TPS. The benchmark is still far behind the original BF16's 3.6392 on its separately measured test panel and the stronger calibrated four-bit's 3.7958 at 4.2513 BPW. No Qwen MoE native code, runtime, or resident service was changed.

From Kelana root, run `run.py freeze` once before evaluation; construct with `tune.py --source fresh-scale8 --name fresh-duration16 --fixture /path/to/workspace/data/kelana-subbit/ternary/expanded-tokens.npz --train-offset 456 --steps 16 --windows 16 --tokens 256 --lr .0001 --evaluate-every 8 --score-windows 4`. The training and each `run.py evaluate --name NAME --offset 0|8` used Bonsai's `tools/run-batch-compare --runtime-max 48s --memory-gib 24 --host-reserve-gib 4 --exec` (evaluation: 47s/16 GiB). Finish with `run.py summarize`. The wrapper restored the entry service state after each panel.
