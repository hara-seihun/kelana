# The normalized Qwen router needs seven exponentials

Qwen3.6-35B-A3B's routed branch selects eight of 256 experts using softmax probabilities, then divides the eight selected probabilities by their sum. In the selected native source, `src/models/qwen35moe.cpp::build_layer_ffn` passes softmax gating and `norm_w=true` to `build_moe_ffn`; `src/llama-graph.cpp` constructs `SOFT_MAX → ARGSORT → GET_ROWS → SUM_ROWS → CLAMP → DIV`. The fused `ggml/src/ggml-cuda/topk-moe.cu` evaluates 256 exponentials before selection, then reduces and normalizes the eight selected probabilities. The [width-dependent fused-router diagnosis](../../../../bonsai-halo/docs/qwen-moe-graph-dispatch.md) already showed that changing this kernel's FP32 map can change complete-model logits. The construction below is an exact **real-arithmetic** replacement of the entire router observation, not a bit-preserving patch to that kernel.

For finite real logits `l_0,…,l_255`, choose the ordered top-eight indices `e_0,…,e_7` with the same deterministic index tie break. Let `m=l_e0`, `t_0=1`, `t_j=exp(l_ej-m)` for `j=1,…,7`, and `a_j=t_j/(sum_{q=0}^7 t_q)`. Output `(e_j,a_j)` directly to the grouped expert consumer. There is no need to construct the 256-way softmax or the selected eight intermediate probabilities. Consequently the complete real-arithmetic weighted expert sum `sum_j a_j D_ej h_ej(x)` is unchanged, while the separate shared-expert path remains unchanged.

Proof: `p_i=exp(l_i-M)/S` for any common stabilizing maximum `M` and positive `S`. Exponential and division by a positive common denominator preserve the logit order, so the selected indices agree. The selected probability sum is `exp(M-m)/S * sum_j exp(l_ej-m)`; dividing each selected probability by that sum cancels both common factors. The native graph clamps the selected probability sum at `2^-14`. For any 256 nonnegative probabilities summing to one, their eight largest sum to at least `8/256 = 1/32`, so this clamp is inactive on the stated finite-real domain. Equal logits follow the same index tie break. NaNs, infinities, floating-point underflow and changed selection ties are outside this proof.

On a fixed ordered route, the seven differences `l_ej-l_e0` are also a complete coordinate for the seven independent positive weights: `log(a_j/a_0)` recovers each difference. The local Jacobian has rank seven. Any smooth exact coordinate for all possible normalized selected weights on that route therefore needs at least seven real dimensions. This is a bound on the **router observation**, not on the 2,048-dimensional common expert input or its complete output; the latter has its own [actual-route Jacobian bound](../routed-jacobian/README.md). The eight IDs remain indispensable for choosing expert images.

## Cost and boundary

For one Qwen router row, the existing fused program performs 256 `expf` evaluations, accumulates 256 terms and performs a warp sum before iterative top-eight selection, followed by selected-weight normalization. Selecting raw logits first and exponentiating only the seven nonmaximal selected differences removes **249 exponentials and the 256-way preselection sum**. Over forty routed layers this is 9,960 fewer exponential evaluations per generated token, conditional on every layer using the fused kernel. Both programs still read/compare 256 logits, select eight experts, read the selected expert images and compute their gate/up/down products, route metadata and weighted sum. The new seven-term denominator reduction replaces part of the selected-probability normalization. Exponentials may overlap weight latency; these operation counts imply no native speedup or whole-model rate by themselves. The construction needs a native fused implementation, equal-work unprofiled panel and quality testing before use. Prompt and batched calls currently take a different top-k dispatch, so applying it only to singleton decode would worsen map inconsistency.

The FP32 arithmetic contract is separate. The original graph rounds 256 exponentials, their sum, each probability and the selected normalization. The shortcut changes those roundings and may even change selected IDs where softmax rounds two distinct logits to the same value. `check.py` supplies a deterministic FP32 example: seven logits equal one, while experts 7 and 8 have logits zero and `float32(1e-8)`. Both latter probabilities round to `.0089370143` in the host's float32-output softmax. Raw-logit selection takes expert 8; rounded-probability selection takes expert 7. This host example is not the HIP kernel's precise instruction sequence or a claim that a Qwen route flips on captured text. No native runtime is changed. A compatible **alternative numerical map** needs held complete-model loss and generation decisions at paid inference cost; it cannot be installed as an exact scheduling improvement.

[The all-256 real-route replay](real-routes.md) reads the actual normalized producer, F32 router image and captured expert outputs on those tokens. Raw-logit top-eight agrees with every captured route. A conservative FP32 dot-product envelope separates eighth from ninth on 233/239 tokens, and a seven-exp FP32 score calculation changes the held weighted expert sum by at most 5.59e-6 relative L2. This makes the new numerical map worth a native full-model experiment; it is not exact FP32 replacement acceptance.

The capture check reads the selected runtime's layer-0 routed IDs and normalized weights on 113 train and 126 held tokens. Every row has eight distinct IDs and score sum within `1.1e-7` of one. The smallest selected score is `.02917` on held. Those scores verify the captured output contract and its source hashes, not the uncaptured 256 raw logits or native replacement quality. Run `python3 research/moe/router-observer/check.py`; [the receipt](/path/to/workspace/data/qwen-moe/router-observer/receipt.json) records its source and capture hashes, extrema and the synthetic FP32 counterexample. It uses no GPU and does not alter Bonsai's service.

[Partial-dot certificates on actual producer inputs](partial-certificate.md) close a different shortcut: certifying the top eight without reading all router columns. A fixed weight-energy order certifies held routes after 2,028.59 of 2,048 columns on average. Even an uncharged token-dependent coordinate order saves only a conditional 0.231% of whole-model weight bytes if its layer-0 fraction holds across all forty layers. This is a measured negative for that certificate family, not for the normalized-weight observer below.

[The FP32 omitted-logit witness](precision.md) holds the eight selected logits and IDs fixed while lowering all other logits on captured layer-0 rows. Rounded selected weights change on 125/126 held rows under a declared host FP32 normalization grammar. This proves the selected eight logits alone cannot reproduce that grammar's bits over unrestricted logit vectors, even when the route is unchanged. Its largest held weighted-sum difference is 1.85e-7 relative L2; it is not a replay of native HIP reductions or whole-model quality.

The next decisive experiment is a separate fast fused raw-top-eight arm, run on identical full-model workloads and disjoint text against both installed fused and width-invariant unfused controls. Keep all three maps distinct: measure complete-model prompt, plain and MTP verification time, and compare routed IDs, selected scores, greedy streams and held language loss. If saved exponentials do not convert into a complete-model gain, this algebra still identifies the minimum router carrier but does not justify a new serving map.
