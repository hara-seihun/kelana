# Paired routed gate/up input rank

Two experts **actually selected together** at Qwen layer 0 almost fill the entire 2,048-dimensional input coordinate even if one computes all their gate/up preactivations as a joint linear map. Original BF16 experts 1 and 4 co-route on train token 13. Their concatenated `[2048,2048]` gate/up matrix has **exact rank 2,043 over the rationals and reals**. Elimination modulo 251 certifies 2,043 independent rows. Five independent source-BF16 row identities, checked at all 2,048 coefficients, give the matching upper bound. Four are equal/opposite row pairs, and the fifth is a signed-sentinel four-row relation: with stacked row indices, `529=-17`, `561=49`, `1623=-1111`, `1780=1268`, and `497=1009+825+313`. The last identity would be missed by duplicate-row counting. On held text, experts 1 and 3 co-route on tokens 78, 107, 113, 117 and 122, and have modular rank 1,920; experts 14 and 15 co-route on token 61 and have modular rank 1,988. The latter two modular values are lower bounds, not claims of exact real rank. The train pair is the sharp witness for the cost argument.

The result is a measured negative for an **exact route-conditioned shared linear input** that must expose both experts' gate/up preactivations on unrestricted real inputs. Write their stacked map as `A C`, with `C` mapping 2,048 inputs to `k` shared coordinates. Equality for all inputs requires `k >= rank([G_1;G_4]) >= 2043`. More generally, a scheme that first evaluates `k` shared linear coordinates and then linearly reconstructs all eight routed experts' 8,192 gate/up outputs has at least 20,920,320 scalar products per token at this route's `k`, against 16,777,216 direct products, a **1.247x arithmetic disadvantage** even before routing, memory traffic or FP32 rounding. This counts a dense common `2043 x 2048` map and dense `8192 x 2043` reconstruction. It is a family cost, not measured native throughput or a bound on sparse coefficients, packed operations, nonlinear whole-sum observers or approximate codes. Storing a full-bank dense shared factor at this rank would cost more equal-precision coefficients than the original bank, before metadata.

The pair has five exact dependent rows, including one non-pair relation among four tiny signed BF16 sentinel rows. They can be reused as individual preactivations in real arithmetic, but saving five of 2,048 outputs cannot make a narrow `k`-coordinate exact factor pay in this dense-product grammar. This does not grant bit-identical FP32 signed-sentinel dot execution: the row relation is over exact BF16-valued real coefficients. The independent [installed GGUF routed-sum Jacobian certificate](../routed-jacobian/README.md) addresses a different observation after SwiGLU, down projections and weighted summation; it proves full local dimension at one held producer input. This paired result instead prices the proposed shared *preactivation* coordinate for an actual route in the original BF16 bank. It says nothing about preserving native FP32 bits by reassociation, or about its original weights agreeing with the installed GGUF output.

`witness.cpp` reads the pinned original expert slice, scales each finite BF16 coefficient by `2^133` to an integer, reduces modulo 251, and computes rank by finite-field elimination. A nonzero minor modulo 251 is nonzero over the rationals. The program independently rereads the twelve rows of the five claimed identities, checks exact BF16 signs and magnitudes at every coefficient, and rejects modular rank above their upper bound. [The original receipt](/path/to/workspace/data/qwen-moe/paired-gate-rank/receipt.json) retains all three route rank outputs and token indices; [the exact-rank receipt](/path/to/workspace/data/qwen-moe/paired-gate-rank/exact-rank-receipt.json) hashes the amended source, same slice and CPU binary and retains both bounds. No GPU or service was used.
