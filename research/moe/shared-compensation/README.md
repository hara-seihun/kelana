# Can Qwen's already-computed shared expert replace a routed expert?

The installed MoE evaluates a ninth, shared expert on every token. If its output pointed toward a routed contribution, changing only the shared gate could absorb a skipped routed expert without a new weight image. This experiment gives the proposal an *unavailable free oracle*: after observing all eight routed outputs and the shared output, pick whichever routed expert is easiest to omit and choose a separate optimal shared-output coefficient **per token**. This optimistic construction barely improves even local quality.

| Layer-0 local observation | Train, 113 tokens RMS | Held, 126 tokens RMS | Held tokens within 1% / 5% |
| --- | ---: | ---: | ---: |
| Best single routed omission, shared unchanged | .062208 | .055047 | 1 / 63 |
| Best omission + free hindsight shared gain | .062145 | .054936 | 1 / 63 |

The median absolute cosine between the easiest omitted contribution and the shared direction is .0354 train / .0388 held; even selecting the best aligned of all eight reaches absolute cosine at most .4704 / .5393 on these splits. The shared output itself is not tiny (median norm .438 / .453 of the combined FFN output); the missing direction is mostly orthogonal. The gain selected by the unconstrained oracle happens to leave the total shared coefficient nonnegative on every row (delta range −.00742..+.02183 train, −.00686..+.03060 held), so that constraint does not alter this result. The 1%-threshold held count differs from the routed-only omission study's zero because the denominator here includes the shared output.

For contribution `v_i = score_i * down_i` and already-computed shared output `s`, the oracle minimizes `||v_i − delta*s||²` at `delta = <v_i,s>/||s||²`; residual square is `||v_i||² − <v_i,s>²/||s||²`. It then chooses the best of eight independently for each token. The measured error divides by `||s + sum_i v_i||` and aggregate RMS weights tokens by that denominator. This is an exact FP64 projection identity for the *fixed captured vectors*. Its online realization would need the missing output to calculate the gain, an extra dot/reduction and change the model's shared gate; none are charged. Omitting one of eight routed weight images on every layer would save at most 76,439,552 / 2,626,187,904 = **2.91067%** of the modeled single-token one-read stream before native grouping, but the held oracle incurs .054936 local RMS at that unconditional saving. At 1% the oracle gets only one held token at this layer, even while allowed a perfect decision and gain. No whole-model or native speed claim follows.

The [source](study.py) reads actual 113/126-token layer-0 post-attention producers, IDs, normalized router scores and individual native-captured routed down outputs. It decodes the pinned installed GGUF's Q8_0 shared gate/up/down and F32 sigmoid gate from the model using the installed libggml decoder, then evaluates that branch in FP64. This combines a native-captured routed branch with an offline real-arithmetic shared branch; it is not bit-identical native FP32 execution. **Next question:** do not implement a shared-gate-only substitution of a routed expert. A different paid, input-dependent output *direction* trained on broader quantized producers needs a frozen complete-model image and disjoint held language loss; alternatively reduce exact GDN state movement on the existing native path. This result does not reject jointly retraining the shared expert and routed weights, or an observation contract weaker than the complete FFN output.
