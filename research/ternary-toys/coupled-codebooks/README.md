# A paired-channel codebook at the same packed byte count

A four-column, two-output linear producer feeds a fixed two-output consumer, then a residual addition. Inputs are anisotropic and correlated. We fit the observable map `C W x`, not the entries of `W`. The residual cancels from the error but remains part of the composed computation. There are 64 training inputs and 1,024 independently drawn held inputs. Each trial has one FP16 group scale.

The scalar control searches **all 3^8 = 6,561 ternary matrices**, with the best nonnegative FP16 scale for each. Its eight trits occupy two radix-243 bytes. The paired candidate searches **all 16 × 4^4 = 4,096 assignments** of a group template `a,b ∈ {0,1,2,3}` and four two-bit column labels. The labels select `(a,b), (-a,-b), (b,a), (-b,-a)`. Its four labels occupy one byte; its two template parameters occupy four bits in a second byte. Both formats pay two bytes for the FP16 scale, so both occupy **four physical bytes per eight weights, 4 BPW**. Four high bits of the paired metadata byte are unused. There is no separately stored table: the sign and swap rule defines the four vectors. Code and scale selection use the full training map; neither arm gets a free relabeling. For a fixed code, least squares gives the continuous scale optimum. The search checks its adjacent FP16 words.

The paired-motif targets use randomly permuted paired columns at ratios 1:2, 1:3 or 2:3, plus independent Gaussian weight perturbations of standard deviation 0.11 before a group gain. The noise means the dictionary does not exactly represent the target. Eight Gaussian unstructured targets test the same mechanism off its assumed manifold. Held errors below sum mean squared observed output error over eight groups, with the same fixed consumer and input distribution in both cases.

| Target family | Exact scalar ternary | Paired codebook | Paired wins |
| --- | ---: | ---: | ---: |
| Noisy paired motif | 4.852597 | 0.128005 | 8/8 |
| Unstructured Gaussian | 2.313192 | 6.518197 | 0/8 |

The advantage is conditional, not a general quantizer win. The paired motif needs both magnitudes in the same column; a scalar ternary group scale cannot represent them together. Conversely, four linked column choices are too restrictive for unrelated weights. The scalar search already optimizes codes against the composed, anisotropic response, so independent nearest-weight rounding is not the explanation.

Storage parity is not runtime parity. The scalar winners have 52 nonzero terms across the eight paired-motif groups; the paired winners have 64. The scalar consumer reads two code bytes and one FP16 scale per group, peels eight trits, and applies up to eight signed input additions. The paired consumer reads the same four bytes, extracts four two-bit addresses and two template fields, chooses sign and swap per column, and applies eight signed `a*x`/`b*x` terms before the same scale and fixed consumer. With the fitted templates `a,b ≤ 3`, multiplication can be shifts and additions, but those shifts, label selection and extra nonzero terms are online work. No native timing or speedup is claimed. This construction improves quality at the fixed tiny byte budget, not inference throughput.

The eight-weight group is deliberately small enough for exhaustive scalar search. Its FP16 scale inflates the physical rate to 4 BPW, far above the 1.7271-BPW Qwen image. Longer groups amortize the scale and metadata but also require testing whether real paired-channel weights follow a useful shared template. The next discriminating experiment is to measure paired gate/up or two output channels in a real Qwen layer, cluster groupwise paired columns on calibration activations, then score their **composed downstream residual response** against an equally paid scalar ternary fit. Charge any learned template, routing and the native decoder. If the pair-orbit assignments are rare, the unstructured control predicts a loss.

Run from this directory with `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python experiment.py`. It writes [results.json](results.json), including each selected code, scale, train/held error, raw weight error and source assignment. The seed, input transform and consumer are recorded there. This CPU run takes seconds and does not use the GPU.
